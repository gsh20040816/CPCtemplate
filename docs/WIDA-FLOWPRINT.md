# WIDA 打印稿：网络流

原稿是 hh2048/XCPC 树 `cfdb12db6792eb2303798541fb5c760ed2bc618b` 的 blob `3ebc352fec43201867c290e9d13b34dfa82db384`，路径 `02 - 打印稿模板汇总/04 - 网络流.md`。

`Flow_` 是 Dinic。`Flow(n)` 实际分配到 `n`，点从 0 开始也能放下。单边、空图、经典分流和几张不超过 5 个点的随机图，最大流都与 Edmonds-Karp 一致。稿里的 `reset` 把反向边的流量加回正向边。测的时候把它放进结构体，第二次 `work` 得到同一个值。原稿只把 `reset` 写成片段，Gomory-Hu 的 `main` 没有调用它。

最小割例子用 `Flow_<int>`。跨部边写成 `1E18`，在这台编译器上变成 `2147483647`。两个项目收益是 10 和 1，材料费用是 3，两个项目都连到这份材料。穷举最好的收益是 8。程序输出材料费用之和减去最大流，得到 0。文字说的最大收益和这段代码不是同一个数。

Gomory-Hu 片段写的是 `Flow<int>`。上面的别名 `Flow` 已经是 `Flow_<int>`，不是模板，所以这段不能和前面的最大流一起编译。`fa` 一开始全是 0，也没有调用 `reset`。这轮没有把它当成一棵正确的最小割树。

费用流和已经核过的 Dijkstra 版本一样，节点从 0 编号。两条路合成流量 2、费用 7。所有点都可达时，费用 -5 的一条边得到流量 1、费用 -5。负费用分支整段被注释掉了。到不了的点在第二次增广时会把 `long long` 最大值再加进势里，UBSan 报 signed integer overflow。

`python3 tests/wida_flowprint.py` 在普通 `-O2` 和 ASan/UBSan 下通过 Dinic、这个选择例子和完全可达的费用流。没有新的在线 AC，也没有新增模板。来源保持 partial。
