# 右侧容量匹配：kuangbin 4.11 与 Dinic

kuangbin 2018 正文152–153页（物理154–155页）的二分图多重匹配，是每个左点最多匹配一次、右点 v 最多匹配 num[v] 次的无权最大基数问题。这里复用现有 `src/compact/flow.hpp` 的 `Dinic`，不新增另一份最大流或普通 HK，也不把右点容量强行改成1。

## 可直接使用的建图

下面只需抄写手册中的 Dinic，再抄此函数。左右点各自使用0-based，cap长度为m、每项为非负long long，边端点合法；n+m+2及边编号必须能用int表示并能分配相应内存。返回最大匹配的配对列表，大小就是最优值；允许重边，结果不会重复使用左点。不承诺平局时与原片段相同的方案。

```cpp
vector<pair<int, int>> capacity_matching(
    int n, const vector<long long> &cap,
    const vector<pair<int, int>> &edges)
{
    int m = cap.size();
    int s = n + m + 1;
    int t = s + 1;
    Dinic g(t);
    for (int u = 0; u < n; u++)
        g.add(s, u + 1, 1);
    for (int v = 0; v < m; v++)
        g.add(n + v + 1, t, cap[v]);
    vector<int> id;
    for (auto [u, v] : edges)
        id.push_back(g.add(u + 1, n + v + 1, 1));
    g.flow(s, t);
    vector<pair<int, int>> ans;
    for (int i = 0; i < (int)edges.size(); i++)
        if (g.used(id[i]))
            ans.push_back(edges[i]);
    return ans;
}
```

每次调用函数重新建图、返回完整方案。Dinic内部仍用递归DFS。该段是来源模型的建图示例，由测试直接提取编译；不是新登记的独立组件或正式OJ模板题，也尚未加入PDF用法目录。

## 正确性与成本

任意合法配对可沿源→左→右→汇各送一单位流；源边限制左点唯一，汇边限制右点容量。反之，整数最大流在左右边上只能是0或1，流量守恒保证这些边构成合法配对。因此最大流值等于最优配对数，used读取的正流边给出方案。网络最初只有这四层的有向边，不包含可独立循环的原边。

总流至多n，无需累加所有右侧容量；单个容量允许LLONG_MAX，即使容量总和超过long long也不在本建图中求和。一般上界沿用Dinic的O(V²E)，V=n+m+2，E为输入边数加n+m（反向边是常数倍），空间O(V+E)。不把所有右容量为1时的专门界无条件套到本模型。若输入是来源矩阵，扫描矩阵另需O(nm)。

## 来源接口与边界

原片段的uN/vN及g均0-based，g[u][v]非零代表可以配对；linker[v][0]是右点已匹配数量，linker[v][1..数量]是左点列表。hungary每次清空数量并从头重算。若直接复用一个Dinic对象，第二次flow返回的是新增流，不是总匹配数；上面的函数每次重建，因此没有这项歧义。不要在已有流上随意减少右容量后继续求解。

固定数组MAXN=1010、MAXM=510。linker的第二维还要保存数量，不能误认为一个右点可以保存1010个左点：若uN=1010且都分给同一右点，第1010次写入的下标已经越界。本批在独立UBSan程序中重现此边界，来源正常对照限制n≤1009、m≤510；容量可以大于n，但不能超出来源int。当前vector建图不受该静态数组限制。

原片段逐次增广中每个右点至多访问一次；满员时递归尝试挪走其匹配左点。零容量右点既不能接纳，也没有可挪走的左点。原算法与流建图求解同一问题，但不要求相同增广顺序。来源代码仅去除PDF行号与页眉、统一减号字符，执行语句和常量保留在测试夹具中；没有将其中压行风格复制到公开模板。

测试与结果见 `tests/capacitated_matching_source_audit.py` 及对应verification记录。独立参照按右点枚举其接纳的左点子集，以已用左点集合为状态求最大值；不以两个增广算法互相一致作为唯一证据。原片段和当前建图分别检查基数、合法边、左点唯一、右侧容量及重复求解。

本批属于来源映射和本地接口验证，不新增在线AC、速度榜或正式模板题记录。全库目标、PDF用法登记及其他未覆盖条目继续保留。
