# 在线序列区间第k小

`SequenceKth` 提供在线位置插入、单点修改、区间秩统计和第k小。外层为递归重量平衡树，内层复用本库 `ost`，即GNU PBDS红黑秩树。它补齐来源树套树的序列模型，避免沿用不伸展Splay查询的性能假设；原稿的完整协议核验及退化反例见 `SEQUENCE-KTH-SOURCE-AUDIT.md`。

## 使用合同

以0-based `vector<long long>` 构造，默认空序列；`size()`返回当前长度。`insert(k,x)`在前k项后插入，k为0..size()；`set(k,x)`修改第k项，1≤k≤size()。`less(l,r,x)`计1-based非空闭区间内严格小于x的项，最后参数传true则计≤x；`kth(l,r,k)`返回区间第k小，1≤k≤r-l+1。允许重复值和完整long long范围。

不支持删除；这是来源插入/修改模型的边界。节点从1编号，每次插入创建一个稳定编号，不因外层重建而改变；要求vector节点数小于INT_MAX。a/root及带节点编号的方法属于内部，不可外部改写。使用C++20的std::midpoint；GNU PBDS不是ISO标准库，须使用带此扩展的工具链。

内树保存(value,id)，每项唯一；同值的多个副本不会被集合合并。严格小于x使用order_of_key({x,0})，小于等于x使用比全部已分配编号都大的a.size()作第二关键字，避免对x做±1而溢出。修改递归返回旧(value,id)，沿访问路径删除旧键并加入新键，重复赋相同值也保持一次副本。

插入前先完成vector扩容，此后递归只传编号；不跨扩容保存Node引用。区间计数分解为两条边界路径和完整覆盖子树，完整子树调用内树秩查询。第k小在全树最小值到最大值之间二分，midpoint(lo,hi)不溢出且lo≤mid<hi，故mid+1也安全，最多64轮；查询区间的答案位于全树范围内。空树只可构造/插入/size，不可调用非空区间接口。

## 重建与复杂度

外树任一孩子大小不超过子树的3/4，否则按递归中序收集编号并中点重建。内树在每个节点由孩子元素重建，故外树高度O(log(n+2))。不能把内层红黑树与外树的重建成本混淆。

秩查询O(log²(n+2))，kth最多64次秩查询，O(64log²(n+2))；修改O(log²(n+2))。构建及s点重建保守O(s log²(s+2))，插入保守均摊O(log³(n+2))、单次最坏O(n log²(n+2))。vector扩容可能复制内树，总量在此保守界内，且会暂时增加内存峰值。空间O(n log(n+2))，PBDS逐键分配的常数及峰值要按实际环境评估，不能只用外层Node大小估算。无删除，容量随插入增长，重新构造对象清空。

## 来源协议适配

`verify/api/sequence_kth.compact.cpp` 按固定来源的EOF多组、Q/M/I、异或lastans协议。I x val转换为insert(x-1,val)，M转set，Q转kth；只有Q更新lastans。不交换查询端点。此适配限定来源值域0..100000，答案转int与参数异或均在该范围；核心signed64能力由独立接口测试验证，不冒充来源题面允许该范围。

BZOJ官方题面访问失败，属于来源模型/API演示，不能登记为正式题目AC或速度榜。独立非比赛模板题入口仍待确认。

## 验证

接口穷举长度0..5的二元序列，遍历插入位置及LLONG_MIN/-1/0/LLONG_MAX四种值，共1284次插入，并对新项做相同赋值和改为1；逐次枚举全部区间和每个k，以排序结果核对，同时核对严格/非严格计数。检查树高条件、子树大小、每棵内树全部(value,id)、中序序列以及节点恰好被引用一次。30组各300次随机插改查询，共9000次，包含频繁极值赋值与vector扩容。

完整来源协议200组随机多测，每组180操作，独立Python列表模型产生答案后反向异或编码。另有两组30000初值（递增互异和全相等），连续300次全区间最小值查询，1000次赋值、1000次头插和端点秩查询；对应旧Splay反例并检查插入后的长度变化。本地数据规模不等同于原OJ资源限制已通过。

普通和ASan/UBSan下分别运行头文件、独立复制及NDEBUG接口探针，以及完整驱动、展开、最小抄写及NDEBUG适配。NDEBUG不会移除使用require的oracle。突变测试针对≤误写<、插入位置偏一和未删除旧键，采用无后续解码依赖的短反例，以答案不一致拒绝；不依赖错误答案导致后续非法参数崩溃。LeakSanitizer在该环境关闭。

用法327已纳入总册与数据结构册，ost依赖页码/章节由生成器链接；实际展开版哈希绑定双模式收据。
