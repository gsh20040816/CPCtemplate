# 相邻十进制好数之和

`good_number_sum` 补齐 WIDA 字符串07的完整求和应用，使用已核验的exkmp避开原稿越界。它不将普通字符哈希的加法当作数值加法，也不依赖哈希无碰撞来保证答案。当前337个组件、460个完整用法。

## 接口

`good_number_sum(s,x,mod=(1ULL<<61)-1)` 返回 `{l,k,r}`，即零基半开区间s[l,k)与s[k,r)；两段均非空且相邻，对应十进制整数的和等于x。无解返回三个-1，不承诺方案的字典序。

s和非空x必须只含1至9，不能含0。允许s为空；长度分别不超过500000、200000。模数满足1≤mod<2^61，可以是合数，模数1也合法；改变它只影响筛选效率。这里选择固定大模数以保持接口简短、运行可复现，不给对抗输入的线性时间承诺。

## 为什么只需要线性个候选

令目标长度为m，两个正数长度都不超过m。

若两数都短于m，必定都长m-1。否则较短者至多m-2位，和至多 `(10^(m-1)-1)+(10^(m-2)-1)`，小于最小的m位好数111...1。m=1时不会进入这一分支。因此枚举相邻的两段m-1位即可。

否则至少一个数A长m。设A与x的LCP为l。A小于x，所以若有合法解必有l<m；首个不同位上x较大。剩余后缀长t=m-l-1，另一数B=x-A满足：

- B<10^(t+1)。
- 因x没有零，其后缀至少为t位的111...1，故B≥10^t+(10^t-1)/9-(10^t-1)=(10^t-1)/9+1。

t≥1时这给出B至少t位，因此长度只能是m-l或m-l-1；t=0时B为一位，丢弃非正候选长度。把B放到A左右两侧都检查，便覆盖所有相邻方案。exkmp在O(n+m)内计算每个长数候选与x的LCP。

上述证明依赖好数前提。允许目标含0后长度可能跨越更长的借位链，本接口不适用；不能只删输入断言就扩展定义域。

## 碰撞只影响耗时

前缀余数采用真正的十进制底10和数字值，先判断两段余数之和是否等于目标余数。128位乘积保证模运算精确，mod<2^61保证两个余数相加不溢出unsigned64。

余数命中后，从右往左执行普通竖式加法，逐位比较目标，并检查进位与两段是否恰好耗尽。碰撞候选失败后继续枚举，绝不直接输出。合法解不会被取模筛掉，因此筛选和精确校验既不引入错误答案，也不漏掉答案。

设C为通过余数筛选的候选数，时间O(n+m+C*m)，最坏O(n*m+n+m)，空间O(n+m)。默认大模数对通常输入筛选较强，但这是效果说明，不是对抗输入的渐进时间保证。测试使用mod=1和7故意制造大量碰撞；它们不是赛时推荐的性能设置。不得为了提速去掉最后的精确验证。

## 完整题目用法

用法460对应 [CF1598G官方题面](https://codeforces.com/contest/1598/problem/G)，输入s与x，题面保证有解。返回的{l,k,r}转换为一基闭区间 `[l+1,k]` 与 `[k+1,r]`。驱动也为库函数扩展的无解情况输出-1，但正式题面不要求该分支。
