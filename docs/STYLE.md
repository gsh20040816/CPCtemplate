## 赛时抄写规则（用户最新要求优先）

- 可读性与赛时快速抄写是最高优先级，不以少行数或封装完整程度衡量模板质量。
- 按 issue #2，短条件语句、短循环可适度合并；相关更新可使用清楚的逗号表达式，避免不明确的求值顺序。
- 复杂函数、分支和循环仍展开；不强行压缩多级嵌套、状态传播和有副作用的表达式。
- 简单无状态算法直接使用函数；需要维护状态时使用轻量 struct，不强制统一成完整类库。
- 不为统一接口添加无意义的代理层、继承、框架或泛型参数。边界约定写在说明中，代码保留必要检查。
- 只保留 STL/vector 版，优先小写短名，减少不必要的大写。现有公开类型名结合对应模板验证逐项调整，不为了改名添加代理封装。
- 具体调整见 [issue #2](ISSUE-2.md)，配置以 `src/compact/.clang-format` 为准。已归档的 OJ 提交快照保留原样，用于核对历史 AC 证据，不作为新码风示例。

- DFS 按递归写法编写，禁止为了本地栈限制改成显式调用栈；测试环境应适配模板。Tarjan 的分量栈属于算法本身，保留。

- 按 [issue #10](ISSUE-10.md)，竞赛单翻译单元自由函数省略不必要的显式 inline。变量定义中的 inline 与函数优化提示区分处理。能由构造函数直接完成的初始化逐项迁移，同时适配重建测试、驱动和说明。
