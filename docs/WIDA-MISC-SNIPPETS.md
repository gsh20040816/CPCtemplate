# WIDA 杂类：字符调整和二分片段

三份原稿都在 hh2048/XCPC 树 `cfdb12db6792eb2303798541fb5c760ed2bc618b` 的 `03 - jiangly模板收集/01 - 杂类`。它们不是完整程序：没有 `main`，整数和实数片段也没有给出 `check` 的定义。注释里的 QOJ 提交页面这次没有打开。来源保持 partial，不新增模板。

## 字符调整

blob `37c6c358f1af2b5632e79b6b84e80400f5a8a38e`。

`rev` 只改写下标 1、3、5 这些位置，偶下标保持原字符。小写变大写，大写变小写。`get` 把 `a..z` 映到 0..25，其他字符走 `26 + c - 'A'`，因此 `A..Z` 是 26..51。`0` 得到 9，函数不拒绝非字母。`isupper`、`tolower` 和 `toupper` 受本地化影响；下面的结果只在 C 本地化下核对。

## 整数二分

blob `7a1e25df5b5ca0b0d07877d1fa97ca5e2d8edc32`。两段都假定 `check` 有单调分界，片段本身不检查这个前提。

前一段用 `(lo + hi + 1) / 2`，`check` 为真时抬高下界，最终取最后一个为真的位置。后一段用 `(lo + hi) / 2`，为真时压低上界，最终取第一个为真的位置。若整个区间都为假，前一段返回原来的下端，后一段返回原来的上端，都不会再检查端点。若整个区间都为真，前一段返回上端，后一段返回下端。

第一段示例把上界写成 `1e9`，这个范围内两个 `int` 相加不会溢出。第二段的上界是变量 `n`，片段没有限制它。`2147483646 + 2147483647` 在 UBSan 下报 signed integer overflow。不能把示例范围里的通过扩大成任意 `int` 端点都安全。

## 实数二分

blob `9b36a370c76c04198dee56c3e40f0d296eb205cd`。

第一段在 `hi - lo > max(1, lo) * eps` 时取中点；`check` 为真就下降上界。它使用 `eps`，但这段没有定义 `eps`。用外部 `eps = 1e-9` 寻找 `x >= 2.5` 的下界时，结果落在 2.5 下方约 `1.5e-9`。这不是输出值已经等于根的证明。

第二段定义 `long double` 和 `eps = 1e-7`，在固定区间 `[-1e4, 1e4]` 上比较相邻两点，保留函数值较小的一侧，返回的是函数值而不是自变量。`(x - 3)^2` 的返回值接近 0；`-x` 的返回值接近 `-10000`，也就是该区间的最小值。它不是任意区间、任意精度或最大值搜索。

## 证据

`python3 tests/wida_misc_snippets.py`：普通 `-O2` 与 ASan/UBSan 都通过上述字符、整数端点和两个实数例子。溢出用单独的 UBSan 运行确认，不放进普通通过计数。证据见 verification/wida-misc-snippets.json。没有在线 AC。
