# 无源汇上下界可行流（185）

为已有BoundedCirculation补齐LibreOJ 115完整用法，算法核心未改。通过[LibreOJ官方题目接口](https://api.loj.ac/api/problem/getProblem)读取displayId=115的中文题面、样例和判题配置；[题目页面](https://loj.ac/p/115)明确为独立模板题。约束1≤n≤200、1≤m≤10200、0≤lower≤upper<3000，点号1..n。无解输出NO；有解输出YES及按输入顺序逐行排列的m个流量。

## 接口与正确性约定

`add(u,v,lo,hi)`返回0起的原始边编号；它与内部Dinic的偶数残量边编号不同。输入边均按原顺序保留，包括重边和自环。构造完后仅调用一次`solve()`，成功才能读取`used(id)`，还原值包含该边下界。这里每个点都要求流量守恒，没有指定源汇，也不额外添加一条汇到源回边。

先给每条边放置lo流量，记录每点的流入下界减流出下界balance；剩余边容量为hi-lo。正balance表示还需通过剩余网络送出的流量，因此超级源连到该点；负balance的点连超级汇。若超级源需求全部送达，就得到所有点守恒的可行循环流，反之原约束无解。最终边流量等于lo加该边残量网络中的净流量。自环的下界在同一点抵消，不影响守恒。

接口使用long long。一般输入允许更大容量，但所有边下界总和不得超过LLONG_MAX，保证balance和超级源总需求安全；不能把本题upper<3000误当作接口上界，也不能忽略求和溢出条件。DFS保持递归；本地深链验证扩大进程主栈，没有改写算法。

## 本地验证

`tests/circulation_usages.py`编译实际打印程序，普通与ASan/UBSan分别运行。独立参照逐边枚举所有可能流量，合并可达的平衡向量，不使用另一份最大流实现。输出检查每条边上下界、每个点流量守恒、原始边顺序和逐行格式。

每模式包括420个两点有序多重图、728个三点有向图、400个随机小图；题目最大规模分别构造有解、无解和强制200点递归路径的三组。另列扩展：3个无边图、3×10^18容量和5万点递归链。共1556次完整程序调用。五个故意错误输出检查错误无解声明、不守恒、越界、缺行和一行多个流量均被拒绝。

`tests/circulation.cpp`双模式检查add返回原边编号、Dinic边编号映射、下界流量还原、自环/重边/孤立点、求解状态、无解状态和int64容量。打印用法还执行官方两组样例及自环、重边、固定流量的输入；答案按方案合法性核验，不要求与样例流量逐字相同。

LibreOJ允许读取题面和测试文件目录，但`downloadProblemFiles`接口返回HTTP 403，本批没有取得官方完整数据，也没有调用官方checker或新增线上AC。元信息获取与限制记录在`verification/circulation-statement.json`。
