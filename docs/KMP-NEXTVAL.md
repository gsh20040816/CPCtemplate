# KMP优化失败表nextval

用法344补齐kuangbin §1.1中`preKMP`的可观察输出及优化回退扫描，复用已有`prefix_function`，不新增重复KMP核心。普通匹配、顺序同构匹配分别见已有`kmp_match`与[SEQUENCE-MATCHING.md](SEQUENCE-MATCHING.md)。常规题直接用现有普通KMP即可；优化表只减少部分已知无效的字符比较，不改变O(n+m)复杂度，也不宣称当前OJ上更快。

## 表的准确含义

模式t长度m非空。普通前缀函数p[i]是t[0..i]的最长真border长度。`nextval[0]=-1`；对0<i<m，nextval[i]是满足下列条件的最大j：0≤j<i，t[0..j)=t[i−j..i)，且t[j]≠t[i]。若不存在则为−1。

失配发生在文本当前字符与t[i]不同的位置。若某个普通border长度j满足t[j]=t[i]，该状态必然还会失败，可以直接跳过。令j=p[i−1]：字符不同就保留j，否则使用已经计算好的nextval[j]。i递增且j<i，每项常数时间；无需修改原前缀函数，也无需再次沿长border链枚举。

**末尾nextval[m]使用p[m−1]，不能套用失配跳过规则。** 完整匹配后并没有一个t[m]字符与文本失配，因此必须回到普通最长border以保留重叠。例如模式`aaa`的表是`[-1,-1,-1,2]`，文本`aaaaa`的起点是0、1、2。模式中含零字节时也保持这个末尾约定，不能依赖零终止符参与比较。

扫描时j表示已匹配前缀长度。失配沿nextval回退，j=−1时消费一个文本字符并回到0；完整匹配后立即回退nextval[m]，下次读t[j]时始终j<m。文本为空仍输出表、数量0和空起点行；模式为空不在用法契约内。

## 演示协议

多组直到EOF，每组输入n,m，然后n个文本字节整数和m个模式字节整数，数值0..255。n≥0，1≤m<INT_MAX，实际长度还须满足内存限制。用整数读入使空文本、零字节及所有高位字节都能明确表达。输出三行：m+1个nextval项、匹配数量、升序0-based起点；无匹配第三行仍保留为空行。

预处理和扫描总时间O(n+m)，除两条输入字符串外额外空间O(m+答案数)。API直接展示表和扫描，不是某道线上题的完整协议，也不计作线上AC。
