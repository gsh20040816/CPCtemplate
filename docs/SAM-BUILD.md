# 指定状态在线扩展与直接Trie建图

本批新增OnlineSAM，并给GeneralSAM添加build之前的add(p,c)。两者都只使用vector，沿用a/go/link/len的数据布局，可以复用上一批SAMLex与sam_lcs。原单串SuffixAutomaton保持原样。

## 在线扩展的约定

OnlineSAM的根为0，缺失转移为0，根link=-1。`extend(p,c)`将字符c∈[0,26)接在p所代表的最长串后，返回结果状态；调用后即可查询全部已加入路径的子串并集。逐文档插入时每串从p=0开始。旧状态编号和len不变，go/link可变化。若手中只有落在p的较短匹配串，不能把它当成len[p]的最长串来扩展。

total维护不同非空子串数。a可读，但不要外部改写。此接口没有持久化历史，也不自动维护出现次数、终态标记或文档频率；反复加入相同路径不会增加total，但必要时仍可能分裂endpos状态。重置使用新对象。保存的是状态号，不能保存可能被vector扩容失效的Node引用或指针。状态总数、最大长度须可用int表示，数组须可分配；每次至多增加2个状态，总数保守不超过2Q+1，total≤Q(Q+1)/2，状态可索引的常规Q范围内long long足够。

没有对应转移时创建cur，将后缀链接链上缺失的该字符转移补向cur，再确定其后缀链接。遇到已有转移p→q时：若len[q]=len[p]+1可直接使用q；否则克隆q，克隆长度为len[p]+1，并重定向仍指向q的相应后缀转移。q和克隆分别承载较长、较短的长度区间。克隆不会增加已接受语言，q减少的len-link差与克隆新增的差正好抵消；真正的新cur只增加len[cur]-len[link[cur]]，所以total可以增量更新。

新节点分支会调用一次extend来处理一个已存在的转移；被调分支不再递归，故递归深度至多2。代码在该调用返回之后才访问a[cur]，避免vector扩容使引用失效。没有显式模拟DFS栈。

## 复杂度反例：任意在线顺序不能冒称线性

单次扩展的两条后缀链都严格降低len，因此为O(D+26)，D是当前最大串长。Q次给出保守上界O(QD+26Q)，空间O(26Q)。这不是按操作数线性的保证。

具体构造：先加入a、aa、…、a^n这条链，再依次在a^n、a^(n-1)、…、空根之后添加b，共2n+1次操作。第一次b补出整条后缀链；之后每次新增一个较短克隆，分别重定向n、n-1、…、1条已有转移，合计n(n+1)/2。因此仅有O(n)个节点的输入树，也可使这种顺序达到平方级。

测试对真实OnlineSAM核心仅插入重定向计数器，n=200/400/800/1600时精确得到20100/80200/320400/1280800。该结果证明上述具体最坏构造，不是平台速度排名，也不能从常见逐串输入测试推断所有调用顺序都快。

如果已知全部Trie边，应优先GeneralSAM的BFS构建。OI Wiki的[广义SAM构造](https://oi-wiki.org/string/general-sam/)按深度顺序处理Trie，说明了与任意顺序在线扩展不同的前提。用法256只是需要立即查询时的在线示例，明确暴露复杂度边界。

## 直接按Trie边建立GeneralSAM

`add(p,c)`仅在build之前调用，p是已有Trie节点，c∈[0,26)。返回子节点号；该标签边已存在则复用，不存在则新建。单次均摊O(1)，可把输入树的节点映射到Trie节点，同一根路径或重复同标签分支会合并。原`add(string)`内部按字符调用此方法，接口语义不变。

构造一棵有K个节点的Trie只需O(K)次边登记，再用原build以O(26K)时间/空间完成，无需把每条根叶路径展开成字符串。build后原Trie节点号仍代表原根路径，go则已变为SAM转移，不应继续当作原Trie边；所有add入口此后都禁止。重复build仍无副作用。

用法257自定义了父编号小于当前节点的输入格式，避免额外遍历；若题目以无向边给出，可按父子关系递归DFS或用真正的BFS登记。示例输出包含空串的总数，查询第1项输出空行，其余调用SAMLex::kth(k-1)。这只是对kuangbin TSUBSTR中相关能力的API演示，不是未核验输入格式的官方驱动。k须为正数，alphabet须为26字母排列。

## 本地验证

`tests/sam_build.py`每种核心形式运行39609组、3079185项检查：头文件/标准头抄写体各assert和NDEBUG，普通与ASan/UBSan两模式。穷举长度≤5的二字母历史父节点操作序列，随机分支操作，并从含克隆的SAM选取每个内部状态继续扩展。每一步独立枚举子串及(文档,结束位置)集合，核对endpos类、所有可接受路径、后缀链接、最长串句柄、增量total；同时检查直接Trie入口和原字符串入口。包含25万长克隆密集闭式结果和查询组件兼容性。

7个语义mutant分别破坏已有边克隆、克隆长度、旧节点后缀链接、新节点链接、增量计数、Trie返回值与逐字符父节点，均由参考拒绝。重定向计数器另行验证上述平方级例子。

三种完整程序形式各测试：在线分支API 101份、含空串排名API 101份、OnlineSAM的P6139 168份、原GeneralSAM的P6139 168份。P6139含已有文档中核验的两份官方样例、独立随机endpos类、百万长链/克隆密集串、两条50万交替串、40万文档合计百万字符和完整深15二叉Trie。空串排名API按完整输出文本检查，不能用split吞掉正确的空行。

修改GeneralSAM后，上一批查询runner也在两模式重跑：各核心形式2591组、510427检查，7个mutant，以及P3975/LCS/广义API三种完整形式各170/166/100份输入。原general_sam.cpp的3375组三文档穷举、2000组随机及逆序、百万链和40万重复串也在普通与sanitizer下通过。6个受影响完整用法重新编译执行，其他用法保留原证据。以上不是全库重新通过声明。
