# 带修莫队与树路径用法（168–170）

三份完整程序仅打印 main 和所需组件声明；vector 风格、递归 DFS、原字号。

| 用法 | 题目 | 直接调用范围 | 题目性质 |
|---|---|---|---|
| 168 | [P1903](https://www.luogu.com.cn/problem/P1903) | ModifiedMo.add/run，四个统计回调 | 原题明确标为模板题 |
| 169 | [P3398](https://www.luogu.com.cn/problem/P3398) | EulerLCA.build/lca/depth，路径交的非空判定 | 比赛应用 |
| 170 | [CF379F](https://codeforces.com/problemset/problem/379/F) | HLD.add/build/lca/dep，TreeDiameter.insert/length | 比赛应用 |

P1903 读入时用 cur 记录正确的修改前值，a 保持时间零。每次回退的编号和方向必须匹配；区间内修改先删旧贡献、再赋值、再加新贡献。颜色上界来自题面，通用值域须另行离散化。

P3398 的 depth 是边数；与 lca 使用同一根。空交、单点交、整段交都合法；题目仅看 vertices 是否非零，不能声称它在线检查了端点或精确数量。

CF379F 先读入所有添叶操作，建最终树，再按点号顺序插入。添叶不改变旧点距离，所以固定树度量的接口前提成立；不把未来顶点提前加入摘要。最终有 1000004 个点，用 HLD 保持线性空间，DFS 保持递归。此程序不调用 merge/farthest；完整接口由独立本地测试覆盖。

## 本地证据

`python3 tests/mo_tree_usages.py` 与 `CPC_SANITIZE=1 python3 tests/mo_tree_usages.py`：

- P1903 每模式 302 次完整程序调用：300 个随机操作流用 set 逐次求不同数；另有 n=m=133333 的全异区间查询、全区间查询与同点反复修改。
- P3398 每模式 247 次完整程序调用：146 棵至五点全部标号树及全部四端点，100 棵随机换号树，n=q=100000 链。独立 BFS 获取每条路径的顶点集合后求交。
- CF379F 每模式 251 次完整程序调用：250 个合法随机添叶过程，每步重建当前树并用两次 BFS 求直径；q=500000 长链实例逐个核对输出，递归深度 500001。

`python3 tests/usage_examples.py --only example-168 example-169 example-170` 验证实际打印代码的完整展开程序，普通及 ASan/UBSan 均通过。此前 167 份用法的指纹和两模式执行记录保持有效。

接口回归 `tests/modified_mo.cpp`、`tests/path_intersection.cpp`、`tests/tree_diameter.cpp` 双模式通过。带修莫队逐项检查活动区间、时间和修改前值，支持默认/自定义块长、空区间、零询问和重置后重放。路径交穷举全部根、四端点，核验返回端点间的路径等于集合交。直径枚举小点集、集合并、自合并、所有查询点，含零权和 LLONG_MAX 单边，检查最远点见证与长度。

路径交/直径旧测试引用的 classic 历史基线仅从提交 `1a9fa3e91d7dff58915341040be069611370054c` 提取到临时目录，未恢复到当前源码树。测试依靠独立集合和距离参照，历史实现只作附加比较。报告及源文件指纹见 `verification/mo-tree-regressions.json`。
