# 精确分数四则运算

本批新增 Rational、P1572完整驱动及任意精度API用法441/442，与本轮q-二项式合并后当前327组件、443份完整用法。覆盖两份WIDA分数来源的构造、规范化、四则、复合赋值、比较、近似转换及输出；本次没有线上AC。

## 接口和数值范围

默认 `Rational<>` 用long long保存最简分子num及正分母den，signed128作为中间类型。构造、每次运算立即约分，零为0/1。四则和全部六种比较支持默认版与整数混合；大整数版建议显式构造分数。`x+=x`、`x-=x`、`x*=x`、非零`x/=x`安全，因为先得到完整新对象再赋值。输出整数或最简分数；分子分母可读取，但不应直接修改。

每次构造和运算的最终最简分子须在[-2^63,2^63-1]内，正分母≤2^63-1。构造参数为long long时，包括LLONG_MIN在内的符号翻转均先提升到signed128；例如LLONG_MIN/LLONG_MIN合法且为1，而1/LLONG_MIN化简后正分母为2^63，超出保存域。除零、LLONG_MIN取负、最简结果超出保存域均不属于合法调用。断言只是开发时检查，NDEBUG不会扩大合法域。

设M=2^63，合法分子绝对值≤M，分母≤M-1。交叉积绝对值≤M(M-1)；加减两个交叉积绝对值≤2M(M-1)=2^127-2^64，严格小于signed128正上界，且不会达到signed128最小值。乘法分子绝对值≤M²=2^126，除法分子和分母也在这个级别。故所有默认运算的约分前中间值、取绝对值、gcd及符号翻转均可表示，不要求它们先能放入64位。约分后检查范围再窄化。

`Rational<cpp_int,cpp_int>`配合Boost头文件支持任意精度；gcd的余数显式保存为W，避免把大整数表达式模板当作稳定值。时间取决于大整数乘除和gcd成本，不声称常数时间。其他T/W组合不在本次完整验证范围内，使用者需自行证明范围。`assign/make`仅为内部实现，不能以任意signed128极值直接调用而绕过构造的输入域。

显式double转换只是近似。尤其任意精度分子、分母分别转double可能溢出并产生非有限结果，不能用于精确排序或判断；精确比较始终用整数交叉积。

## 完整用法与验证

[洛谷P1572正式题面](https://www.luogu.com.cn/problem/P1572)提供加减表达式协议，长度≤100，分子分母≤1000，并保证逐项化简的中间结果在int内。输入流读取带符号分子，随后读取斜线和分母，不需要另外解析正负号；输出格式与默认分数输出一致。该题只验证加减，不能据此声称乘除、任意精度已在线覆盖。

核心普通和ASan/UBSan各2600000次小范围原稿交叉对照及自运算/比较检查；包含signed64边界、负分母、可约分大中间值和4096位大整数。另有44178组独立Python Fraction真值，含最高199位十进制整数、六种比较和自运算。完整纸面程序与头文件程序分别通过NDEBUG普通版和ASan/UBSan：300条合法P1572表达式，以及500项任意精度API操作。证据见verification/fraction.json与verification/fraction-usages.json。

没有取得本次线上判定，覆盖表为local-tested。来源引用QOJ498911的完整原题协议仍未获取；通用分数组件覆盖与该原题验证分开记录。
