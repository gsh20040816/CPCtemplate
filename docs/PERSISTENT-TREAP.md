# 可持久化有序 Treap

`PersistentOrderedTreap` 维护可重整数集合的分叉历史。与现有 `OrderedTreap` 的单个可变根不同，更新从指定版本出发复制路径，旧版本和兄弟分支继续可查。它不提供序列反转、区间懒标记或跨对象根合并。

## 接口与版本

版本 0 是空集合。`insert(v,x)`、`erase(v,x)`、`copy(v)` 都追加一个版本并返回编号；删除不存在的值也产生一个与 v 相同的版本。删除只移除一个副本。查询 `size(v)`、`less(v,x)`、`less(v,x,true)`、`rank(v,x)`、`kth(v,k)`、`prev(v,x)`、`next(v,x)` 不创建版本，也不分配树节点。

`rank` 为严格小于 x 的副本数加一，不要求 x 存在；`kth` 的 k 为 1-based，调用方保证合法。前驱和后继严格比较，不存在返回 `nullopt`，不保留有限哨兵键。支持 `LLONG_MIN`/`LLONG_MAX`，不计算 x±1。

多测重新构造对象。`t`、`root`、节点编号和递归辅助函数是内部状态，外部不得改写；允许提前调用两个 vector 的 reserve，不改变版本语义。所有节点数、版本数、每版副本数须小于 `INT_MAX`，使下标、子树大小和排名加一可表示。

## 为什么历史版本不变

每个不同键维护一个节点和副本计数。插入先复制访问节点，再递归修改其孩子；旋转只修改本次新复制的父子节点。删除复制实际发生变化的路径；删除最后一个副本时，合并两棵共享子树也只复制选中的合并路径。删除不存在的键沿原路返回原节点编号，不分配树节点。

只把节点编号保存在局部变量中，不跨递归分配保存 vector 元素的引用。vector 扩容可以搬走整个节点池，但编号仍然有效。`copy` 只追加原根编号；它不分配树节点，但版本表自身仍可能扩容，时间为摊还 O(1)，不能据此声称整个进程绝不分配内存。

在随机优先级假设下，更新与顺序统计查询期望 O(log(d+1))，d 是所查版本的不同键数。递归深度与该版本树高有关，没有确定性最坏对数保证。节点池不回收，内存按全部历史更新复制路径的总长度计算，而不是某一版本的集合大小。固定种子便于复现，不代表对知道该种子的对抗输入仍有随机保证。

## P3835 完整用法

[官方题面](https://www.luogu.com.cn/problem/P3835) 要求每次操作都产生版本 i，查询操作也如此。因此驱动在打印查询答案后调用 `copy(v)`；插删操作直接产生新版本，不额外 copy。前驱/后继缺失时分别映射为题目要求的 -2147483647 和 2147483647，哨兵只存在于输出适配层。

输入至多 500000 次操作，键绝对值至多 10^9，过去版本编号小于当前操作编号。实现支持的完整 long long 键范围不意味着题面允许该范围；二者测试证据分开记录。完整调用见 `verify/luogu/P3835.compact.cpp`，书中只呈现调用与题意，算法正文单独收录。

## 内存预算

当前常见 64 位构建中节点大小为 32 字节。vector 自动倍增的容量可能明显大于实际节点数，扩容时还需同时容纳新旧缓冲。驱动预留 `26*n+1` 个节点及 `n+1` 个版本槽，以减少实测规模下的增长浪费；这只是明确的预留预算，不是节点数上界，也不限制后续增长。n=500000 时预留节点容量为 416000032 字节，必须先核对题目内存限制。

固定测试种子的 500000 次随机不同键插入使用 11989642 个节点；不预留时容量达到 512 MiB，峰值 RSS 533136 KiB。预留后容量约 397 MiB，峰值 RSS 382208 KiB。时间和内存是本机这组数据的观测，不是所有输入的界，也不是线上性能排名。当前取得的官方题面文本没有给出内存限制，因此不宣称已满足线上内存限制或获得 AC。

若内存预算不足，不能简单把 reserve 数字减小后就认为峰值更低；应核算实际节点、容量增长与重分配成本，再选择键宽、节点布局或其他实现。保留完整 long long 键和重复计数是本实现的明确取舍。

## 验证范围

`tests/persistent_ordered_treap.cpp` 使用逐版本排序 vector、深度有限的全分叉枚举、旧节点字段逐项快照和多个种子，检查重复键、极值、历史版本不变、查询不分配节点、copy 根别名及不存在删除。另有 500000 次随机、顺序和重复键压力模式。

`tests/persistent_treap_application.py` 打包实际 P3835 驱动，执行 100 组各 1000 次随机分叉操作，再执行一份恰好 500000 次的长历史、兄弟删除和查询版本别名输入；答案用独立排序快照或区间集合事实生成。普通与 ASan/UBSan 分别运行，当前环境关闭不兼容的 LeakSanitizer，泄漏检测不在通过声明内。未提交线上评测。

复现命令：`g++ -std=c++20 -O2 tests/persistent_ordered_treap.cpp -o build/persistent-treap && build/persistent-treap`；压力模式加 `random 500000 reserve`、`sorted 500000` 或 `duplicates 500000`。题目驱动执行 `python3 tests/persistent_treap_application.py`，消毒器模式加 `SANITIZE=1`。精确书内调用测试为 `ASAN_OPTIONS=detect_leaks=0 python3 tests/usage_examples.py --only example-199`。源码、模式、输出和内存观测记录在 `verification/persistent-treap.json`。
