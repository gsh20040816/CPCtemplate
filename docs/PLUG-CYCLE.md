# 插头 DP：覆盖全部可用格子的单个闭环

`grid_cycle<Count>(a)` 输入矩形字符串网格：`.` 必须经过，`*` 不能经过。相邻仅指上下左右。统计覆盖所有可用格子的一个无向简单环，每格度数恰为2；起点和行进方向不造成不同方案，旋转/翻转后的不同边集仍分别计数。空网格、全障碍、单行和单列均为0；不支持多环覆盖、开放路径或重复经过顶点。

函数自动转置，使轮廓宽度 m=min(原行数,原列数)。矩形、字符合法且尺寸可用int表示是前置条件，m≤15。状态有m+1个槽，每槽4位，使用unsigned long long编码。槽j、j+1分别是当前格子的左、上插头；处理后分别存下、右插头。每行开始左移4位，右边界槽因禁止越界连接恒为0，因此不会丢失有效插头，最大移位为60位。

每个非零编号代表一条尚未闭合的路径，其两个端点位于轮廓线上，故每个编号出现两次，最多8条路径。按槽位首次出现顺序将编号映射到1,2,...，零仍为零，使同一连通关系只有一个编码。创建路径临时使用15，不与已规范化的1..8冲突。unordered_map的哈希碰撞只影响速度，完整键比较保证计数正确；这里不存在以哈希摘要代替连通性判等。

转移分四类：无入边时必须同时连下、右并创建一条路径；一条入边时选择下或右延伸；两条不同编号的入边连接两条路径，将其剩余端点统一编号；两条相同编号的入边会闭环，仅在最后一个可用格子且其他槽全零时累计答案，不能再作为普通状态传播。障碍格只允许两条入边均不存在。其他情况舍弃。

正确性不变量：处理过的可用顶点度数已经确定为2，未完成连通分量均为不相交路径，轮廓恰记录它们的两个开放端点。各转移枚举当前顶点所有合法度数2的边选择并准确更新路径连通性。若提前闭环，剩余顶点或其他路径无法接入这个度数已满的环，故必须拒绝；合法最终环一定在扫描的最后一个可用顶点闭合。每个边集唯一决定逐格选择，因而既不遗漏，也不因路径方向重复计数。

令S为扫描过程中最多的可达轮廓状态数，使用固定宽度计数类型时，期望时间O(n*m²*S)、状态表空间O(S)，另有网格副本O(nm)与临时轮廓O(m)。S随宽度指数增长，不能因编码容纳15列就视为多项式算法；哈希表没有最坏常数时间保证。Count需支持零初始化、整数0/1构造、复制和+=，所有中间状态的计数都必须可表示。long long和__int128需要证明中间值不会溢出；模整数返回模意义计数；cpp_int给出精确整数，位复杂度还需乘计数位数的代价。

完整驱动对应[P5056](https://www.luogu.com.cn/problem/P5056)（2≤n,m≤12，页面1秒/125MB），使用`__int128`并手写十进制输出。数值界证明：仅当前格子同时能向下和向右延伸时可能有两个后继，其他情况至多一个；这样的格子最多(n-1)(m-1)≤121个，所以所有部分选择历史以及每个状态的计数都不超过2^121，小于2^127。这是针对正式题输入域的中间值上界，不靠最终答案大小猜测。首次Boost驱动提交R302626160因评测环境缺少头文件CE，新驱动[R302626494](https://www.luogu.com.cn/record/302626494)已100分AC，10个测试点，单点最大323ms、总时间414ms、峰值2.42MB；排名未核查。代码为本项目独立实现；模型与规范化编码参考[OI Wiki插头DP](https://oi-wiki.org/dp/plug/)，没有复制其实现。

本地验证：独立递归Hamilton环搜索从最小编号点出发，除去两个方向；穷举行列均为1..4的74954种障碍布局，另有500个随机5×5网格、宽15边框环、全障碍和两个独立小环反例。头文件、NDEBUG和最小抄写形式通过O2、ASan/UBSan。大例使用[OEIS A003763](https://oeis.org/A003763)的2×2至14×14完整方格独立枚举值；14×14超过64位，用以验证Count没有被意外截断。
