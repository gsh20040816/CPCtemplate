# 广义 SAM 的状态数口径

后续指定状态在线扩展与直接Trie边接口见 `docs/SAM-BUILD.md`；本文件中未提供接口的说法属于此前批次，当前范围以新文档和coverage.csv为准。

`GeneralSAM` 用 Trie BFS 原地构造，维护按 `(文档编号, 结束位置)` 定义的 endpos 等价类。支持不同非空子串计数及沿转移判定子串；不自动提供终态标记、文档出现次数或最小 DFA 化。

## P6139 的官方样例口径

[洛谷 P6139](https://www.luogu.com.cn/problem/P6139) 当前题面将第二行描述为接受各串后缀的最小 DFA 点数，并补充可认为是广义 SAM 点数。这两种描述不能在一般多串场景下直接等同。

2026-09-29 在题目页面重新核对的官方样例一为：

```text
4
aa
ab
bac
caa
```

官方输出为 `10`、`10`。直接枚举所有子串及 `(文档编号, 结束位置)` 集合，得到10个不同非空子串和包含根的10个 endpos 状态。
但把这些字符串所有后缀的 Trie 按终态及子转移签名合并，仅有7个状态；直接枚举每个前缀的右语言（可接上去而被接受的字符串集合），同样得到7种。均省略拒绝汇点。
因此**官方样例明确要求 endpos 点数**；本库的 `a.size()` 符合这个口径，不能为了题面的“最小”二字再合并成7点。
这只是可重现的样例及本地验证证据，尚不是隐藏评测全部通过的证据。

## 两种语义的最小反例

输入 `ab`、`b`，不同非空子串为 `a`、`b`、`ab`。其 endpos 集合分别为 `{(0,0)}`、`{(0,1),(1,0)}`、`{(0,1)}`，加初态共4个广义 SAM 状态。

仅识别后缀并集时，部分 DFA 可用3个状态：初态 R 在 `a` 上转向 A，在 `b` 上转向 B；A 在 `b` 上转向 B，B 为终态，其他转移拒绝。若包含空后缀，R 也标为终态。B 和读完 `ab` 的状态可合并。这里省略拒绝汇点，与通常 SAM 的表示一致。

[OI Wiki 的广义 SAM 构造](https://oi-wiki.org/string/general-sam/)与 issue #11 附件的逐串扩展版本均以子串状态与后缀链接为核心。附件最后输出不同子串数和已创建状态数；不含 DFA 最小化步骤。本库使用 Trie BFS，插入顺序不影响 endpos 状态数量。

## 使用与边界

先对所有小写字符串 `add(s)`，再 `build()`，输出 `distinct()` 与 `a.size()`。构造后禁止继续插入；新建对象可重置，重复 build 不改变结果。空串可以作为库输入，但P6139输入每串非空；重复串允许。固定26字母表，登记总时间 O(L)，构建时间与空间 O(26K)，K 是 Trie 节点数；状态数小于2K。

`verify/luogu/P6139.compact.cpp` 第二行采用上述 endpos 口径，作为 example-132 纳入本地已验证用法。线上验证仍待补，不表示已获 AC。
