# 完整64位固定模整数

新增 `StaticMod64<P>`，用于需要固定64位模数的组合计算。支持1≤P≤UINT64_MAX，可为合数，复用已有精确 `Mod64` 乘法和幂。当前331个组件、449份完整用法。它补齐07E固定64位包装的主要算术接口，不替代普通int模数类型。

## 接口与抄写

依赖Mod64，先抄依赖再抄本结构。构造接受不超过64位的标准signed或unsigned整数，支持LLONG_MIN和UINT64_MAX；默认零。公开成员v保持[0,P)，只能读取，不要直接赋非规范值。输出直接使用v，超过LLONG_MAX的余数不能转long long。

支持加减乘、一元负号、==/!=以及+=、-=、*=。pow(k)接受完整uint64非负指数，约定0^0=1 mod P。try_inv()在gcd(v,P)=1时返回规范逆元，否则nullopt；inv、/和/=要求分母可逆，断言关闭时不保证诊断非法调用。模1的唯一余数为0，按gcd(0,1)=1，逆元也返回0。

没有增加字符串解析和流重载；按题目范围用signed64或unsigned64读取，再构造。用法449在固定合数UINT64_MAX下展示signed64的a、unsigned64的b、完整uint64指数及不可逆输出-1。128位或任意精度输入须先自行正规化，不能直接传给构造函数。

加减乘O(1)，pow为O(log(k+1))，求逆O(log P)，额外空间O(1)。依赖GNU/Clang的128位整数。大整数除法通常比32位运算慢，只有数值范围需要时才用此类型。

## 溢出论证

加法不先计算可能溢出的v+b：若v≥P-b，则结果为v-(P-b)；否则v+b<P≤UINT64_MAX。减法在v<b时计算P-(b-v)，所有减法均有非负结果。取负单独处理0。

乘法将两个uint64先提升unsigned128，乘积至多(2^64-1)^2，可精确表示，再对P取余；不使用long double。构造先把signed/unsigned输入和P提升signed128，做有符号余数并加P正规化，因此不会把大模数强制转成负signed64。

扩展欧几里得的余数和系数均用signed128。对于两个非负且不超过2^64-1的初始值，标准系数递推在相邻余数下降时交替符号；终止前系数及商乘前一系数的量级受初始输入控制，远低于signed128界。最后系数在(-P,P)内，负数补P后再转uint64。模1也沿同一过程返回0。

## 验证与来源区别

普通NDEBUG与ASan/UBSan各1486662项独立Boost cpp_int检查：1..40全部小模数的规范输入穷举，十个代表模数的随机运算与完整指数幂、signed/unsigned构造边界、自赋值别名、逆元存在性与乘积证书。

准确纸面与头文件驱动分别在普通和消毒器模式下对照4140组Python任意精度真值，包含UINT64_MAX模数下不可逆的3、逆元超过signed64范围的2，以及零/最大指数。见verification/static-mod64*.json。

WIDA07E原浮点估商在本机53位long double下存在已复现反例，原固定包装的加法也不支持未经额外限制的完整uint64模数；本版分别用整数模乘和先比较后加减替代。原包装固定inv假设素数，本版允许一般单位逆元。原稿std::strong_ordering比较普通余数，本版需要大小比较时直接比较v；没有定义模环内在序关系。

07E的来源应用和接口最终核对仍待完成，覆盖仍标partial。本批没有新增线上AC，不能用其他模整数历史提交替代本类型验证。

同机GCC16/C++20/O2，模18446744073709551557，300万次依赖乘加链，交替三轮：直接uint128乘加取余中位0.024932秒，包装0.024804秒，约0.995倍，属于该工作负载下基本一致的量级。不是线上时间或普遍加速保证，原始记录见verification/static-mod64-performance.json。
