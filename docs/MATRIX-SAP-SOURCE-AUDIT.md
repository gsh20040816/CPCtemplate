## 不能混淆的两个接口

| 原条目 | 容量存储 | 同源汇第二次调用 | 当前映射 |
|---|---|---|---|
| 4.16.1 | maze直接变成残量矩阵 | 返回0，保留已有最大流后的残量 | 同一Isap对象继续flow，或从已有残量矩阵重建求本次增量 |
| 4.16.2 | maze保持原容量，flow矩阵每次清零 | 重新计算并返回完整最大流 | 从容量矩阵每次新建Isap，再求流 |

第二份允许重选源汇，因为每次从零重算。第一份交换源汇则在已有残量图上求流，得到的不是原容量图的新方向最大流：若原先s→t已送F，反向原最大流为G，当前残量图t→s最大流为F+G。新增的F部分是在撤销原流。本测试用独立割枚举验证这个关系；不能在同一个Isap对象里偷偷改源汇并套用其同源汇接口合同。需要这个残量矩阵问题时，应把当前残量当作一个新网络构造。

原flow[u][v]是反对称净流，满足−cap[v][u]≤flow[u][v]≤cap[u][v]；有两个方向的原容量时，flow可以为负。它不是逐条原边非负流量。原第一份的净流可由初始cap减最终maze得到。

同向重边放进矩阵时需累加容量；覆盖赋值会丢边。同一个有序点对的多条原边无法从矩阵净流唯一恢复。若只需任选一个逐边方案，可以把正净流按各原边容量分配、令相反方向为零；若要直接读取每条原边方案，保留原边列表并逐次add更直接。

## 一个简洁的当前用法

下列代码接受0-based非负方阵cap和不同源汇；依赖Isap，每次重建，返回完整最大流与反对称净流矩阵，输入保持不变。总最大流须≤LLONG_MAX。它是来源模型的接口示例，不是新增组件或正式OJ驱动。测试直接编译这段代码对应的`current.inc`，最终说明中的代码会逐字比对。

```cpp
using Matrix = vector<vector<long long>>;

pair<long long, Matrix> matrix_flow(const Matrix &cap, int s, int t)
{
    int n = (int)cap.size();
    Isap g(n);
    for (int u = 0; u < n; u++)
        for (int v = 0; v < n; v++)
            if (cap[u][v]) g.add(u + 1, v + 1, cap[u][v]);
    long long value = g.flow(s + 1, t + 1);
    Matrix net(n, vector<long long>(n));
    for (int id = 0; id < (int)g.e.size(); id += 2)
    {
        auto a = g.e[id];
        int u = a.from - 1, v = a.to - 1;
        net[u][v] += g.used(id);
        net[v][u] -= g.used(id);
    }
    return {value, net};
}
```

由返回net重建残量时，用`int128(cap[u][v])-net[u][v]`，不能直接在long long里相减。例如两方向容量均LLONG_MAX，正向满流后反向合并残量为2×LLONG_MAX。Isap把两个原边的残量对分别存储，单条仍不超过其原容量，因此这个案例本身受支持；仅合并后的矩阵残量需要加宽。

该包装构造及方案占O(n²)空间和扫描时间，最大流使用现有ISAP界O(n²m)，m为非零容量项数；不新增完整矩阵算法实现，也不声称两种容器一定谁更快。用户要求默认vector并避免重复封装，故这里保留原稿语义的建图/输出映射。

## 原稿边界

两份原稿MAXN=1100，但gap也只有1100格，重标号可以达到nodenum。空图n=1100时首次重标号就会写gap[1100]；两版均由独立UBSan进程重现。通用安全点数应限n≤1099，不能直接由maze大小推断支持1100点。

原稿int还可能在单个残量中溢出，即使最后最大流仍能放进int。第一份两点双向容量INT_MAX，正向增广后执行反向容量加法溢出；第二份使用六点改道网络：0→1、0→2、1→3、1→4、2→3、3→5、4→5容量均1，另有3→1容量INT_MAX。先送0→1→3→5，再沿0→2→3→1→4→5撤销旧流时，3→1的合并残量为INT_MAX+1，选增广瓶颈时的`maze-flow`实际溢出。这两个不同算术位置分别由UBSan重现。测试的正常对照域使用n≤1099、容量非负且所有矩阵项总和≤10^8，保证答案、反向合并残量及有符号净流均在int内；不声称这是任何官方OJ的题目限制。

原稿没有完整输入main，也没有绑定官方题目；不补造题号。当前ISAP的P3376用法和已验证边界见[ISAP](ISAP.md)，不把这份矩阵示例当作新的在线AC。
