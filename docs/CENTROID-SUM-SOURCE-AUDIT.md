## 对应现有模板

使用已有 `CentroidSum<long long>`，不新增重复组件。原稿和当前算法均按重心祖先保存距离，查询时加总桶、减去同一分支桶；赋值更新必须把 `new-old` 同时加入两类桶。原稿逐点向Fenwick加值建树，最坏构造O(n log² n)；当前按距离收集后线性建Fenwick，构造O(n log n)。两者操作最坏O(log² n)、空间O(n log n)。原稿大小和距离采用队列遍历，当前保留递归DFS，最坏调用深度O(n)，本批提供512 MiB本地栈。

| 原稿 | 当前 |
|---|---|
| 1..n点号，输入边无权 | 0..n-1点号，`add(u,v)`固定单位边树 |
| 全局 `val/vec/bits/cc` | 对象内 `value/path/all/part` |
| 距离d直接作为0-based Fenwick下标 | 距离d使用1-based下标d+1 |
| `! u x`令点权等于x | `set(u-1,x)`，不是增量 |
| `? u d`为距离球求和，包含u自身 | `query(u-1,d)` |
| 每组重置TT、池指针、编号与各点vec | 每组构造对象并build(values) |
| 权值、差值、桶和、答案、半径均int | 本次适配long long；所有中间运算仍必须可表示 |

完整适配在 `tests/centroid_sum_source_driver.cpp`，可直接阅读或用 `tools/bundle.py` 展开。它仅复现原稿EOF多组数据、`!`赋值和查询的输入协议，放在tests而不是正式OJ驱动目录。当前库已有的P6329手册用法及其异或协议不变，不能将两题的输入解码混用。

## 独立验证

测试 `tests/centroid_sum_source.py` 不依赖C++ assert检查输出：Python以BFS求原树距离，直接扫描当前权值求和。普通及ASan/UBSan分别运行原177行程序、当前头文件assert/NDEBUG、完整展开assert/NDEBUG共5种形态。

- 穷举n≤5的146棵标号树，检查所有中心和各半径；每点重复赋同值后再检查全部距离球。
- 180棵随机树，混合150次赋值/查询，含负点权、负半径、零半径、超过直径及INT_MAX半径。与穷举树串成同一进程326组输入，共42967个查询，检查多组数据状态重置。
- 十万点链、星、平衡树、随机树，每种2400次操作；小半径由BFS扫描核验，全覆盖半径直接求和。每份大树后紧接单点树，防止池指针或vec残留。四种输入每份1802个查询。
- 当前四种形态额外验证双INT_MAX点权总和、INT_MIN到INT_MAX赋值、LLONG_MIN负半径及LLONG_MAX半径。
- 漏更新分支桶、漏减分支桶、赋值误作增量三个错误变体均被独立答案拒绝。

来源正常对照在int安全范围内；负点权和负半径是额外来源模型测试，不声称原题允许。消毒器关闭本环境的LeakSanitizer，未声明泄漏检测通过。

## 原稿整数边界

独立运行原程序，由UBSan分别重现：

1. 两点权值都为INT_MAX，构造时Fenwick桶相加溢出。
2. 单点原权INT_MIN，赋值INT_MAX，`d-val[u]`差值溢出。
3. 两点零权树，查询半径INT_MIN，非重心点计算`d-distance`下溢；即使数学答案为0也不能直接做int减法。

这些均是额外接口边界反例，不宣称是原题合法输入内的错误。当前long long适配通过前两类值；负半径先返回0，避免第三类减法。

原稿MAXN=100010，点和队列均从1开始，因此静态点号上限是100009，本批最大实跑100000。每个重心块大小s分配总桶s，加各分支桶大小r+1；所有重心层累计池用量恰为 `2*Σs-1`，因为分支总数n-1。重心子块不超过一半，故 `Σs≤n*(floor(log2(n))+1)`，在该点数上限内小于原40*MAXN池。Fenwick对象数量恰为2n-1。此为静态容量推导，不冒充已实跑每种最大拓扑。

来源 `char op[10]` 配合不限定宽度的scanf仅用于符合单字符操作协议的输入，不提供任意字符串解析保证。重复数据组时间戳TT也要求int可表示。
