# 有限二进制浮点极角的精确排序

`RealPolarLess` 是独立比较器，沿用 `RealPlane::Point` 的 long double 存储，不调用其近似 dot/cross，也不修改现有几何构造。`example-228` 是自定义API演示，不是正式OJ题。新增后208个算法、228份用法；正式模板组件154、仅应用43、仅API8、待补3。分类不代表在线AC。

## 输入契约和顺序

输入是实际已存入的有限二进制浮点值，尾数精度p≤64；需要目标支持GNU unsigned int128。拒绝NaN/Inf作为角度，+0和−0数值等价。依赖正常、符合标准的frexp/ldexp与比较语义：不支持fast-math、FTZ/DAZ、修改x87有效精度等破坏这些条件的环境。普通四种舍入方向另有局部测试，不要求只有最近舍入。

顺序为原点最前，之后从正x轴起逆时针[0,2π)，同向按距离递增，数值相同的向量等价。它是严格弱序，不把“很接近”的角度归到epsilon组。

精确性只针对已存储二进制值。十进制输入先舍入；调用前若减去参考原点，该减法的舍入、溢出或下溢不会被修复。它不是任意中心的稳健orientation、通用浮点凸包或圆交点实现。p>64、无uint128的目标明确不在支持范围；不能据本机double精度路径检查声称测试过其他ABI/操作系统。

## 为什么两个浮点乘积可以精确比较

对非零有限x，frexp给出abs(x)=f·2^e，1/2≤f<1。在p位二进制格式中，u=ldexp(f,p)是精确整数，即使原x是次正规数也成立；2^(p−1)≤u≤2^p−1。p≤64时转换到uint64_t精确，p=64也不会把2^64转入整数，更不能先转到signed64。

对于乘积x·y，先提升到unsigned128再计算M=u_x·u_y，有0<M<2^(2p)≤2^128。设b为M的位数，保存V=M<<(128−b)和E=e_x+e_y−2p+b；精确绝对值等于V·2^(E−128)，且2^127≤V<2^128。移位在0..127，无位丢失；指数相加前先提升到long long。

不同E对应互不重叠的半开数量级范围；E相同时比较V。先比符号，两个负乘积反转绝对值比较，含零乘积直接处理。这样比较a.x*b.y与a.y*b.x就得到精确叉积符号，无需直接形成两个坐标的浮点乘积、相减或距离平方；ldexp只做上述可精确表示的二次幂缩放。product/cross_sign是仅接受有限值的内部辅助；主比较入口保留有限值断言。

本机p=64时非零frexp指数范围[-16444,16384]，归一化乘积E范围[-32889,32768]；binary64相应为[-1073,1024]及[-2147,2048]。使用long long保存指数不是把浮点转换成大整数坐标，也不分配任意精度存储。

## 严格弱序与长度并列

半圆条件y<0或(y==0且x<0)区分[0,π)和[π,2π)。同一半圆内不同方向相差严格小于π，故正叉积就是角度递增。叉积为零时，非零向量在同一半圆只能同向，不能反向。沿非竖直射线abs(x)与长度成正比，竖直射线则用abs(y)，无需可能溢出的距离平方。原点提前单独处理，因此整个顺序传递，同点（含零符号差）等价。

每次比较只有定长整数操作与常数次frexp/ldexp，无分配和查表。std::sort需要O(n log n)次比较；这不构成比直接浮点叉积更快的排名或评测时限保证。

## 可抄写演示

`docs/usage-drivers/real-polar-demo.cpp` 读0≤n≤200000和n对坐标，按上述比较器排序后输出1-based原编号；完全相同数值再按原编号打破并列。它使用普通格式化提取，不承诺整词、整行或EOF校验；只对实际读入失败、n越界或非有限值返回1。末尾额外内容和已接受数值前缀后留下的字符不是有效协议的一部分，不把它伪装成严格词法解析器。

测试的精确dyadic十进制案例选取能被正常表示并成功转换的值；非精确十进制例的参考基于实际读取值的独立十六进制解码，不基于舍入前实数。某些C++库对次正规数的十进制输入会报告范围错误；主程序不承诺接受所有这类拼写，核心次正规范围由直接构造的精确值测试。
