# WIDA 07E 固定模整数补充审计

在 Barrett32 与动态 mint 接入后，继续审计同一精确原稿里的固定模数包装及浮点64位模乘。原稿为 `tests/fixtures/wida_mod_reduction/07E.cpp`，Git blob `c5af9ebd28047a3c6bd7023cbe26150761c8e86b`，本批没有新增算法组件或线上AC。

## 当前范围

普通与 ASan/UBSan/float-cast-overflow 两种构建各1000001项精确算术检查。固定32位包装在模998244353下随机10万组加减乘除通过；invGcd在10万组完整signed64输入和正signed64模数上通过gcd、返回范围和同余证书。浮点模乘分别在三个模数下取10万组规范输入，与uint128整数余数比较，并核对现有Mod64输出。

本机 GCC16 的 long double 有效精度为53位，不是所有平台都如此。普通和消毒器结果一致：

| 模数 | 10万组中浮点原稿错误数 |
| --- | ---: |
| 1000000007 | 0 |
| 1000000000000000003 | 64577 |
| 9223372036854775783 | 97023 |

最简已复现反例：m=9223372036854775783，a=b=m-1，精确答案1，原稿701。另一个模数下，a=476281729113641836、b=369164126775384218，原稿59710031966572773，正确值612965958257021214。精确值也由Python任意精度运算独立核对。

这是浮点估商在本平台精度不足的算术错误，不是消毒器报错；没有据此推断不同long double精度的历史OJ提交必然失败。现有Mod64使用uint128整数余数，不依赖浮点精度，仍作为64位核心。

固定64位包装的加法还有独立的上界问题：模18446744073709551557，(m-1)+(m-1)在uint64中先回绕，原稿返回18446744073709551496，正确余数18446744073709551555。signed构造还把模数转成signed类型，所以不能把这个包装直接宣称支持完整uint64模数。原稿固定包装的inv使用费马幂，也不能推广到一般合数的单位逆元。
