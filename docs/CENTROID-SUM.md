# 动态点分树 距离范围内的点权和

`CentroidSum<T>` 处理固定无权树上的点权修改与距离球求和。它与静态 `CentroidPairs` 的全树点对计数不同：一次查询指定中心 u，返回所有满足 dist(u,v)≤k 的点 v 的权值总和，包含中心本身。只改点权，不修改拓扑。

## 接口

`CentroidSum<long long> tree(n)`，n≥1。先用 `add(u,v)` 加入连接树的 n-1 条单位长度无向边，点号 0..n-1，再 `build(values)`。`set(u,x)` 是赋值而不是增量；`query(u,k)` 返回距离不超过 k 的和，k 可为 long long，负 k 返回 0。`build` 可在同一固定树上再次调用，清空分解状态并替换所有点权。建树后不能继续添加边。

默认 T=long long；T 需要零值及加减，相关运算视为 O(1)。点权可以为负，但所有桶内累加、Fenwick 内部和、赋值差以及查询容斥的中间值都必须可表示。仅保证最终答案不溢出不够。内部邻接表、重心路径和 Fenwick 桶不作为外部可修改接口。

## 每层加总再减去同一分支

每个顶点保存其所有重心祖先记录 `(c,d,b)`：到重心 c 的原树距离 d，以及它位于删除 c 后的哪一支 b；顶点就是 c 时 b=-1。重心 c 的 all 桶统计当前分解块内所有顶点按 dist(c,v) 分类的权值，part 桶只统计对应分支。

查询 u 在这层先加入 all[c] 中距离≤k-dist(u,c) 的权值，再减去 u 所在的 part[c][b] 的同一范围。同一支的点留到更低重心层处理；不在同一支的点到 u 的路径经过 c，距离相加正确。某对 u,v 在第一次被重心分开的层恰好留下一个贡献，中心本身也不会遗漏或重复。

修改点权时先算 delta=new-old，然后沿该点的全部记录更新 all 与非空分支桶。每层同时更新两类桶，不能仅更新 all，否则同支容斥会使用旧权值。

## 距离桶与复杂度

距离 d 存入 1-based Fenwick 的 d+1 位置。查询负半径直接返回 0；大半径截断到桶末尾，避免将 long long 半径盲目转换为 int。复用的 `Fenwick<T>` 来自 `data_structure.hpp`，不需要 kth 的非负频数条件，因为这里只做加法和前缀和。

每层用 DFS 收集原始距离桶，再线性构造 Fenwick，而不是对每个顶点逐次做对数插入。单层工作和空间均与当前块大小成正比，重心层数 O(log n)，故构造及总空间 O(n log n)，修改和查询 O(log² n)。

重心分解本身只有对数层，然而寻找大小、收集距离的原树 DFS 在链上可达 O(n) 深度。实现保持仓库要求的递归写法；测试提供 256 MiB 栈，不能把重心层数误写成所有递归的最大深度。具体评测环境的栈限制仍须核对。

## P6329 的在线适配

[官方题面](https://www.luogu.com.cn/problem/P6329) 使用 1-based 顶点，操作 0 查询、操作 1 赋值。每条操作的 x 和 y 必须先与最近一次查询答案异或，随后才把 x 减一；操作类型不异或。只有查询更新 last，赋值操作保持 last 不变。不能先解码整份输入或对更新操作错误地重置 last。

题面 n,m≤100000，点权和新值不超过 10000，边长为 1。使用 long long 保存解码参数、权值及答案；完整驱动在 `verify/luogu/P6329.compact.cpp`。本模板接受的负权、负半径和极大半径是额外接口范围，分别由核心测试核验，不混成题面支持。

## 验证

核心测试使用 BFS 全点距离和直接扫描点权作为独立 oracle，覆盖 324 个小规模拓扑案例、每例三次重建、负权及极大半径；最大 n=100000 的链、星、平衡树和随机树各做 100000 次更新。完整打包驱动另做 140 份由独立编码器产生的 XOR 输入与四份 n=m=100000 输入。

普通及 ASan/UBSan 分开运行；当前环境关闭不兼容的 LeakSanitizer，不宣称泄漏检测通过。运行资源和源文件指纹记录在 `verification/centroid-sum.json`。没有在线提交或 AC 记录，也没有动态图 link/cut 支持。
