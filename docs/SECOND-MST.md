# 次小生成树与换边方案

`SecondMST` 补齐 kuangbin 2018 正文 135–136 页的 4.3 节，来源 PDF SHA256 为 `f1c90eae0c3fb309d58a14b050fe12b239efb474b033299a547b55646c2768ad`。原节用稠密 Prim、全点对路径最大边权，并说明枚举非树边换入。这里以 Kruskal、递归 DFS 和倍增替代稠密矩阵，保持非严格次小功能，另补严格次小、重边及方案编号。不据此关闭来源中的其他 MST 扩展。

按 [OI Wiki 的最小生成树分类](https://oi-wiki.org/graph/mst/)收录。普通 dsu 沿用队内要求：0-based、路径减半、y 根挂到 x 根，不引入按秩/大小合并。

## 接口

`SecondMST(n)` 要求 n≥1，顶点为 0..n-1。`add(u,v,w)` 返回边的原始 0-based 编号，支持自环、重边和完整 signed 64 位权。边号区分同端点同权的不同边。调用者不得外改 e 或工作数组。

`solve(strict=true)` 返回：

- connected：能否生成树；断图返回空结果，weight=0、tree 为空、next 无值、in/out=-1。这里的 weight=0 不是断图的 MST 权值。
- weight / tree：128 位 MST 总权及边号列表；同权按输入编号确定选边。
- next：可选的 128 位次小总权。默认严格大于 weight；strict=false 时只要求边集不同，可与 MST 同权。
- in / out：从 tree 删除 out，再加入 in，得到对应 next 的一棵树。无候选时均为 -1。

可继续加边后重新 solve，也可反复切换 strict；每次重新建树与倍增表。n=1 的空树权为 0，自环不能构造另一棵树；单棵树图没有次小。内部 merge/dfs/path 与工作数组不是额外公开查询接口。

总权及换边增量先提升到 int128，不能先用 long long 计算 `w-in_tree_weight`。例如 LLONG_MAX-LLONG_MIN 超出 long long。缺失的最大值用边号 -1 表示，不能用 LLONG_MIN 作为不存在的哨兵。

## 严格次小的关键

任意非树非自环边 e 加入当前 MST 后产生唯一环。按 MST 最优性，e 的权不小于树路径最大边权。非严格模式删除路径最大边即得最便宜的一次换边，即使差值为零也合法。

严格模式若 e 的权大于路径最大值，仍删最大值；若相等，则必须删路径上严格小于它的最大值。因此倍增表保存的是**两个不同的最大权值**，不是两个最大边。若路径上全等于 e，则这条边没有严格增大的最优换入候选，应跳过。例：树路径权 0、1，额外边权 1；删除权 1 只得到另一棵 MST，删除权 0 才得到严格次小。

为什么枚举一次换边足够：生成树之间存在交换配对，可将另一棵树的非树边与当前树可删除的边一一配对，每对都是合法的单边交换。由于当前树最优，每个配对的权差非负。若另一棵树更重，则存在正差值，最小正差值不超过总差；沿对应环选择最大且严格更小的可删边只会进一步减小正增量。故全局最小正换边增量恰为严格次小差值。同权的其他 MST 则能提供零差换边。

时间 O((n+m)log(n+m))，空间 O(m+n log n)。不将无按秩合并的 dsu 写成反 Ackermann 界。DFS 保留递归，最深 n；测试进程配栈，不改变模板。

## 完整应用与本地验证

example-144 对应 [P4180 BJWC2010](https://www.luogu.com.cn/problem/P4180)：n≤100000、m≤300000、权 0..10⁹；当前题面明确允许自环，保证严格次小存在。读入点号减一，调用默认 strict 模式。该题总权≤(n-1)·10⁹，可以安全将结果转为 long long 打印；核心的完整 signed 64 位合同则不能随意这样转换。P4180 是比赛应用，不据此计入非比赛正式模板覆盖。

`tests/second_mst.cpp`：枚举 n≤4 的所有简单图（每对点为无边、-1、0、1），再加 2200 份含自环、重边及 LLONG_MIN/MAX 的随机图与定向反例，共 6368 份。独立枚举所有 n-1 边子集，通过图遍历判连通，建立完整生成树权值/边集列表；同时检查 MST、两种次小、无解状态及实际换边后的连通性和权值。每个图重复 true/false/true 调用以检验重建。

100000 点递归长链、300000 边、重复同权边、负极值星形，以及新加便宜边/极大边后重算均通过。核心测试普通与 ASan/UBSan 用 256MiB pthread 栈；完整 P4180 测试在 macOS 用 512MiB 主线程栈。

`tests/mst_switch_applications.py` 另用 260 份完整输入的生成树子集参考，及最大 n/m 的链、星形/自环/64 位总权输入检查 P4180 驱动。打印用法原样展开双模式执行。证据见 `verification/mst-switch.json`；没有线上 AC 或排名，也未运行 GitHub CI。
