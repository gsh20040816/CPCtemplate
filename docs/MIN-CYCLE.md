# 非负权无向图最小环

Issue #15；`MinCycle`，用法374 P6175，用法375输出完整方案。

## 约定

求至少三个不同顶点的简单环。输入允许重边和自环，但自环、两条平行边组成的二元环不在目标中。每对不同端点只保留最轻原边，同权留最早输入的那条；被忽略的原边仍有稳定的返回编号。边权必须非负，可为0或LLONG_MAX；有负边的无向图不适用本模板。

构造n≥0，点号0..n-1。add返回原边号；solve可重复、可在加边后重算，返回独立的optional结果。无解nullopt，零权环是有效解；不能用0或-1混淆无解。结果weight为int128，vertices不重复首点，edges[i]连接相邻两个环点，最后一条连接末点与首点。并列任意解，不承诺字典序。

## 正确性与复杂度

按最大编号点k给每个合法环分类。去掉k及其两条邻边后，得到邻点i、j之间、内部点均小于k的路径。在Floyd第k轮开始时，d[i][j]恰好是这类路径的最小长度。检查i<j<k并加上两条真实邻边即可覆盖所有类别；非负权下最短路径可选为简单路径，不含k，拼接得到至少三点的合法环。必须先检查候选，再执行第k轮松弛，不能颠倒。

只在严格更短时修改next，因此零权等长路径不会替换为经过自身的路径。方案沿next的真实边逐步恢复；这不是显式栈模拟DFS，也不需要DFS。在每轮枚举候选时只存本轮最优端点，结束后至多恢复一次，所有恢复至多O(n²)，避免在每次改进候选时恢复而引入额外n因子。

solve为O(n³+n²)，构造O(n²)，add摊还O(1)。总空间O(n²+m)：保留全部原边以便输出编号，矩阵仅存每对端点的最轻边。非负signed64权、int范围点数下，简单路径及两个有限距离相加均小于2^95；内部2^120哨兵充分大。计算先在int128中进行，绝不先做long long加法。

## 题目与证据

[P6175原题](https://www.luogu.com.cn/problem/P6175)直接求上述目标，n≤100、m≤5000、1≤边权≤100000。合法环最多100条边，答案≤10000000，因此驱动可转long long；无解输出带句号的 `No solution.`。算法模型参考[OI Wiki最小环](https://oi-wiki.org/graph/min-cycle/)。

`python3 tests/min_cycle.py`，加`--sanitize`运行ASan/UBSan。核心穷举5点图每条无向边“不存在/0/7”三种状态，共59049图；另有3000组含重边自环、断连、零权、LLONG_MAX的随机图，检查重复求解、复制后加边、原对象不变。独立真值用递归枚举所有简单环，完全不依赖Floyd递推。

每个返回方案逐项检查顶点互异、环长≥3、原边端点、原边权和；不能只比较最优权。另测200点LLONG_MAX权环、100点稠密极大权图和加入零权大环。两份驱动各验证头文件、NDEBUG、完整展开、最小依赖抄写；P6175另有150组暴力、n100/m5000满规模环和稠密图，API检验完整128位输出及方案。三个错误变体破坏至少三点约束、重边取最轻和128位权值，均要求检出。

本地验证、实际AC、速度排名分开登记，线上只提交问题要求的非空正权输入；空图、零权、大权和原边方案不因权值输出AC就自动视为线上覆盖。

实际 [AC 302333056](https://www.luogu.com.cn/record/302333056)：C++20 O2，100分、12 AC，总计68ms、最慢8ms、峰值1.04MB。当前最小抄写版与上传字节一致，SHA-256为`e989a3db9b671dc95f0635219f155b8d8154d72a310d1dff669c5354dcb81549`。未核验速度排名。
