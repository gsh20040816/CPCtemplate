# WIDA 05 固定位数 BigInt 核验

原稿是 hh2048/XCPC 树 `cfdb12db6792eb2303798541fb5c760ed2bc618b` 的 blob `fd39b7103c67a148e15a9d09cd508d8bf2efc5c6`，精确字节和 GPL-3.0 许可保存在 tests/fixtures/wida_bigint。它仅包含固定1000槽的十进制数组、int构造、乘/除int、加法和输出，不是当前 BigInteger 全部功能的原型。

## 映射与定义域

| 原稿 | 当前 BigInteger |
| --- | --- |
| BigInt(int x) | BigInteger(long long x)，另支持十进制字符串 |
| a *= x | a = a * BigInteger(x) |
| a /= x | a = a.divmod(x).first |
| a += b | a = a + b |
| ostream << a | ostream << a.str() |

原稿安全比较域限非负规范十进制系数，结果须保持1000槽内，机器int中间量不溢出，输出值为正，且加法两操作数不为同一对象。此处是本批实际验证的限制，不代表已找出所有可能定义域。大测试数由测试外围填入公开a数组；原稿没有字符串解析器，不能把该辅助填值器算作原稿功能。

当前版使用vector的10^9进制，支持有符号数与规范零，小整数除法向零截断并返回带被除数符号的余数。符号、不同进制、动态容量不是逐字段兼容，不能复制原稿a数组到当前d数组。当前版也不提供大整数除大整数，不能从“高精度”名称推定该能力。

## 独立反例

1. 零的输出：原稿从最高位往下跳零，不检查下标，最终访问a[-1]。消毒器复现。
2. 最高位加法进位：1000个9加1访问a[1000]。消毒器复现；当前版产生1001位结果。
3. 乘法中间量：BigInt(9) *= INT_MAX 在a[i]*x处发生signed int overflow。
4. 除法中间量：10^10除以INT_MAX，余数向低位传递时乘10发生signed int overflow，即使最终商只有一位也不安全。
5. 同对象自加：a=9后a+=a得到28，而不是18。原因是低位进位先修改了下一位，自加时又把这个进位翻倍。普通优化和消毒器构建都复现；这是逻辑错误，不需要未定义行为。

当前BigInteger对这五类对应输入另有Python整数真值验证。不能将原稿在窄范围正确解读为上述边界也正确。

## 本地证据

运行 python3 tests/wida_bigint.py。普通优化（关闭assert）和ASan/UBSan各通过1068组正数规范范围内的加、乘、除计算，真值来自Python整数；同时检查原稿全部十进制槽仍为0至9，再实际使用原输出运算符。

自加错误和当前版边界分别运行；零输出、容量越界、乘法与除法溢出在独立消毒器子进程中作为预期失败保存，不计入通过的1068组。结果、原始诊断和文件SHA-256见verification/wida-bigint.json。
