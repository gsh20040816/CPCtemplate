# 树状数组第 k 小：P3369 使用代码

对应 issue #1/#12，保留 issue #2 明确要求保留的 `Fenwick::kth`。不新增算法核心，不恢复已排除的 P3374 基础单点加/区间和题。

## 题目与分类

- 官方题面：[P3369【模板】普通平衡树](https://www.luogu.com.cn/problem/P3369)，核对日期 2026-10-02
- 分类：正式模板题 `kind=template`。题面要求维护可重集合的六种操作，并不要求实现特定平衡树；预读操作、离散化后用 Fenwick 维护频数可完整求解
- 约束：操作数 `1≤n≤100000`，参数绝对值不超过 `10000000`。第 k 小、严格前驱和严格后继的答案保证存在；排名和邻居查询的参数不一定已在集合中
- 完整驱动：[P3369.fenwick-selection.compact.cpp](../verify/luogu/P3369.fenwick-selection.compact.cpp)
- 所需模板只有 `Fenwick`。使用代码是该驱动的整个 `main`，不重复抄写算法定义

## 使用约定

1. 预读全部操作，收集除第 k 小查询外的所有参数并排序去重。这里的查询没有强制在线解码要求；不能直接移植到依赖前次答案解码值域的题目
2. 压缩数组 `a` 为 0-based；Fenwick 频数下标为 `1..a.size()`。下标 `p` 的原值存于 `a[p]`，对应频数位置 `p+1`
3. `lower_bound` 的结果 `p` 正好是小于参数的不同坐标个数；`sum(p)` 是这些坐标的总频数。排名为 `sum(p)+1`，重复值不改变这一公式
4. 第 k 小使用 `a[f.kth(k)-1]`。严格前驱使用 `k=sum(lower_bound位置)`；严格后继使用 `k=sum(upper_bound位置)+1`。用 `upper_bound` 跳过全部相等值，不能把后继写成 `rank(x)+1`
5. 删除只减去一个副本；先检查该位置频数为正，避免负频数破坏 `kth` 的单调性。不存在值的删除被保守地忽略；这是驱动的防护行为，不额外声称题面保证或要求该行为
6. 核心 `kth` 要求 `k>0` 且所有位置频数非负；超过总频数返回 `n+1`，不是可解引用的元素下标。本驱动只在题目保证答案存在时将返回值映射为原值；非法 kth 或不存在的前驱/后继不在驱动输入约定内

频数和不超过操作数，`Fenwick<int>` 足够；原值也在 `int` 范围内。初始化为零，每次运行重新构造；存储操作和坐标共 `O(n)`，排序与全部操作共 `O(n log n)`。不支持读完后再引入未登记坐标，也不使用取模后的频数做 kth。

## 独立验证

运行：

```sh
python3 tests/fenwick-selection.py
```

这个独立测试不改共享登记表、生成器或共享使用用例证书，只生成 `build/fenwick-selection-*` 文件：

- `tests/fenwick-selection.cpp` 以普通频数数组和其前缀数组作为独立参考；完整枚举长度 `0..9`、频数 `0..2`，并验证合法递减后的状态
- 随机高频更新仍保持非负，单坐标频数可达 `10^12`；核对每段频数的第一个、最后一个排名，空树、全零、超总数哨兵和 `LLONG_MAX` 查询
- 核对 `2^k` 及相邻长度，最大长度 `100000`，含删空、零频间隔和最后坐标。`k=0` 属于断言前提外，不当作支持的输入
- 使用与 `tools/usage_examples.py` 相同的依赖展开函数，编译完整打印程序；逐字比较输出，不只编译驱动或单独测试核心
- 六份规范用例和 200 份固定种子随机程序，以 Python 有序列表独立求解。随机程序的删除对象和第 k 小/邻居查询均有效
- 四份 `100000` 操作输入覆盖最大离散化域、极端原值、大量不同数、删出零频间隔和重复值；额外一份不存在值删除输入单独标为防护扩展
