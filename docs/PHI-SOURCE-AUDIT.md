§2.7的四段代码均已完整核对，分别为5、12、12、27行，共56行，位于印刷32–33页（物理34–35页）。固定源PDF的SHA256为`f1c90eae0c3fb309d58a14b050fe12b239efb474b033299a547b55646c2768ad`；提取只删除行号并将PDF中的Unicode减号还原为ASCII减号。完整提取结果保留在忽略的build目录，测试脚本可重新生成，没有向模板库添加另一份重复核心。

## 四段代码与现有接口

| 原稿 | 对应组件 | 审计范围 |
|---|---|---|
| §2.7.1 由分解结果累乘 | `euler_phi(n, solver)` | 原稿依赖`getFactors`，自身只有五行；需要不同质因子列表。当前复用`PollardRho`的升序含重数结果并跳过相邻重复项。 |
| §2.7.2 埃氏筛欧拉函数 | `LinearSieve(n).phi` | 原稿固定计算到3000000；当前按需分配vector，使用线性筛，功能替代而非同一实现。 |
| §2.7.3 单值试除 | `euler_phi(n)` | 原稿`i`是int，`i*i`先在int内计算；当前使用unsigned64与`p <= n/p`。 |
| §2.7.4 欧拉线性筛 | `LinearSieve(n)` | 原稿静态容量10000000，同时输出素数表；当前prime/phi对应，并额外提供lp/mu。 |

输入均应为正整数；phi(1)=1。当前筛支持n=0并返回占位零项，但原稿对n=0写phi[1]不表示存在有效的第1项表。原稿线性筛重新调用时重置check和tot，重算1..N；较大旧上界之外的值可能残留，不能作为本次结果读取。当前重建对象避免了此问题。

原稿线性筛容量内的`i*prime[j]`不应与单值试除的平方溢出混淆：到第一个超过N的候选就退出，且在处理i的最小质因子时停止，容量10000000下乘积远低于INT_MAX。不能只看到乘法就断言该范围有溢出；若扩大容量，仍应改用除法比较。当前组件已用`p > n/i`在相乘前终止。

## 原稿边界与反例

- §2.7.3输入2147483647时，独立试除确认它是素数，正确答案2147483646。原稿会计算`46341*46341`，UBSan实际报告有符号int溢出；参数声明为long long并不能扩大这次乘法的类型。当前试除与PollardRho两入口都得到正确答案。
- §2.7.1把n赋给int ret。测试用long long调用者传入2³²，当前编译器观察到ret及结果均为0，正确值应为2³¹。这是超出int累加器定义范围的调用及窄化结果，报告不将其写成UBSan检测到的有符号溢出。原稿在正确分解、1≤n≤INT_MAX时先除后乘，中间值不超过n。
- 五行片段的`getFactors`没有定义在本节。审计适配器以独立试除供应正确质因子，再原样执行这五行，**没有冒充测试了上游分解实现**。原§2.2的表末尾缺陷已在[合数分解来源审计](FACTOR-SOURCE-AUDIT.md)单独记录。

## 独立证据

每种构建均完成下列检查：

1. 原线性筛10000000项与当前表逐项一致，素数表也完全一致；另对当前表逐项检查`sum(phi(d), d|n)=n`。此恒等式配合phi(1)=1递归唯一确定每项，不是两份相似筛法互相证明。
2. 原埃氏筛3000000项全部与已被恒等式验证的当前表一致；人为污染一项后重新初始化，再验证恢复。线性筛按1、37、1000、19、100000次序重复调用，核对每次有效区间和素数表。
3. 1..20000逐一比较原单值、原五行分解累乘、当前试除、当前PollardRho四入口；1..500另用直接gcd计数验证。
4. 2147483647的当前正确值、2³²的窄化反例与当前正确值、2⁶³的当前正确值另行检查。原单值溢出由独立UBSan诊断程序运行，不把故意触发缺陷的程序混进成功对照。

头文件、NDEBUG、实际抄写依赖五组件三种形式，分别在O2和ASan/UBSan下通过；NDEBUG不关闭测试的显式require检查。消毒器未包含LeakSanitizer。抄写上下文显式包含`<cassert>`。
