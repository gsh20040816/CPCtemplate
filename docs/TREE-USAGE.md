issue #12 新增 example-137/138/139，全部直接来自当前完整驱动，不重复打印模板定义。三个核心本批保持不变，DFS均递归；没有新增在线AC或排名。

## 点分治 P3806

[官方模板题](https://www.luogu.com.cn/problem/P3806)要求判断树上是否有距离k的两个不同顶点，n≤10000、m≤100、k≤10⁷、正边权≤10000。`CentroidPairs` 在加入所有边后调用一次 `build()`，每个查询用 `count_exact(k)!=0`。

核心的计数范围比该题更广：无序、不同、连通顶点对；支持非负边权、森林和负查询。负k计0；零距离不会把单个点与自身配对，但零权路径连接的两个不同点会计入。`all[c]`含当前重心距离0；减去每份`part[c]`内部配对，消除两端落在同一子块的重复/错误归属，再递归处理子块。

预处理O(n log²n)、每次查询O(n log n)，该题100次询问可以复用各距离排序。改边后重新build；这不是动态点分树。一般契约要求所有简单路径长可用long long表示，比较采用减法避免距离相加溢出。

独立Floyd的128位距离检查500份森林、零权、LLONG_MAX边界、重复build；10万点链和零权星形另有闭式计数。完整题目驱动另有220份路径枚举参考、1万点/100查询最大输入和单点。

## 树上启发式合并 CF600E

[官方题面](https://codeforces.com/problemset/problem/600/E)以1为根，n≤100000、颜色1..n，求每个子树最高频颜色编号之和。不是众数频率，也不是任选一个众数。传入n+1长度的颜色数组，`run(colors)`后输出`answer[1..n]`，`max_freq`保留对应频率；答案必须用long long，例如所有颜色不同的10万点整树和为5000050000。

轻儿子计算后清空，重儿子统计保留，再逐个加入轻儿子的DFS序区间。清空时撤销整个临时子树，最后统一重置`best/sum`；不能逐个删除后仍沿用只支持增加的最高频更新规则。核心离散化保留原编号，所以还支持负颜色、INT_MIN和稀疏编号，但这些是扩展核心测试，不是该题输入。

1000份独立祖先链直方图检查两次换根/换色，核对answer、max_freq和最终清空。完整CF驱动另测260份独立参考、10万同色/异色长链和星形，覆盖64位并列颜色和。本题是比赛应用，正式非比赛模板题仍待补。

## 虚树 P2495

[P2495](https://www.luogu.com.cn/problem/P2495)虽然当前标题标有模板，原题来自SDOI2011，仍将本用法登记为比赛应用，不以此关闭正式非比赛模板题要求。n≤250000、查询数及关键点总数≤500000、边权1..100000。资源点不含根1。

`prepare()`只做一次。每次标记关键点后显式把1加入keys；`build`不会自动加入原树根。`result.vertices`和虚边端点都沿用原树编号，不能把它们当成0..k-1。虚边`minimum`是压缩路径最小边权，`distance`是路径总长，此题必须用前者。

只将本次vertices的dp清零。虚边按后代DFS序输出，逆序处理保证孩子已累加完：孩子是资源点时必切入边路径，贡献minimum；否则贡献min(minimum,dp[child])。父亲为资源点时，后续向其父亲传播只取入边路径代价，因此祖先/后代关键点同时出现也正确。答案在dp[1]，用long long；星形所有叶子均关键时可达24999900000。最后只清除本次keys的标记，避免每次O(n)清空。

独立核心参考对300份树换根两次，逐查询枚举两两LCA闭包，再沿原树父链恢复虚边、距离及最小边权；包含空/重复/单点关键集。完整驱动160份小树、2240个查询枚举所有删边子集；25万点长链、50万次查询、星形最大答案检验递归与清空。
