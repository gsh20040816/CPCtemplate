# 时间线段树分治与离线动态连通性

对应[issue14](https://github.com/gsh20040816/CPCtemplate/issues/14)第一项。核心 `TimeConnectivity` 复用既有 `RollbackDSU`，不修改普通并查集和既有回滚实现。

## 接口与时间语义

`TimeConnectivity(n,q)` 的点号为0..n；1-based图不使用0，0-based图可以传最大点号。n>=0且n<INT_MAX，0<=q<=INT_MAX/4；这只是整数索引界，还需满足内存限制。

`add(l,r,u,v)`登记边在离散时间 `[l,r)` 有效，允许空区间、相同边的重复/重叠区间和自环。先登记全部区间，再 `run(visit)`；按时间0..q-1调用 `visit(t,const RollbackDSU &d)`。回调内可读 `find` 和 `siz[find(u)]`。不能保留临时并查集引用，也不能在遍历期间修改图。run每次重建并查集，可重复调用；两次调用间可继续添加区间。q=0无回调。

时间t表示第t条操作发生后的状态；若每条操作只有增、删、查三者之一，增删所在时刻没有查询，也与该操作前查询的传统记法兼容。加边a、删除b配成[a,b)，最后仍在的边结束于q，初始边从0开始。若同一时刻既修改又查询，要先约定查询在修改前还是后，再统一编号，不能混用。

## 为什么正确

每个生存区间分解成互不重叠的线段树节点区间。对于叶子t，一条边的有效区间包含t，当且仅当其规范分解中恰有一个节点位于根到t的路径上。因此访问叶子前合并的边正是当前有效边；并查集划分即连通分量。

进入节点保存历史长度，合并该节点的边，递归访问孩子，退出时回滚到保存长度。两个孩子之间不泄漏状态。历史记录只包含成功合并；重边、自环或环上的冗余边不会造成错误撤销。按大小合并且不路径压缩，使find最坏O(log(n+2))，每条成功合并撤销O(1)。所有DFS都是递归。

K个非空区间产生O(K log(q+1))条节点记录。建区间时间同阶；一次run时间O(n+q+K log(q+1) log(n+2))再加回调开销；空间O(n+q+K log(q+1))。不存在把q上限当作一定能在赛题内存中运行的承诺。

## 完整用法

用法352是[洛谷P2147洞穴勘测](https://www.luogu.com.cn/problem/P2147)的离线解法。已核对正式题面：n<=10000、q<=200000，初始空图，合法Connect/Destroy，始终为森林；输出Yes/No。浏览器显示时间1秒、内存125MB，两份官方样例均用header/NDEBUG/expanded/copied程序运行通过。它是SDOI2008竞赛应用，不是任意多重图正式模板题，旧LCT的历史AC不转移给此实现。

用法353为API演示：EOF多组n,m,q，初始m条边，操作为+/-/?。n>=1、m+q<=INT_MAX；点号1..n。允许自环、重边，删除一份存在的边。map按无序端点记录 `{份数,起始时间}`，0到1时开启、1到0时关闭。只关心连通性，计数为正的整个区间可合并成一次登记，不需要给每份边独立ID。若删除操作按边ID给出且边还有属性，就应按ID分别配对。

查询输出连通性与第一个点的分量大小。注意只有增删规范化端点，查询保留原端点次序；交换查询端点不改变连通性，但可能改变分量大小。初始边和未删边按相同规则封口。删除不存在的边不在用法合同内，不能靠关闭assert获得有意义结果。

## 验证

`tests/time_connectivity.cpp`生成4000组区间图，含n=0、q=0、空区间、端点、重复和重叠区间、自环、环，逐时刻以邻接图BFS验证所有点对连通与分量大小。每图重复run两遍，再添加区间重新run，检查状态恢复与回调顺序；need检查在NDEBUG下仍有效。

`tests/time_connectivity.py`对区间核心运行header/NDEBUG/最小抄写三种形式；完整用法运行header/NDEBUG/实际展开/最小抄写四种形式。独立BFS验证322组多重图流和64组合法森林流；另有n=10000、q=200000的森林加删查压力。普通与ASan/UBSan报告分别归档。去掉回滚、提前结束区间、重边余一份就关闭区间三种错误变体均由检查失败或错误输出检出。

开发对拍曾发现查询端点规范化错误，已修正；当前报告对应修正后的源文件哈希。没有将这些测试当作所有输入的形式化证明或全站性能排名。
