# WIDA 12C Montgomery 多项式审计

精确原稿保存为tests/fixtures/wida_montgomery_poly/12C.cpp，blob为2fc05cbaebfde127ea5437a97ff27b4f7c6033fd。新增平方根倒数完整用法450；模板组件仍为331个，完整用法增至450份。

## 函数对应和前提

| 原稿 | 本库对应 |
| --- | --- |
| add、sub | 对规范系数逐项加减，不足补零 |
| mul、dft、idft | NttConvolution::multiply、ntt |
| inv | FpsInverse::inverse |
| quo | 形式级数相除：乘以分母级数逆元并截断 |
| quorem、quo_with_rem、rem | PolynomialDivision::divide 返回商与余数 |
| deriv、integr | FpsFunctions::derivative、integral |
| log、exp | FpsFunctions::log、exp |
| pow | 单位常数项域可直接对应FpsPower；本库还处理非单位首项、前导零和大十进制指数 |
| sqrt | FpsSqrt::sqrt |
| sqrtinv | FpsSqrt::inverse_sqrt，见用法450；直接Newton更新 |

quo是模x^n的形式级数相除，要求分母常数项非零；quorem是普通多项式商，要求除数最高非零项有效。两者不能混用。原稿多项式pow按exp(k log(a))实现，直接使用要求a[0]=1；例如常数多项式2的平方会返回1，本库一般整数幂返回4。这里只记录原稿隐含前提，不将单位常数项以外的调用算作其受支持域。

原稿NTT含固定2^21工作缓冲区和对应根表，泛型P还需适当的素数及二进制单位根条件，不能只看标量类的奇数上界。本批仅在998244353和小规模检查，不把模板参数形式当作任意奇数都可用的证明。

## 重复调用反例

新进程中，连续两次对[1,2]求模x²平方根，原稿第一次返回[1,1]，第二次返回[1,2]；第二个结果平方不等于输入。连续两次sqrtinv则第一次[1,998244352]，第二次[1,499122176]。

原因可定位到静态数组c的复用：循环只覆盖前半部分，随后对c[i-1]执行减法，却未清除上一调用的相应元素。静态零初始化让首次调用掩盖这个问题。普通和ASan/UBSan均复现；这是状态残留造成的算术错误，不是越界或消毒器报错。本库局部vector版本与直接平方根倒数重复调用稳定。

## 独立检查

对长度1、2、3、7、8、9、16、31、32、33、63、64、65、100、127、128，各生成5组输入。乘法用O(n²)卷积，逆元、指数用逐项递推；对数用朴素导数乘逆元后积分，幂用最多5次朴素截断乘法；开方以首项为1的已知根构造平方，商余式以已知商和低次余式构造。

两种构建中，本库各通过1202项独立结果检查。原稿加减乘、级数逆/除、导数/积分、log/exp、单位常数项pow、普通商余式在这批小规模样本中对照一致；原稿sqrt的80次混合长度重复调用有74次不一致，sqrtinv有70次。没有把原稿错误结果当作本库真值。

用法450额外用Python独立构造与求逆递推检查210组，长度覆盖到513，含重复调用、负系数输入、无平方根、零根和有平方根但不可逆的前导零情况。头文件与准确纸面程序均在普通NDEBUG和消毒器模式执行。复杂度仍为O(n log n)，空间O(n)；初次审计使用两次既有算法组合；后续改为直接Newton高半段更新，不引入原稿的全局工作数组，见[FPS优化记录](FPS-NEWTON.md)。

初次审计未覆盖最大长度、其他NTT素数和原Nowcoder引用应用；本轮追加范围见下节，仍非全量12C验收。07D标量部分也有独立审计范围。12C标partial，不新增线上AC，也不改变已有FPS的历史AC范围。证据见verification/wida-montgomery-poly.json和verification/fps-inverse-sqrt-protocols.json。

## 本地性能差距

另以a_i=i+1构造a=(1-x)^(-2) mod x^n，平方根倒数应逐项等于1-x。每轮启动新进程，避免把原稿已知的重复调用缺陷混入首次调用计时。GCC16/C++20/O2交替三轮中位：n=32768，原稿0.002511秒、组合0.137142秒（54.62倍）；n=131072，原稿0.011227秒、组合0.626438秒（55.80倍）。每项系数均验证正确，计时包含输入vector构造与首次缓存初始化。

这是特定本地工作负载而非线上成绩/SOTA；差距超过80%，必须报告。当前组合强调复用和正确的重复调用，但不能声称性能接近原稿优化实现。后续应检查通用模整数重复取模、NTT与平方根/逆元组合的冗余卷积。原始计时见verification/fps-inverse-sqrt-performance.json。

后续通用ModInt去除重复规范化后，重新构建旧版做五轮对照，结果与剩余差距见[固定模整数回归](MODINT-NORMALIZATION.md)。上述原始计时仍保留为改动前证据。

## 追加容量与模数检查

对998244353、167772161、469762049，原稿的卷积输出长度2^21采用全一输入逐项核对三角系数；inverse(1-x)在2^21项逐项为1；新进程中每个模数首次sqrtinv对a_i=i+1逐项为1-x。另对跨二次幂边界的短卷积，用朴素乘法分别核对原稿与本库参数化NTT。普通NDEBUG与ASan/UBSan每种均完成18878337项检查，见verification/wida-poly-capacity.json。

还复现根表的隐含限制：模97、两个长度9的全一多项式相乘，原稿给出[9,8,8,8,8,8,8,8,2,2,2,2,2,2,2,2,0]，正确结果是[1,2,3,4,5,6,7,8,9,8,7,6,5,4,3,2,1]，15项错误。本库NttConvolution<97,5>全部正确。原稿在初始化时直接使用(P-1)>>21，所检查的三个大素数均满足2^21整除P-1，而97不满足；仅有“奇素数且小于2^30”不足以保证原稿这套根表正确。

这些结果不覆盖其他运算的最大规模或所有NTT素数，更不修复原稿重复sqrt/sqrtinv缺陷。原引用应用仍未读取并核验，12C继续partial。
