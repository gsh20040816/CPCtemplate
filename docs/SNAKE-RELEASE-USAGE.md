# 开放时间 BFS 的 Snake Move 应用

## 来源与边界

这是 [2023 杭州 G 的比赛应用](https://codeforces.com/gym/104976/attachments/download/24253/hangzhou(en).pdf)，不是独立模板题。重新核对题面物理第11–12页：每步可移动蛇头或缩去尾部；长度1不能缩尾，移动可同步进入原尾格。n、m至多3000，蛇长至多min(nm,100000)，目标是最少操作数的平方和模2^64，不可达格贡献0。[官方题解](https://icpcarchive.github.io/Asia%20East%20Continent%20Contests/Hangzhou/2023%20Asia%20Hangzhou%20Regional%20Contest/solution.pdf)物理第9–11页给出开放时间与队列优化思路。

## 为什么能用等待最短路

驱动把初始蛇身按头到尾编号为0..k−1。头的起始时间为0；身体第i格（i>0）设 `open=k-i`，其余自由格为0，障碍不连边。这里的open表示最早能完成进入该格的操作时刻，尾格为1。长度2可一步头尾互换；长度3的直链从头进入颈部要两步，不能把下标约定混用。

每条移动边耗时1，下一格的到达时刻为 `max(d[u]+1,open[v])`。初始身体每经过一次命令都会释放一个尾部原位置；移动同时留下的新身体只占据已走过的路径。对一个不重复顶点的候选头部路径，等待可以替换为缩尾；若确实还需要等，时刻仍小于k−1，此时不可能已经缩成长度1。所有初始身体释放后也不再需要等待。因此这不是给普通“不能等待且不能缩尾”的贪吃蛇直接套最短路。

两个关键检查例：两格蛇的答案为1；三格直链的各点时间是0、2、3，平方和为13。它们分别约束同步进尾格及开放时间的差一问题。新测试用真实身体序列作为状态，逐条执行移动/缩尾，而不是另写一份相同的开放时间递推充当证明。

## 模板本身的使用前提

`release_bfs` 的普通队列按距离递增；被开放时间延迟的点放入固定时刻桶。每次从两者取较早时刻。由于 `max(t+1,open[v])` 随t不减，第一次从最早已处理前驱发现v就已定距，不必重复松弛。这个性质依赖单位边和固定开放时间，不适用于一般带权边或周期开放。

本题用隐式四邻网格，不建立数千万条边。R=max(open)小于100000，时间O(nm+R)，空间O(nm+R)；通用接口仍按自身R约束和内存前提使用。`1ULL*d*d` 在乘法前转为无符号64位，累加回绕恰是题目取模；不能改成signed long long溢出。
