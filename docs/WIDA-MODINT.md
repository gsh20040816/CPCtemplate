# WIDA 07C ModIntBase

原稿是 hh2048/XCPC 树 `cfdb12db6792eb2303798541fb5c760ed2bc618b` 的 blob `feb38dce787b7469cc183b02927933cd72ca5a70`，路径 `03 - jiangly模板收集/03 - 数论、几何与多项式/07C - 取模运算类（ModIntBase）.cpp`。文件使用 `u32` 和 `u64`，但没有定义它们，单独编译失败。注释里的动态模数只有一行 TODO。

补上 `uint32_t` / `uint64_t` 别名后，`ModInt<998244353>` 的加减乘除、`power(2, 10)`、负数构造和比较与整数取模一致。`-1` 和 `-5` 分别得到 `P - 1`、`P - 5`。`inv` 用费马小定理，没有检查 0。`inv(0)` 返回 0，不是中止。

32 位 `mulMod` 用 64 位整数乘积取模。64 位 `mulMod` 用 `long double` 估计商。对

`a = 7454363357621997443`，`b = 342088715882458571`，`P = 11257775608867173391`，

原稿给出 `4840048882768193505`，`__int128` 给出 `1319689441135291815`。因此 64 位乘法不能当成精确取模。

`python3 tests/wida_modint.py` 在普通 `-O2` 和 ASan/UBSan 下通过 32 位素数模例子，并核对了上述 64 位反例。提交页面没有打开，没有新的在线 AC，也没有新增模板。来源保持 partial。
