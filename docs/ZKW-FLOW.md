# zkw最小费用最大流

`ZkwFlow`以零约化费用边递归增广，在不能增广时按可达割调整势。它不是每次运行SPFA求增广路，也不是势能Dijkstra改名。只保留vector与递归DFS，采用简单独立struct；为了让访问标记的语义清楚，每次DFS从头扫描邻接边，不复用原稿cur优化。

## 接口与范围

点号1..n，s≠t，`add(u,v,cap,cost)`返回偶数原边编号，`used(id)`读取该原边流量，反边为id^1。允许重边、反向原边、自环及零容量。`flow(s,t,limit)`返回本次新增的流量与int128费用，默认limit=LLONG_MAX；重复调用保持同源汇，返回值不累计之前的流或费用。负费用合法，但调用前残量图全局不得有负费用环。`init/dfs/relabel`是内部方法；重建对象清空网络，e/g供读取方案与结构，不任意修改残量。

每次flow首先从全点零势出发运行Bellman-Ford，建立可行势并检查整个残量图，包括与源汇不连通的部分。发现负环抛invalid_argument，尚未更改任何边流量；limit=0也执行检查。它不是能求解任意负环模型的算法。已有最小费用流加边后若产生负环，也不能直接续流，需使用适合该模型的负环费用流实现。

容量非负，cost≠LLONG_MIN，以便反边取负；要求总最大流≤LLONG_MAX，所有原边Σ(cap×|cost|)<2^120。距离势、约化费用和费用和均用int128。只有具体题面保证答案范围时，才能把费用转成long long输出。

## 为什么调势正确

势h满足每条正残量边u→v的约化费用`cost+h[u]-h[v]≥0`。初始全图Bellman-Ford建立这个不变量，不能把含负边的图直接用全零势开始。

DFS只沿零约化费用边走；vis防止零费用环导致递归循环，递归深度≤V。每次只返回一条成功增广路，回溯时成对更新残量。路径原费用之和为h[t]−h[s]，不假定h[t]=0；打开的反向残量约化费用也为零，因此保持势可行。零约化费用路径是当前最短残量路，增广保持该流量下费用最小。

失败的DFS完整标记源点沿零约化费用边能到达的集合S，汇点不在其中。若没有正残量边离开S，则已经达到最大流。否则取所有离开S边约化费用的最小值d，并令S内h减d。离开S的约化费用减d，进入S的加d，内部不变；全部仍非负，且至少一条新的离开S边变为零。调势后重跑DFS。单次成功增广之前，失败调势会严格扩大零边可达集合，至多V次。成功之后重新清vis；不能复用上次的访问标记遗漏新开的反向边。

若实际成功增广A次，包括全局Bellman-Ford、每次DFS和调势扫描，保守总界为O((A+1)V(V+E))，空间O(V+E)。当E≥V时可写作O((A+1)VE)；不能把A替换成V，整数容量下A还可能随流量增长。当前版本不宣称快于势能Dijkstra或SPFA。

## kuangbin原稿差异

固定2018原稿正文170–172页（物理172–174页）已逐页核对。完整81行（含原编号55空行）保存为`tests/fixtures/zkw_sources/kuangbin.inc`；去掉行号/页眉/缩进，拼回排版折行，规范减号与波浪号。PDF SHA256为`f1c90eae0c3fb309d58a14b050fe12b239efb474b033299a547b55646c2768ad`。

| 原稿 | 当前 |
|---|---|
| 0..N−1编号、全局edge与solve | 1..n编号、对象内vector，多对象不共享边表 |
| 返回pair(最小费用,最大流) | 返回pair(新增流量,新增费用)，顺序相反 |
| dis为到汇方向标签，初始全零 | h为全图可行势，原距离标签对应h[t]−h[u] |
| aug(ss,INF)，无公开限流 | flow(s,t,limit)，容量long long |
| 原有flow字段保留，再调用仅清min_cost/max_flow/dis | 当前也保留边流，重建势后继续返回增量 |

原稿零标签只对非负原边费用保证初始可行。四点反例：1→2、2→4容量1费用0，1→3容量1费用−1，3→2容量1费用0。原稿先选零费用路径，最终返回(费用0,流量1)，而独立枚举的最优费用为−1；图本身没有负环。当前实现输出(流量1,费用−1)。不能以“原稿有时能调出负标签”就声称任意无负环负边都受支持。正常来源对照仅选原费用全非负的小图，且保持int安全范围。

原INF同时限制最小跨割调整量：单边容量1、费用恰为INF时，原稿认为无法继续调标，返回(0,0)，当前返回(1,INF)。另以容量50000、费用50000重现原int费用乘法溢出，单独由UBSan登记为预期失败。来源MAXN=100支持0-based至多100点，MAXM=20000包含反边，因此至多10000条原边；这两个数组计数是静态边界说明，本批未声称实跑全部上限。正常对照实际n≤6、每边容量≤2、费用很小。

## 测试与手册

独立枚举每条边的所有整数流量，按容量、守恒和流量分组求最小费用，不把其他费用流实现当作唯一参照。三点729种非负0/1费用图，加2400组以非负约化费用和顶点势构造的随机图，另加撤销与来源负边反例，共3131图，其中2412图符合来源非负费用前提。

每图同时检查一次求尽、逐单位限流、全部中间费用、续流耗尽、每条流量及反边关系和守恒。专门验证第一次经过2→3负费用边，第二次用反边撤销它；零费用环、平行边、自环、全图/不可达负环的拒绝（limit=0也拒绝且流不变）、LLONG_MAX流量、超64位正负费用均覆盖。十万点零费用递归链与500种路径费用用于长递归和反复调标。

普通及ASan/UBSan各头文件/最小抄写、assert/NDEBUG四种核心形态，每种155675项检查；检查不依赖assert。used符号错误、漏反向残量、把汇点势误当0三个错误变体均被拒绝。

正式入口为[Luogu P3381](https://www.luogu.com.cn/problem/P3381)，2026-10-08重读官方题面：n≤5000、m≤50000、容量/费用0..1000、无自环，流量和最小费用≤2^31−1。驱动`verify/luogu/P3381.zkw.compact.cpp`对应手册用法322，仅在该题答案界内转换费用输出。驱动/展开/最小抄写/NDEBUG每种182输入，独立Python整数流枚举与5000点/50000边闭式案例检查。额外API范围与正式题面范围分开记录。

本批只有本地证据，未新增在线AC或速度榜。报告见`verification/zkw-normal.json`、`verification/zkw-sanitizer.json`；完整库目标继续。
