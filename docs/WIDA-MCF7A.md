# WIDA 07A 旧版费用流

原稿是 hh2048/XCPC 树 `cfdb12db6792eb2303798541fb5c760ed2bc618b` 的 blob `478da7e5f988c4959a9af238ec9d0e975515d6a3`，路径 `03 - jiangly模板收集/02 - 图与网络/07A - 费用流（MCFGraph 旧版）.cpp`。片段使用 `i64`，但没有定义它。

`addEdge` 的正负费用分支被注释掉，实际只保留负费用那一支：`u -> v` 的容量是 0、费用是 `f`，`v -> u` 的容量是 `c`、费用是 `-f`。因此 `addEdge(0, 1, 5, 3)` 后，从 0 到 1 的流量是 0；从 1 到 0 送出 5，费用是 -15。现有 `MinCostFlow` 按调用者写下的方向建边，同样的 5 和 3 得到流量 5、费用 15。不能把这份原稿当成那个接口。

Dijkstra 成功后执行 `h[i] += dis[i]`。到不了的点距离是 `int64` 最大值，第一次只是把势能设成这个最大值，还不会溢出；下一次仍能增广时，UBSan 报 `9223372036854775807 + 9223372036854775807` 溢出。不可达点的势能不是定义好的算法状态。

`python3 tests/wida_mcf7a.py` 在普通 `-O2` 和 ASan/UBSan 下核对了两点图，并用 UBSan 核对了不可达点。Codeforces 提交页面没有打开，没有新的在线 AC。来源保持 partial。
