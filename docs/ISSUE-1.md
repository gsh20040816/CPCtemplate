# Issue #1 执行顺序

依据：[调整方向](https://github.com/gsh20040816/CPCtemplate/issues/1)，2026-09-12 读取。

1. 先逐项核对非比赛模板题：[待审映射清单](template-problems.json)。清单覆盖当前目录中的算法，并保留未完成的上游条目。已有驱动和 QOJ 模板标签仅作为候选，不能把比赛应用、单个子接口或题名相似当作完成映射。
2. 每个已确认题目记录题面、提交入口、输入范围、实际测试接口及 AC 源码快照。优先 STL 封装；不新增 carray 版，除非存在性能证据且经人工确认。
3. 对有最快提交榜的 OJ，记录真实 `rank out of total`、读取时间、排行榜网址、排序指标、并列规则及统计对象。区分所有提交和每人最佳提交，不以排行榜第一页条数充当总数。没有可核验的总数时保留待核验，不能编造排名。
4. 审查组件组合：下标、区间、模数类型、容量、溢出条件、依赖头文件、状态重置，以及能否在同一翻译单元中使用。组合测试与单模块 AC 分开记录。
5. 补充 extc++：PBDS 有序树、gp_hash_table、rope。先核对操作与复杂度边界，再确定模板题；不能用 std::set 的通过记录代替 PBDS 验证。
6. 新增或修订模板优先使用首字母或首 2–3 个字母的简短变量名，按 issue #2 允许适度合并短语句，保持清晰控制流、轻封装和递归 DFS。仅维护 vector / struct / array 版本。

当前带修莫队为开始执行 issue 前已在进行的模板项，P1903 为明确的模板题；完成其收尾后，优先推进第 1 项，不继续自行扩展比赛专用算法。

`tools/template_inventory.py` 仅生成候选清单，不设置已核验状态。待逐项人工审读题面后，再添加独立的审核记录与排行榜证据；重新生成候选不会覆盖这些证据。

首条独立核验记录见 [template-problem-reviews.json](template-problem-reviews.json)，目前 P1903 已有最终源码 AC，排行榜核验仍待完成。
