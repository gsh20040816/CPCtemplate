# WIDA 打印稿：字符串

原稿是 hh2048/XCPC 树 `cfdb12db6792eb2303798541fb5c760ed2bc618b` 的 blob `0f160f11d0a3d00c5ec6c3e058824ae71b35e2bb`，路径 `02 - 打印稿模板汇总/10 - 串.md`。

KMP 是带 `[&]` 的 lambda，不能放在全局。放进函数后，`"abc"` 里的 `"c"` 出现在位置 3，`"z"` 没有出现。`"aaa"` 里的 `"aa"` 得到 2 个位置。Z 函数对 `"aaaa"` 与朴素扩展一致。

小数据 LCS 写了 `cin >> a + 1`，这份标准库不能把输入读进 `char*`，原程序编译失败。把递推改成直接填入 `"abc"` 和 `"ac"` 后，长度是 2。大数据解要补 `maxn`。排列 `1 2 3` 对 `3 2 1` 的长度是 1。

双哈希依赖不在这段里的 `Zmod`。用一个本地的取模类型后，`"abc"` 的前两个字符哈希等于 `'a' * base + 'b'`。因为表头是 1 不是 0，整段 `substring(0, 2)` 不等于 `get()`。把首字符改成 `'d'` 后，结果和按同样规则重建的 `"dbc"` 一致。`compress({"ab","bc"})` 得到 `abc`。

字典树在补上 `N` 和 `LL` 后，`"ab"` 和 `"abc"` 使 `query("ab")` 为 2。01 字典树对 1、2、3 查询 0 和 1 的最大异或都是 3。后缀数组对 `banana` 的 `sa` 是 `5 3 1 0 4 2`，`lcp` 是 `1 3 0 0 2`。

AC 自动机的数组大约一亿个 `int`，放在栈上会崩溃。放到堆上并清零后，`"ab"` 和 `"bc"` 在 `"abc"` 里第一次查询是 2，查询会把计数改成 -1，第二次是 0。回文自动机同样放到堆上，`"aba"` 的回文出现次数总和是 4，新建结点是 3。后缀自动机从结点 0 扩展 `"ab"`，结束时 `cntNodes` 是 2，返回的结点也是 2。第一字符被预先填好的转移吸掉了。

两份子序列自动机同名。模板版能判断 `1,2,1,3` 含有 `1,1,3`，不含 `1,2,2`。朴素版的 `contains` 只接受非常量左值，具名数组上的结果一致。
