## 原稿实际依赖调用者

`tot`、`trie` 和 `f` 都是零初始化。`add` 从节点 1 出发，但文件自己不会先创建节点 1。`f[0]` 也保持 0，不是 `inf`。

不先调用 `newNode` 时，`add(0, 3)` 的第一次分配得到节点 1，随后把这个编号写回 `trie[1][0]`。0 的 30 个位都走这条自环，结果是 `trie[1][0] == 1`、`f[1] == 3`、`tot == 1`。这不是一棵可用的 30 位字典树。

先调用一次 `newNode` 后，节点 1 才是空根，`f[1] == inf`。此后 `add(x, i)` 按 29 到 0 位插入，并在路径上保存最小下标。`query(a, b)` 跟随 `a xor b` 的位。`b` 的当前位为 1 时读取 `a` 的对应孩子，为 0 时读取相反孩子；最后再把终点的 `f` 并入两个候选。任一候选仍是 `inf` 就返回 -1，否则返回 `max(1, ans1, ans2)`。缺失孩子编号是 0，因此会读到 `f[0] == 0`。返回值里的 `max(1, ...)` 可能把这个 0 抬成 1，调用者看不出缺失边。

测试里把 `f[0]` 改成 `inf` 会改变结果。这只是对照，不是原稿的一部分，也不能当成已提供的哨兵。

现有 `PersistentXorTrie` 保存历史版本并查询区间最大异或，不保存插入下标，也没有 `query(a, b)` 的两个候选。不能用它关闭本条目。

## 本地证据

`python3 tests/wida_binary_trie.py` 在普通 `-O2` 和 ASan/UBSan `-O1` 下各做 437 项检查：

- 原始全局状态下 `add(0, 3)` 得到上述自环。
- 先建根、保留 `f[0] == 0` 时，32 组插入和查询与独立过程一致。
- 同一输入在测试中把 `f[0]` 改为 `inf` 后，至少一组结果不同，并与对应的独立过程一致。
