# 静态 ModInt 的单位元求逆

本批扩展原静态类型，不另加模整数类，不增加算法或用法计数。旧inv明确只支持素数模数，这不是修复其原契约内的算错，而是补issue #3保留的静态合数求逆缺项。

## 契约

- 编译期int模数1..INT_MAX；static_assert拒绝非正模数
- 构造仍接受完整signed64，v保持最小非负余数；调用者不能手动破坏正规化
- try_inv返回optional：gcd(v,mod)=1时有值，否则nullopt
- 模1只有余数0，按现有通用/动态求逆接口约定，try_inv与inv返回0
- inv、/、/=要求分母可逆；断言开启时诊断违反前提。NDEBUG时不可逆inv是前提违例，不保证返回特殊值或安全拒绝；需要处理非单位元时先用try_inv
- 加减乘、pow非负signed64指数、组合赋值的返回引用和别名语义不变

例如ModInt<8>(3).inv()为3，而ModInt<8>(2).try_inv()为空。求逆不改变对象。Binomial、NTT、高斯、FPS等上层算法的素数、长度或可逆条件不随这个基础类型扩展自动放宽。

## 短欧几里得的界

初始a=v,b=m,x=1,y=0，保持a≡xv (mod m)、b≡yv (mod m)。每轮作a−qb与x−qy后交换两组变量，q=floor(a/b)。结束时a=gcd(v,m)，只有a=1时把x正规化为逆元。

还有两个界不变量：x、y异号或其中一个为零，且a|y|+b|x|=m。b>0时，qb≤a≤m，且

|x−qy|=|x|+q|y|≤m/b≤m。

所以余数乘积、系数乘积和更新结果的绝对值不超过m。模数只到INT_MAX，用long long有充分余量，不需要完整signed64逆元的int128辅助模板。模1及v=0时也符合该过程。时间O(log(m+1))，额外空间O(1)。

打印片段只增加标准库optional/nullopt与swap，无新的算法依赖。该小段与动态mint有少量相似逻辑，这是为了保持静态模板可独立抄写；两者仍分别验证。

## 验证设计与历史证据

- tests/static_modint.cpp：实例化模数1..150，对每个余数逐个候选乘法枚举逆元，验证单位元存在性、唯一性、除法、算术、组合赋值返回引用与自别名；幂用逐项乘法参考
- 四个大模数各3000个固定种子余数，包括2的幂、2147483646、2147483647与998244353；以独立gcd存在性及无溢出unsigned64乘法证书验证，两个素数另用独立幂参考；另查0/1/2/半模数/末两余数及连续Fibonacci数的长欧几里得过程
- 完整signed64构造端点、零、模1、3 mod 8和不可逆情形
- tests/static_modint.py：完整头文件、真正按手册listing截取的最小类（仅标准头、pedantic-errors）、以及最小类NDEBUG三种上下文均运行。NDEBUG只测试有定义的inv调用；非单位元通过try_inv处理。断言开启的两种上下文另在子进程验证非法inv被拒绝，软core限制为0但不改变硬限制或父进程限制
- 非正模数编译拒绝与模1成功对照；同一固定200000个非零素数余数，比较原pow/Fermat路径与新inv路径，每上下文三次，仅记录本机时间与校验和，不推断所有模数的速度或OJ时限
