# 前缀可持久化 01 Trie

`PersistentXorTrie` 保存追加序列的每个前缀；`max_xor(l,r,x)` 从半开区间 `[l,r)` 中选择**一个出现位置**的原值，与 `x` 异或后取无符号最大值。空区间返回 `nullopt`。它不是线性基的任意子集异或：例如键 `{1,2}`、查询 `0`，本接口只能返回 `2`，线性基却可组合为 `3`。不包含字符串 Trie、删除、任意分支版本、区间排名或选中位置恢复。

## 不变式与贪心

`root[k]` 恰好表示前 `k` 个键。`root[0]` 和零号节点为空；所有节点只记录两个儿子及前缀中的出现次数。每次追加复制根与每一位经过的节点，合计 `bits+1` 个节点；其余子树共享。旧节点不改写，重复键仍增加各层计数。

查询在 `root[r]` 与 `root[l]` 的对应节点同步下降。某个分支的计数差等于该区间内该分支的出现次数，因此差为零就不可选，否则可以选。由高位到低位优先选与 `x` 当前位相反的分支：更高位的 1 总比所有低位的改进更重要。每一步均保留至少一个候选，所以最终路径给出区间中的一个键 `y`。

存储键须落在 `bits` 位内，但查询 `x` 可以是完整 `uint64_t`。高于 `bits` 的部分对所有候选都相同，不影响路径选择。重建 `y` 后返回 `x ^ y`，保留查询的高位。位宽检查先判断 `bits<64`，不执行移位 64；逐位移位的下标仅为 0..63。

## 容量、分配与复制

构造参数满足 `1<=bits<=64`，`0<=cap<=(INT_MAX-1)/(bits+1)`；域错误抛 `invalid_argument`，索引容量超限抛 `length_error`。预留 `1+cap*(bits+1)` 个节点和 `cap+1` 个根。`append` 对位宽不合法或达到硬容量返回 `false`，不改变逻辑状态；分配失败传播标准异常。

普通已预留实例追加和查询为 O(bits)，已用节点数为 `1+size()*(bits+1)`，预留空间为 O(cap*bits)。复制的 vector 不保证保留原容量，故每次追加先恢复完整预留，再修改逻辑内容。复制后首次追加可能搬移 O(size()*bits) 个元素，分配期间还有旧新内存同时存在的峰值。两个 reserve 均先于节点写入；即使第二个分配失败，第一个 vector 的容量可能改变，但键、节点内容和根列表不变。节点复制按值进行，不持有跨 push_back 的 vector 引用。

所有成员均为内部实现，不可外部修改或缩小容量；查询合法下标是调用者前置条件，assert 只作调试诊断。复制后的两个对象可独立追加；不承诺移出对象仍可复用。多测重新构造实例。

## P4735 下标转化

设 `S[0]=0`，`S[i]=a[1] xor ... xor a[i]`。题目后缀为 `S[N] xor S[p-1]`，故询问候选是 `S[l-1]..S[r-1]`。先插入 `S[0]`，再按顺序插入所有前缀，调用 `max_xor(l-1,r,S[N]^x)`；半开右端是 `r`，不是 `r+1`。当前最后前缀只用于改变查询参数；即使 `r=N`，候选也不包含 `S[N]`。

题面给 N、M 均不超过 300000、序列元素不超过 10^7。前缀异或可能大于 10^7，例如 `8388608 xor 8388607=16777215`，但始终小于 2^24，所以存储使用 24 位。公开题面没有单列查询 x 上界；驱动以 uint64_t 读取，支持该类型全部非负值，不把未说明的界擅自当作 24 位。

最多 `N+M+1=600001` 个已插键，25 个节点/键，共 15000026 个节点和 600002 个根。在 12 字节节点、4 字节 int 的实现上数组负载为 182400320 字节，约 173.95 MiB；这是容量公式，不是进程峰值或评测内存证明。默认使用 64 层会显著增加空间，本应用无需如此。测试不替代在线 AC 或 1.5 秒时限验证。
