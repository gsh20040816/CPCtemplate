# 动态 K-D Tree：计数、求和与取出记录

本轮把三种不同语义分开：KDTreeSum已有点权累加和闭矩形和，用权1适配动态二维偏序计数；新增KDRange处理保留编号的记录插入、矩形取出并删除。静态近邻仍使用KDNearest。没有把同名K-D Tree直接视为同一模板。

## 求和核心与来源适配

WIDA固定commit cfdb12db6792eb2303798541fb5c760ed2bc618b，《08 - 数据结构.md》KD Tree段：插入二维点，查询每个坐标都不超过给定上界的点数。用法269每次add(x,y,1)，再query(INT_MIN,INT_MIN,x,y)，闭边界直接比较，不对极小值减1。重复坐标在KDTreeSum中合并权值，但计数等价于原源码把每条插入保存成单独节点。原结构size是重复记录数，当前a[root].size是不同坐标数，不能混用；计数读取query结果。原按方差选轴，当前交替选轴，不声称节点布局或性能常数相同。

issue11附件4.7《K-D Tree》（印刷页126–129）按坐标合并权值、查询闭矩形和，并以last异或解码参数。其Query(x1,x2,y1,y2)的参数顺序与当前query(x1,y1,x2,y2)不同，不能原样抄调用。现有P4148用法114完成协议适配。原实现使用有限inf初始化空子树包围盒、用up.x=-1标记无需重建；当前实现跳过空子树并直接返回重建根，因此也支持负坐标和完整整数边界。原源码int累加只在相应约束内成立；本核心用long long，并约定所有绝对权值总和及更新中间量可表示。

[Luogu P4148原题](https://www.luogu.com.cn/problem/P4148)要求正更新、棋盘坐标1..N、N≤500000、操作数≤200000，所有参数（操作号除外）异或上一答案；题面给20MB内存限制、答案在int内。本轮核对并测试完整输入，但未取得新在线AC或判题机资源数据。预留20万不同点可避免vector扩容峰值，不等于已证明判题机内存通过。负权和64位坐标只属于核心API验证范围。

KDTreeSum本轮仅把一行add函数和比较器展开为多行，C++ token不变；功能、节点大小与分割策略保持原样。其余原有核心未改动。

## KDRange接口与删除不变量

`KDRange(points={})`批量建立二维记录树。`Item`由`p=array<long long,2>`和`id=int`组成；`add({{x,y},id})`插入一条记录，`extract(low,high)`取出并删除闭矩形内所有记录，返回完整Item。返回顺序不保证；需要编号升序时在调用处排序。坐标及编号均允许重复，每条插入是独立记录；业务需要唯一编号时自行保证。

坐标只比较，支持有符号64位极值。`a[root].alive`可读当前记录数，其他数组、根和回收表不得外部修改。节点分配只使用下标，递归内vector扩容不会保留失效引用。构建和插入以轴坐标、另一坐标、编号比较，完全相等的记录是合法的等价元素。

每个节点保存物理子树大小、存活记录数、包围盒和present标志。删除只修改present与存活数，包围盒仍含已删坐标，因此可能偏大但不会漏点。若子树没有存活点直接跳过；若与查询矩形不相交直接剪枝。所有实际命中的存活记录只输出一次。

插入后维护物理子树3/4平衡；重建时遍历整棵子树，先收集存活记录并回收全部节点下标，再重新建树，避免边遍历边复用造成覆盖。extract完成后若根的存活数少于物理数一半，清理重建根。因此每次公开操作结束时，物理节点数不超过存活数的两倍；树高O(log(n+1))。回收表与可达节点集合互斥，合起来覆盖所有非零槽位。

按nth_element平均线性选择计，批量构建O(n log(n+1))；对不利矩形，查询可访问全部物理节点。含重建的单次公开操作保守上界O(n log²(n+1))，不承诺对数时间。空间随历史最大存活记录数增长，节点回收避免随累计移动次数无限增长；清空后容量仍可保留，赋新空对象可释放。n取操作前后较大的存活数；节点编号必须在int范围内。所有遍历均为递归。

## kuangbin 3.10的搬移模型

原稿印刷页120–123的动态KD树除插入外，还会将矩形内记录按编号取出、标记删除、变换坐标后插回。KDRange覆盖这些结构接口；用法271示范同步搬移：先对整棵树extract，再处理返回的所有点，不在搜索过程中插入新坐标。这样一个点不会因为新位置仍在查询范围内而被同一操作再次选中。

对于原坐标(x,y)，保存(x+y,x-y)，则曼哈顿距离≤E等价于变换坐标落入闭正方形。用法271先用保存的旧x、旧y同时计算两个新坐标，再更新；乘加使用128位，原输入编号维持不变。它是明确约束下的源码模型API演示，不是新增UVALive6045原题驱动。

原稿文字写“距离小于E”，但给出的getvec实际使用闭区间，相当于≤E。原题边界、完整输入约束、时空限制和输出协议仍未核验，本轮不猜测哪个是原意。来源表3.10保持partial：结构和闭边界源码模型已验证，原题适配未完成。

## 独立验证

`tests/kd_range_sources.py`把已有矩形和测试中的assert转换成不受NDEBUG影响的检查：四种核心形式分别覆盖160000次独立map更新/查询、分割与包围盒不变量、64位坐标极值、20万点网格、重复累加、复制和清空。覆盖三种错误变体：覆盖重复权值、漏掉闭边界、关闭重建。计数用法269三种完整形式各81份输入；P4148三种完整形式各62份，包含20万次在线相关操作和接近20万不同点、INT_MAX答案。

`tests/kd_range_probe.cpp`另行检查新KDRange：4万随机操作每步与独立记录多重集比较，检查分割顺序、3/4平衡、包围盒、存活数、可达/空闲槽位划分；含重复坐标和重复编号、64位极值、复制重置、连续5万次移动、10轮全部取出再插入。移动期间槽位数不超过20001（存活数10000），不是进程内存使用测量。

普通与ASan/UBSan分别运行header/copied和assert/NDEBUG四种核心形式。未删除、丢失编号、丢失回收槽位三个错误变体被独立检查拒绝。用法270三种完整形式各80份输入；搬移用法271三种形式各81份输入，以Python直接计算曼哈顿距离和同步变换作参考，包含10万点全部搬移。两类核心合计每模式六个错误变体。新增用法均为API，未新增正式模板题覆盖、在线AC或排名结论。
