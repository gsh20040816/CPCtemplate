# 递归ISAP最大流

`Isap`是独立vector封装，使用反向残量BFS、当前弧、重标号和gap剪枝，增广保持递归。不是把Dinic换一个名称，也不依赖Dinic继承。普通dsu及计算几何合同均不变。

## 赛时接口

点号1..n，源汇不同，容量非负；允许平行边、自环和反向原边。`add(u,v,cap)`返回偶数原边编号，`used(id)`给出原边流量。`e[id]`公开起点、终点、残量cap和初始initial；反边为id^1。`flow(s,t,limit)`返回本次新增流量，默认限额LLONG_MAX。重复调用保持同源汇；可以先限流再续流，也可以加边后续流，已有流必须可行。总最大流须≤LLONG_MAX，不能靠默认限流输出截断结果却声称是完整最大流。

`cut(s)`返回当前残量网络的源点可达点列表。只有已经求尽、汇点不可达时，它才是最小割；限流中途所得集合不冒充最小割。函数使用单独访问数组，不依赖最后一次ISAP的距离标签。`bfs/dfs`是内部方法。重建对象从零重算；若自行改e，需保证成对残量、初始容量与全图守恒，不提供自动修复。

两个方向都有独立容量时调用两次add，分别读取方案。不添加用起来容易混淆的有符号净流接口。一般复杂度O(V²E)，空间O(V+E)，递归深度O(V)。不承诺比Dinic更快。单次限流调用的额外末次增广不改变这个上界。

## 距离、当前弧与gap

初始从汇点反向遍历：检查邻接边的反边残量`e[id^1].cap`，由此得到各点到汇点的真实残量最短距离。不可达点统一为n，gap数组含0..n，避免负下标和n+1越界。

维护每条正残量边u→v都满足dep[u]≤dep[v]+1，沿dep[u]=dep[v]+1的边递归。严格递减距离保证无递归环，即使有原自环。增广打开的反向边也满足标签不等式。当前弧跳过饱和或不满足等式的边；本点标签不变期间，邻点标签只增不减，被跳过边不会重新成为可用边。若重标号，当前弧从头重置。

无法增广时，把dep[u]改为所有正残量后继的最小dep[v]+1，并截断到n。无后继也为n。原标签对应的gap变为0，表示没有顶点取该距离。从源点到汇点的残量路径若存在，其标签从dep[s]到0每条边最多下降1，必经过缺失层，矛盾。因此停止。

实现先更新本点的新标签计数，再处理旧层gap消失。递归子调用若已把源标签设为n，父层立即退出，不能继续重标号覆盖终止信号或再次扣减源标签计数。gap在终止时不要求继续保持可复用的统计；下一次flow重新BFS并构造gap/cur。

本实现每次dfs找到一条增广路便返回，沿途更新残量后再返回源点；不会在已经送出部分流的递归帧里提前gap退出，避免遗漏流量记账。每条增广路除最后一次限流外至少饱和一条边；结合单调标签与当前弧，得到经典O(V²E)上界。

## kuangbin来源对应

固定2018 PDF的正文163–166页（物理165–168页）已视觉核对；SHA256为`f1c90eae0c3fb309d58a14b050fe12b239efb474b033299a547b55646c2768ad`。4.16.3完整73行、4.16.4完整92行保存在`tests/fixtures/isap_sources`，只去掉PDF行号/页眉/排版缩进、拼接折行并规范减号。原稿的pre路径回退和S显式路径栈仅作为测试夹具保留，不进入可抄写模板。本实现按用户要求改为递归控制流程。

4.16.3从全零合法标签开始，4.16.4先BFS但忽略边容量和方向，实际计算底层无向距离；这种距离可作合法下界，不等于残量最短距离。源汇属于不同底层分量时，原4.16.4保留dep[source]=−1，随即访问gap[−1]；空二点图已由独立UBSan进程重现。正常对照中仅在源汇底层连通时调用原BFS版；当前实现所有图都测。

原4.16.4将Min初始化为INF，仅在遇到严格小于INF的残量时赋值inser。所有路径边残量≥INF时可能读取未初始化inser，属于源码静态边界观察；本批不声称由ASan/UBSan检出了未初始化读取。来源对照只使用小容量。原两版使用int流量和固定数组；当前long long和vector不沿用该上限，也不依据MAXN就宣称所有边界均安全。

原addedge(u,v,w,rw)把双向容量放在同一残量对，flow为范围[−rw,w]的有符号净流。当前两次add返回两份非负逐边流；合并成正向流−反向流才对应原净流。测试对w/rw各0..4与两个源汇方向验证这个映射，不能直接要求单条used等于原flow。

两个来源sap均返回本次增量而不清边流量。原init清边表，当前构造重建；所有正常来源案例都连续调用到耗尽。来源只核对最大流值；当前方案另独立检查每条容量、反边关系、守恒及割容量。

## 正式题目与测试

正式入口为[Luogu P3376](https://www.luogu.com.cn/problem/P3376)，2026-10-08重新读取官方题面：有向网络，n≤200、m≤5000、单边容量0≤w<2^31。驱动使用long long，允许输出超过int的总流；不同源汇遵守库合同。`verify/luogu/P3376-isap.compact.cpp`对应手册用法321。没有新增在线AC或速度排名，不复用Dinic的AC记录。

核心测试以独立枚举所有s-t割为参照：三点所有0/1/2容量有向图729组，加3000组随机图；源汇可为任意不同顶点，自环、平行边、零容量、反向原边均覆盖。每组检查零限流、半流量后续流、耗尽、cut，以及加边后再次限流续流。所有检查使用显式need，NDEBUG也执行参照。另测LLONG_MAX、十万点递归长链、十万点分支网络及不可达汇点，不改成显式DFS栈；本地测试配置512MiB栈。

普通/ASan-UBSan各四种核心形态：头文件和最小抄写，分别assert/NDEBUG；每种3729图，其中3200图符合原BFS版安全连通前提，合计1801794项检查。反向BFS方向写错、漏加反向残量、used符号错误三个变体均被拒绝。完整驱动、展开程序、最小抄写与NDEBUG用法各203组输入，包括200点/5000条INT_MAX容量平行边、长链及官方示意样例。

本批新增组件与正式用法；只映射两个邻接表来源，不把SAP矩阵两种形式或最大流父节视为完成。完整来源、数学及赛站覆盖目标继续。

矩阵SAP两种来源的重建/续流、净流矩阵与反向容量范围另见[MATRIX-SAP-SOURCE-AUDIT](MATRIX-SAP-SOURCE-AUDIT.md)；不新增carray实现。
