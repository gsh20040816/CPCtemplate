# Min_25 与精确素数计数

附件 #11 第 65–71 页含积性函数求和与素数计数两份代码。当前分别提供 prime_count 和 Min25：只计素数时不构造三组模数幂和；积性函数求和才建立次数 0/1/2 的素数幂和。

令 w 为所有不同的 floor(n/i)，降序排列。若 x 是其中一个值，则 floor(x/p) 仍是 n 的整除商；small[x] 与 large[n/x] 分别索引不大于平方根的值和较大的商。id 不支持任意不在表内的整数。平方根由浮点初值加整数修正得到；循环用除法限制幂的乘法，避免在边界先溢出。

初始化 g_d(x)=Σ(2≤i≤x)i^d。处理素数 p 时，减去 p^d·(g_d(floor(x/p))−Σ(q<p)q^d)，恰好去掉最小质因子为 p 的合数。必须按 x 降序更新，保证右侧仍为本轮之前的值。对小整数 p，计数通道 g_0(p)−g_0(p−1) 为 1 当且仅当 p 为素数；即使 mod 小于 p，这个差仍只有 0 或 1，因此取模后比较相等不会漏掉素数。所有合数的最小质因子不大于平方根，完成后表中只剩素数贡献。

Min25 的 sum 从 f(p) 的多项式系数组合出纯素数贡献，再枚举合数的最小质因子 p 及其次数 e。剩余部分严格使用更大的素数，保证唯一分解；纯素数幂 p^(e+1) 单独加入，最后加 f(1)=1。回调 power(p,e,pe) 的第三个参数就是整数 p^e；传入系数必须与 e=1 时的回调一致。构造与 sum 解耦，因此同一 n 可多次计算不同函数，筛表不变。

当前实现只预处理次数 0、1、2，不能直接声称覆盖任意次数的素数多项式。模数要求为大于 3 的素数，以保证模整数运算和 2、6 的逆元合法；素数计数函数单独使用精确整数。支持上界 10^12 是接口与整数安全范围，不是全范围时限保证。

[OI Wiki 的复杂度分析](https://oi-wiki.org/math/number-theory/min-25/) 区分直接递归与倒序转移：素数和预处理为 O(n^(3/4)/log n)，直接递归求和不能不加说明地套用倒序转移的相同界。手册对当前递归部分给出保守 O(n) 上界（每条分解路径对应唯一的整数乘积），回调须为 O(1)；实际速度另看当前官方本地数据记录。空间 O(sqrt n)，递归深度 O(log n)。

验证包括独立筛素数、对所有整除商逐一枚举素数幂和、七类积性函数的逐数分解、模 5 等小模数、n=1、平方数边界、重复 sum，以及 n=10^9 的恒等函数前缀和。P5325 完整输入输出由独立最小质因子筛的前缀和核对。固定 Library Checker 的 counting_primes 与 sum_of_multiplicative_function 分别使用全套官方生成数据和 checker。

Library Checker 在 sum_of_multiplicative_function 的固定 info.toml 中将 min_25_sieve.cpp 标为 allow_tle。当前本地 checker 使用较宽超时收集正确性证据，不代表原 10 秒时限下通过，更不代表线上 AC 或速度排名。更快的积性函数求和方法仍是待办，不能用本条覆盖替代。
