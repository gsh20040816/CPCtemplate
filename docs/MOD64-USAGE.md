# 完整无符号 64 位模运算接口用法

这是保留的共享组件 `Mod64` 的接口演示，不是正式 OJ 题目，不恢复已排除的 P1226，也不增加线上 AC 或正式模板题覆盖。

## 自定义输入输出

- 输入 `q`（0..200000），随后 `q` 行 `a b m`
- 合法数据使用无符号十进制整数：`0 ≤ a,b ≤ 2^64−1`，`1 ≤ m ≤ 2^64−1`
- 每行输出 `a*b mod m` 和 `a^b mod m`，均为 `[0,m)` 内的整数
- `m=1` 时两项都是 0；`b=0` 时第二项是 `1 mod m`，因此接口采用此处的 `0^0` 约定
- 读入失败、`q` 超界或 `m=0` 时返回 1；此前完整行可能已经输出。此短驱动不做完整词法或尾随输入校验，负号不属于合法输入

必须用 `unsigned long long` 读入和输出，不能先经过 `long long`；例如 `18446744073709551615` 超过有符号 64 位范围。接口预期该类型是 64 位，编译器支持 `__uint128_t`。代码中在乘法之前提升到无符号 128 位，两个最大 64 位整数的乘积仍可精确表示；不能先计算已溢出的 64 位乘积，再作类型转换。

无需先把 `a,b` 限制为小于模数。模数可以是偶数、合数或最大无符号整数；本用法不使用费马降幂、不要求互质、不计算除法或逆元。`mul` 的非零模数是调用方前提，核心函数不提供非法输入恢复；`power` 的断言也不能替代发布模式的输入检查。

模乘按固定字长算术计为 O(1)，模幂至多处理 64 个指数位；每个查询 O(log(b+1))、辅助空间 O(1)，整个程序流式处理查询。128 位除法的具体速度依赖编译器和平台，本地验证不作为 OJ 排名或常数时间密码学承诺。

最小抄写内容为目录中 `Mod64` 组件及用法234的 `main`。只增加接口调用例，不复制第二套模运算实现。
