# 浮点交点默认容差与判题误差不是同一契约

2026-10-02 核查两个未补用法的候选题时，发现默认浮点接口不能直接覆盖它们的全部合法输入。这里记录的是判题契约不匹配：当前接口本来就允许把相对容差内的近切状态归为 one，并不是它违反了已有近似分类说明。

## 官方域

[AOJ CGL_7_D](https://judge.u-aizu.ac.jp/onlinejudge/description.jsp?id=CGL_7_D&lang=en) 和 [CGL_7_E](https://judge.u-aizu.ac.jp/onlinejudge/description.jsp?id=CGL_7_E) 都给整数坐标（绝对值至多 10000）、整数半径 1..10000，保证有交点。输出要求按 x、y 字典序列出两个点，相切时重复输出同一点，坐标误差小于 10⁻⁶。D 的端点不同，每组 1..1000 条直线；E 的圆心不同。

## 两个合法的非相切反例

1. 直线与圆：圆心 (0,0)、半径 9805；直线经过 P=(9797,396)、Q=(9574,5913)。方向 v=(-223,5517)，D=|v|²=30487018。精确整数式 r²D−cross(v,P)²=1>0，所以有两个交点：P 与 P−2v/D。默认 line_circle_intersections 返回一个弦中点；即使按相切规则重复输出，y 坐标误差约 0.00018096227，超过要求。

2. 两圆：圆 (0,0,10000) 与 (9999,1,1)。D=99980002，K=D+10000²−1=199980001，精确判别式 4·10000²·D−K²=39999>0。半弦长平方为 39999/399920008。默认 circle_intersections 仍返回一个中点；重复后 y 坐标误差约 0.010000875。

距离量上的小阈值不能直接换算成交点坐标上的同样误差，接近相切时开平方会放大影响。只补排序和切点重复输出不能修复这两个映射。

## 可复现诊断

运行 `python3 tools/check_geometry_judge_contracts.py`，输出写入新的 build 子目录。当前版本预期退出码为 1，表示测到了判题不兼容；它不是一个声称通过的算法单元测试，也没有加入常规测试脚本。发布记录为 `verification/geometry-judge-contracts.json`，包含默认浮点实际结果、编译器和源码指纹、long double 尾数位数，以及独立 70 位十进制参考和精确整数判别式。

工具直接调用浮点接口，不拿整数版本替代被测组件。判题坐标参考由独立整数/有理数公式导出；它不依赖本库的整数交点实现。

## 使用边界

- 两个浮点组件继续保留待补用法状态，不宣称通过上述题目
- 不盲目缩小 eps：需要证明官方域的最小非零间隔以及目标平台 long double 的舍入界；long double 在不同平台的表示也不同
- 整数输入可另行选择已有精确整数分类接口，但必须遵守那些接口自己的范围与验证，不能把其通过算给浮点函数
- 本次不改核心算法，不新增线上 AC，也不关闭其他浮点几何缺项

## 2026-10-03 后续：显式零容差分支

上面的默认调用、反例和预期不兼容诊断不变。新增的 `eps=0` 分支改为直接计算平方判别式；并非在旧的投影/平方根公式中简单移除容差。完整浮点用法229/230要求二进制 long double 尾数至少64位、正常最近舍入且无危险优化，其有界整数域证明和验证见 [CIRCLE-ZERO-MODE.md](CIRCLE-ZERO-MODE.md)。不能把这一额外模式解释为默认行为已经改变，也不能扩大到一般实数或53位 long double 平台。
