# 一般图最大权匹配

`WeightedBlossom g(n)`，点号1..n，允许n=0；`add_edge(u,v,w)`添加无向边。自环忽略，重边保留最大权。输入权重允许long long全范围，包括LLONG_MIN。

- `solve()`只最大化总权，允许空匹配；非正权边不参与，不保证同权时匹配边数最多。
- `solve(true)`先最大化匹配边数，再最大化原权。
- 返回`weight`（__int128原权和）、`pairs`和`mate`。mate长度n+1，0号不用，未匹配点为0。
- 最大权完美匹配：`solve(true)`后检查`2*result.pairs==n`；否则不存在完美匹配。单纯调用solve可能舍弃一些可用边，不能用其匹配数判定完美匹配存在性。

每次solve重建内部状态，允许重复、切换模式和加边后重算。公开字段供测试和理解，不作为可修改接口；无需调用内部过程。O(n³)时间、O(n²)空间，矩阵实现适合数百点。n<INT_MAX/2仅是编号约定，实际规模仍受时间和内存限制。花内点展开、修改代表元和增广均递归，没有模拟DFS栈。

## 权值变换与整数范围

基数优先模式令W为最大绝对边权，B=nW+1，把每条存在的边变为w+B。任意两个匹配的原权差至多nW，所以多一条边得到的奖金严格支配原权差；同边数时仍最大化原权。所有真实变换边均为正，不存在的边仍不参与。普通模式丢弃非正边不会降低最大权，但可能改变同权时的匹配数。

计算先转128位再取负，因此LLONG_MIN安全。n<2³⁰、W≤2⁶³，变换权小于2⁹⁴，总原权和小于2⁹²。对偶目标等于二倍变换匹配权，非负顶点标签及正标签奇集的总量受O(n²W)约束，远低于2¹²⁶哨兵。不能先用64位计算nW或绝对值。

## 算法不变量

经典Edmonds原始对偶算法维护紧边交替森林。外点遇未访问花时加入其匹配伴侣；遇另一棵树的外点时增广；同树外点之间的紧边形成奇环，以LCA为根缩成花。矩阵边保留原始端点，from记录端点属于哪个直接子花，不能只记录收缩后的端点。花内匹配沿偶长度段递归翻转。

没有可用紧边时调整顶点和花的对偶标签，使新的边变紧或内花标签变零。零标签内花可以展开并恢复交替森林。若外点标签降到零，则所有标签必须完成本轮更新后终止，不能在顶点循环中提前返回留下部分更新的证书。初始统一顶点标签为最大变换权；权值等于该最大值的边都是紧边，可以贪心形成合法初始匹配，改善等权稠密图耗时。

独立检查器从实际花树恢复每个奇集S，检查标签非负、每条边的端点标签加共同包含该边的花标签至少为二倍变换权，匹配边等号成立；未匹配顶点标签为零，正标签花内部恰有(|S|-1)/2条匹配边。最后检查

`sum(vertex_label) + sum((|S|-1)/2 * blossom_label) == 2 * transformed_matching_weight`。

左边是匹配线性规划的可行对偶上界，右边是合法匹配下界，相等便证明该次结果最优。这是对实际运行结果的证书检查，不替代全部输入的实现审计。

## 验证证据

`tests/weighted_blossom.py`对头文件、NDEBUG和实际抄写版分别在O2与ASan/UBSan下执行28546次检查：四点边权穷举、五点所有简单图、3500个至多12点随机图、LL极值、负权、零权、重边、自环、重复solve及加边后重算。独立子集DP核对最优值，方案与对偶证书独立检查。

附加插桩记录11673次缩花、4998个嵌套子花和404次展开，避免测试只覆盖二分图或无展开路径。400点的8种图分别跑两种模式，16次结果在O2与ASan/UBSan下均通过方案与对偶证书检查；包含稀疏、稠密、等权、零权、全负、LL极值和互不相交奇环块。

[P6699正式题](https://www.luogu.com.cn/problem/P6699)限制n≤400、m≤79800、1≤w≤5×10⁸，1秒、128MB。当前展开源码已通过[记录302632540](https://www.luogu.com.cn/record/302632540)：100分、20点全AC，最慢209ms、最高24.02MB。页面总用时2.80s是多测试点统计，不能与单点1秒限制直接比较。负权、基数优先和完美性判断仅有独立本地证据；运行排名未核验。
