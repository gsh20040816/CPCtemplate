## HDU1814：输出字典序最小代表名单

- 第 `x` 党候选人编号为 `2*x-1` 与 `2*x`，每党恰选一人；冲突的两个人不能同时入选
- 将候选人 `u` 转为变量 `x=(u+1)/2` 和值 `a=(u%2==0)`：奇号是值 0，偶号是值 1
- 冲突 `(u,v)` 表示 `(x!=a) OR (y!=b)`，所以调用 `add(x,!a,y,!b)`；不能直接把这两个候选人当作正子句
- 公共变量号与 `answer` 为 `1..n`，`answer[0]` 只是占位；内部字面量号 `2*(x-1)+value` 是 0-based，不与候选人号混用
- 每组重新构造 `LexTwoSAT(n)`。读取到 EOF 为止，无 `0 0` 结束标记，也不读取测试组数
- `solve()` 失败时只输出 `NIE` 一行，`answer` 为空，不能读取失败方案
- 成功时按 `x=1..n` 输出 `2*x-1+answer[x]`，每人一行，无额外组号或空行。由于每党的两个编号连续，按变量号、0 优先的最小赋值恰对应字典序最小代表名单
- 最坏时间仍为 `O(n(n+m))`，递归传播需要足够调用栈。10000 变量等价链只检验指定传播/回滚结构，不证明一般大输入的性能

## POJ2942：从憎恨关系建立补图

- 输入人与模板顶点都为 `1..n`，无需加减 1。憎恨为无向关系，矩阵两边同时写入
- 只有 `u<v` 且二人不互相憎恨时才 `graph.add(u,v)`。这样每条允许相邻的边只加入一次，自环不加入；重复、逆向憎恨记录被布尔矩阵合并
- 每组重建矩阵与 `BiconnectedCore(n)`，先 `graph.run()`，再调用 `odd_cycle_vertices(graph)`。此例所需上下文为 `BiconnectedCore`、`block_cut_forest`、`odd_cycle_vertices`
- 返回 `odd[1..n]`，1 表示属于某个长度至少为 3 的简单奇环；`odd[0]` 不计入答案。合法圆桌的成员各不相同，对应这样的简单奇环
- 一个非二分点双的点全部可以参加某个奇环，但不应把标记跨割点传到相邻的二分块或桥后。不同标记点不保证能同时出现在同一张圆桌上
- 输出 `odd[u]==0` 的人数，每组恰一行。没有任何合法圆桌时输出 `n`，没有失败标记；不输出成员名单或座次
- `0 0` 终止且不产生答案。源码也能在 EOF 退出；缺少终止标记的输入仅作为驱动健壮性扩展测试
- 对憎恨输入数 `m` 和补图边数 `e`，驱动建图 `O(n²+m)`，分解及奇环标记 `O(n+e)`；矩阵及图空间 `O(n²+e)`。算法继续使用递归 DFS

## 精确打印程序的独立验证

已有 `tests/lex_two_sat_application.py` 与 `tests/odd_cycle_vertices_application.py`
分别枚举代表选择、枚举简单奇环；本批先审阅它们，不重复运行全库。
新增 `tests/graph_printed_usages.py` 使用 `tools/usage_examples.records()` 生成的
**精确注册程序**，不是另写一份同义 `main`，分别执行普通与 ASan/UBSan 模式。

- HDU：1235 组连续输入。包括 1–2 变量全部 1032 个冲突子集（含自冲突扩展）、
  200 组至 9 变量的确定种子随机例、10000 变量回滚链、矛盾组及紧随其后的自由选择组；
  小例按字典序枚举实际代表名单作为独立参考，另测立即 EOF
- POJ：1230 组。包括 `n=1..5` 全部 1099 个简单憎恨图、120 个 6–8 人随机例、
  UVA 官方样例、重复/逆向/自憎恨扩展、三角形接偶环/桥和断开图；小图直接枚举奇数人数的
  圆桌排列检查相邻者，既不调用点双分解，也不使用“非二分块全标记”公式
- 大图采用可直接证明答案的 `n=1000` 完全允许、全部憎恨、完全二分允许、三角形接链四类，
  另有 1000000 条重复憎恨输入和紧随其后的单点重置；立即 EOF、`0 0` 后仍有数据、
  无终止标记的 EOF 都单独检查
- 全部按精确文本比较，含逐人换行、`NIE`、每组仅一行与终止无输出。
  8 个负对照拒绝可行但非最小的代表名单、同一行挤放名单、冲突选择、错误无解、
  错误失败词、把可入座人数当作淘汰人数、额外空行以及终止时误输出
- `tests/usage_examples.py` 同时登记各 3 个集中冒烟输入，供常规打印示例管线执行

运行命令：

```sh
CPC_SANITIZE=0 python3 tests/graph_printed_usages.py
CPC_SANITIZE=1 python3 tests/graph_printed_usages.py
```

本批两条命令均 PASS，实际编译器为 Debian GCC 14.2.0，目标 `x86_64-linux-gnu`；
两项各 3 个集中冒烟输入也已用同一批普通及 sanitizer 二进制核对精确输出。

脚本为 Linux 子进程申请最多 512 MiB 软栈（不改硬上限），支持 macOS 已有的链接栈配置。
ASan/UBSan 使用 `detect_leaks=0`，**不认证 LeakSanitizer**。

源文件 SHA-256、输入输出批次指纹、实际编译器/参数/版本、平台、栈及 sanitizer 配置，
运行前后核对源码与编译器未变化。它是聚焦验证报告，不是全库回归收据。

此脚本不改生成的书册片段、覆盖表或集中验证账本。集成时仍需按
