# WIDA 树状数组、并查集和线段树原稿核验

核验 WIDA 的 jiangly 数据结构目录中 01A、01B、02A、02B、03C、03D 六份精确原稿。来源树为 hh2048/XCPC 的 `cfdb12db6792eb2303798541fb5c760ed2bc618b`，完整路径和 blob ID 保存于 `tests/fixtures/wida_basic_ds/provenance.json`。保留原始字节和 GPL-3.0 许可，不用当前模板替换原稿来做“原稿通过”测试。

## 树状数组：区间和排名都要转换

原稿 01A/01B 的 add(x,v) 使用零基位置，sum(x) 表示 [0,x)，rangeSum(l,r) 表示 [l,r)。当前 Fenwick 使用一基位置和闭区间：

| 原稿操作 | 当前 Fenwick |
| --- | --- |
| add(x,v) | add(x+1,v) |
| sum(x) | sum(x) |
| rangeSum(l,r) | query(l+1,r) |
| kth(k) / select(k) | kth(k+1)-1，仅限非负整数频数与 k>=0 |

原稿的排名查找返回“前缀和不超过 k 的最大前缀长度”；对整数频数，这就是零基的第 k 个元素位置，无结果返回 n。当前 kth 输入从 1 开始，无结果返回 n+1。不能只调整返回下标而忘记输入排名，也不能把 k+1 转换照搬到任意非整数 T。

排名查找要求所有单点频数非负，区间求和允许负数。本批将二者分开测试。原稿两版在 n=0 时调用排名查找会进入 __lg(0)，UBSan 分别复现；只查询空前缀没有这个问题。当前空 Fenwick 的 kth(1) 返回 1。调用者仍应遵守各接口下标和算术范围。

01A 使用 +=、-=、>=，01B 使用 +、-、<=；两者对自定义 T 的要求并不完全相同。当前版也不是任意 T 的逐语法替换。本批验证 long long，不宣称穷尽所有代数类型。

## 普通与回滚并查集

02A 与当前 dsu 都使用 [0,n) 位置、路径压缩；合并返回是否发生变化，size(x) 返回所在集合大小。根的编号和内部父指针不属于本次等价接口，测试只比较独立标签数组表示的划分与大小。原稿 init(n) 重建，当前可重新构造 dsu(n)。

02B 与当前 RollbackDSU 都分配 0 至 n 的槽位，按大小合并且不做路径压缩。time() 对应 snapshot()，revert(t) 对应 rollback(t)。同集合合并返回 false，**不增加历史长度**；时间戳是成功合并次数，不是所有操作次数。只能退回当前历史中的时间戳，退回后继续合并形成新分支，不能恢复已丢弃的未来。

本批用独立标签数组保存每次成功合并后的完整划分。随机选择已有时间戳退回，再继续合并，逐点比较大小并逐对比较连通性；没有用原稿和当前版互相充当唯一真值。

## 03C 搜索与 03D 合并顺序

两份原稿都是零基半开区间，点修改对应当前 segtree::set，区间查询对应 prod。Info()/e() 须为单位元，合并须结合，不能随意选择空区间返回值。03D 的自定义 Merge 在本批以字符串拼接实例化，验证非交换运算的从左到右顺序。

03C 的 findFirst/findLast 通过 pred(区间聚合) 剪枝。若 pred 为 false，必须能排除该区间内所有候选叶子；随意传入谓词可能漏解，也可能丧失复杂度保证。它不等同于任意前缀条件下的 max_right/min_left。

本批检验具体常用实例：Info 为区间最大值、单位元为 INT_MIN，寻找 [l,r) 内第一个/最后一个 >= threshold 的位置（threshold>INT_MIN）。令 ok(info) 表示 info.max<threshold：

```
first = tree.max_right(l, ok);
first = first < r ? first : -1;
last = tree.min_left(r, ok) - 1;
last = last >= l ? last : -1;
```

两个方向都用字面数组扫描作真值，包含空查询、无解、重复值、负数和非二次幂长度。该实例证明这里的转换，不证明全部用户自定义 pred 都可如此转换。原稿初始化调用 __lg(n)，使用时要求 n>0；本批没有对空树初始化作安全承诺。当前 segtree 支持空树查询。
