# WIDA 08C：序列最大值 Treap

本批对应 WIDA 固定树 cfdb12db6792eb2303798541fb5c760ed2bc618b 的 `03 - jiangly模板收集/04 - 数据结构/08C - 其他平衡树.cpp`。原文 blob 为 9a2c66037a45210284725001eb9013f87765706f，完整字节和许可证归属保存在 `tests/fixtures/wida_sequence_max/`。

新增 `SequenceMaxTreap` 与完整用法 435（CF38G Queue），库总数为 321 个组件、435 份完整用法。接口包含按位置插入、按前缀长度分裂、序列拼接、最右严格大于阈值的位置查询、稳定编号输出。所有位置为 0-based，节点编号按插入顺序从 1 递增；拼接没有值域有序要求，但根须属于同一对象且互不相交。分裂和拼接消耗旧根。

各修改与查询期望 O(log N)，随机 Treap 最坏 O(N)，输出 O(N)，空间 O(N)。使用 vector 和递归，保留清晰的逐句代码。值仅用于比较，支持全部 signed64 和重复值；不实现无需求的懒标记和内存回收。

## 原题与独立验证

原题 https://codeforces.com/problemset/problem/38/G 的官方页面已在浏览器核对：n<=100000，重要度是 1..n 的排列，每人的可交换次数在 [0,n]。新来者进入队尾，只能向前越过重要度比他小的人。当前最右严格更大的元素构成屏障，因此插入位置为 `max(i-limit, barrier+1)`。

- 核心测试：每种构建 5,640,666 次森林结构/阈值证书；另有 200000 个相同值的压力数据，覆盖空树、重复值、负值、LLONG_MIN/MAX、分裂与拼接。
- 原稿测试：4865 组，涵盖长度 1..6 的全部排列与多种限额，以及随机排列。直接编译未修改的原稿，补头文件、rng 和新节点 info/sum 初始化。对照逐个相邻交换的独立真值，并调用原稿 splitAt、merge、dfs 检查最终编号。
- 完整输入输出：186 组，包括三个官方样例、180 组随机模拟和三组 n=100000 的可解析边界。
- 以上均通过普通构建和 ASan/UBSan；准确抄录的用法 435 另通过两种构建的样例检查。

证据：`verification/sequence-max-treap.json`、`verification/sequence-max-application.json`、`verification/usage-examples.json`。当前没有线上 AC，不把本地验证替代线上判定。

原稿 query 的含义是尾部 <=阈值的连续长度；其整棵剪枝使用最大值 <阈值。在原题互异排列条件下足够，不能因此宣称原题有错。新组件改用最大值 <=阈值剪枝，以支持重复值域的查询效率。
