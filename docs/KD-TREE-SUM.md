# 动态 K-D Tree 的矩形权值和

核对附件 4.7，实际 126–129 页。图中输入协议及代码对应 [Luogu P4148 简单题](https://www.luogu.com.cn/problem/P4148)，2026-09-29 核验：N<=500000，操作数<=200000，20 MB 内存，每条命令的全部参数都要异或上次答案，答案保证在 int 范围。当前覆盖动态单点累加和闭矩形和；不把最近邻、删除坐标也登记为已实现。

## 接口

`KDTreeSum<Coord=int>(reserve_points=0)` 默认空树。Coord 取 int 或 long long。

- `add(x,y,delta)` 对坐标权值累加 long long，允许负值。相同坐标只占一个节点；权值变成零仍保留坐标，第一次加零也创建节点。
- `query(x1,y1,x2,y2)` 返回闭矩形内的权值和；任一方向左下端大于右上端，返回零。点、线段及空树都可以查询。
- 重新赋值空对象可重置。a、root、节点及辅助函数属于内部状态，调用者不要直接修改。

坐标只比较，不相减，也不使用 +/-inf，因此支持所选整数坐标类型的极值。要求各点绝对权值的总和及所有更新中间量可由 long long 表示，确保任何子树/查询累加顺序均安全；不能只看全局带符号总和。不同点数、预留容量和节点编号小于 INT_MAX，预留容量非负。

## 分割与重建

深度交替使用 x/y 作为主轴，同轴相等时以另一轴打破平局，形成严格全序。插入时先判断坐标完全相同以合并权值，否则沿对应轴的比较方向递归。回溯计算 size、sum 和包围盒；若某个孩子节点数超过父节点数的 3/4，递归收集节点编号，再用 nth_element 按当前深度的轴选择中点，重连这些原节点。

重建不复制点、不分配新的树节点；临时 vector 仅保存编号，不是 DFS 执行栈。左右孩子重建时切换轴，回溯重新计算包围盒。沿插入路径检查所有祖先，最终每个节点都满足 3/4 平衡，树高 O(log(d+1))，d 为已创建的不同坐标数。重复点更新不增加 d。

附件用 up.x=-1 表示“无需重建”，因此推广到坐标 x=-1 会有歧义；本实现直接返回重建后的根编号，无额外坐标标记。附件空节点包围盒用有限 inf，而本实现从本节点坐标初始化，仅合并非空孩子。附件 query 参数次序为 x1,x2,y1,y2，本接口改为通常的 x1,y1,x2,y2，驱动据此明确适配。

## 查询与复杂度

查询只依靠包围盒：完全不交返回零，完全包含返回子树 sum，否则检查当前点并递归两边。权值是否为零或负数不影响剪枝，不能据 sum=0 推断子树没有贡献。

nth_element 以标准库平均线性选择成本计，大小 s 的重建为 O(s log(s+1))。平衡重建后再次失衡需要与子树规模同阶的新点插入，将费用分摊到更新路径得到插入摊还 O(log²(d+1))；单次根重建可 O(d log(d+1))。这依赖选择算法平均成本，不是每次插入的严格最坏对数保证。无需重建的插入/重复点更新为 O(log(d+1))。

矩形查询**最坏 O(d)**，树高对数不表示矩形只访问一条路径；此动态重建版不额外承诺每次 O(sqrt(d))。空间为节点池及至多 O(d) 的临时编号，预留容量另计；递归深度 O(log(d+1))。

## P4148 内存与协议

example-114 使用 `KDTreeSum<> s(200000)`，在读取操作前预留最大不同点数，避免 vector 增长时新旧节点缓冲同时存在。当前 GCC16 环境 sizeof(Node)=56，200001 个默认 int 坐标节点为 11200056 字节，最大重建编号另需约 800000 字节，不含程序、分配器、运行库与栈。用 long long 坐标会增大节点；因此驱动保留原题所需 int 坐标、long long 聚合。

这是分配量核验，不是目标评测机的峰值内存或 AC。默认不预留时节点池仍正确，但峰值可能明显增加；超过预留数量也会再次扩容。题目答案承诺 int，因此 last 用 int，读入的坐标和增量逐项 XOR 后才调用模板。

## 本地证据

- 200 组随机、共 16 万次更新：独立 map 扫描矩形参考，空树、反向边界、重复点、负权及零权。递归审计严格轴分割、3/4 平衡、节点数、权值和、精确包围盒。
- 完整 long long 坐标极值/-1/0 的所有矩形端点组合，单点权值 10^12；坐标无加减，消毒器检查溢出。
- 20 万点有序网格构建，逐行/列和全域闭式答案；确认每个不同点只分配一次，默认节点 56 字节，预留容量恰为 200001。另有 20 万次同一坐标正负更新。
- P4148 完整驱动：150 个随机 XOR 流；两组 20 万操作，一组不断变化 last，另一组接近最大不同点分配后输出 INT_MAX。编码由独立 Python 参考生成，输出逐项比较。

普通及 ASan/UBSan 结果和源码哈希见 verification/kd-tree-sum.json。example-114 打印程序另行编译验证。无新增线上 AC，不计未核实的非比赛模板题或速度排名。
