# 混合欧拉路径：定向与连续走法的接口组合

这是自定义输入协议的 API 演示，不是 OJ 题目、题面复刻或在线 AC 记录。
完整驱动见 [mixed-euler-demo.cpp](usage-drivers/mixed-euler-demo.cpp)，
独立检查见 [mixed_euler_demo.py](../tests/mixed_euler_demo.py)。
它补充 POJ1637 的回路存在性判定：真正输出顶点走法与每一步使用的原边编号。

## 输入与边界

首行 `T`，接着输入 `T` 组。每组首行固定为：

```text
mode n m start finish
```

随后 `m` 行，每行 `u v type`：`type=1` 固定为 `u→v`，
`type=0` 可任选 `u→v` 或 `v→u`。顶点为 **1..n**；
原边依输入顺序编号 **1..m**，自环与平行边都保留，不能去重。

- `C`：默认起点回路；`start=finish=0`，调用 `mixed_euler_orientation(n, edges)`
- `A`：任意起终点的欧拉路径；`start=finish=0`，调用 `mixed_euler_trail(n, edges)`
- `P`：指定起终点；二者均在 `1..n`，调用 `mixed_euler_orientation(n, edges, start, finish)`
  - `start=finish` 表示指定起点的回路，并非忽略起点

演示范围为 `1≤T≤10000`、每组 `1≤n≤200`、`0≤m≤800`；这些只是本演示的
保守边界，不是核心接口的最大规模或任意平台上的性能保证。输入保证格式与范围合法，
没有结束哨兵。每组重新创建方向结果与 `DirectedEuler` 对象，不复用上组状态。

## 输出证书

无解只输出一行 `NO`。有解输出三行：

```text
YES
VERTICES m+1 v0 v1 ... vm
EDGES m e1 e2 ... em
```

这里 `m+1` 和 `m` 输出为实际整数。第 `i` 步使用原边 `ei`，从 `v(i-1)` 走向 `vi`。
每个原边编号恰出现一次；固定边方向不变，可反转边允许任一方向。仅验证顶点相邻关系
不足以区分平行边，必须连同边编号检查。

定向接口返回 `optional<vector<pair<int,int>>>`：

- `nullopt` 才是无解；驱动先检查 optional 是否有值，再解引用
- **有值的空 vector 是合法零边回路**，不可用 `direction->empty()` 判失败
- 零边 `C/A` 输出单顶点 `1` 与 `EDGES 0`
- 零边 `P s s` 输出单顶点 `s`；零边 `P s t` 且 `s≠t` 无解
- 非空图忽略无关孤立点，但指定端点必须在有边部分；多个非孤立连通分量无解

返回的方向按**原输入边顺序**排列，并不是走访顺序。驱动逐项 `trail.add(u,v)`，
随后 `trail.run(start, false)` 才恢复连续走法。指定端点时不能丢掉 `start`；
否则指定起点回路可能被改成另一个起点。`DirectedEuler::add` 返回的编号从 **0** 开始，
本驱动仅在输出时加一，因此输出编号仍对应原始输入行。

定向阶段没有全局字典序最小保证。即使给 `DirectedEuler` 开启排序，也只是在已经选定的
有向图上求字典序路径，不能据此宣称在所有混合图定向方案中全局最小。本演示关闭排序，
只保证任意合法证书。若已返回可行方向却无法生成走法，驱动以非零状态退出；
它不会把内部组合错误伪装成正常的 `NO`。

## 小例子

```text
5
C 3 2 0 0
1 2 1
1 2 0
A 3 1 0 0
2 1 1
P 3 2 2 2
1 2 1
1 2 0
P 3 0 3 3
P 3 0 1 2
```

一份合法输出为：

```text
YES
VERTICES 3 1 2 1
EDGES 2 1 2
YES
VERTICES 2 2 1
EDGES 1 1
YES
VERTICES 3 2 1 2
EDGES 2 2 1
YES
VERTICES 1 3
EDGES 0
NO
```

第一组要求把可反转边改为 `2→1`；第二组说明任意端点接口不能只尝试较小端点到较大端点。
第三组回路必须从指定点 `2` 开始。最后两组区分空方案与无解。
一般情况下答案不唯一，测试应按证书验真，不与某一份合法输出逐字比较。

## 复杂度与递归栈

单次定向最多建立 `n+2` 个点、`m+n` 条正向网络边；采用 Dinic 的一般上界
`O((n+2)^2(m+n))`，空间 `O(n+m)`。任意端点接口统计无向度数，自环计两次；
零个奇度点请求回路，两个奇度点最多尝试两种端点顺序，因此至多两次定向。
最终关闭排序的 `DirectedEuler` 为 `O(n+m)` 时间与空间。

核心实现保持递归：Dinic 增广深度为 `O(n)`，连通性并查集的递归 find 也需栈空间；
欧拉 DFS 深度可达 **m+1**，不能只按顶点数预估。这里的小规模测试使用进程默认栈；
扩大输入前应评估递归栈与最大流开销，不能从本演示推出十万级任意混合图都可行。

## 本地验证及证据范围

运行：

```sh
python3 tests/mixed_euler_demo.py
```

默认分别编译普通与 ASan/UBSan 完整驱动，也可用 `--mode normal` 或 `--mode sanitizer`
仅运行一个模式。检查包括：

- 两顶点、至多四边的全部 495 个边多重集，含固定/可翻转、自环、两种存储方向；每图测默认回路、任意端点及全部指定端点组合
- 固定种子小图逐条枚举所有可反转边方向，以弱连通性与出入度条件独立判存在性；不在 oracle 中重复使用最大流或 Hierholzer
- 两个奇端点的两个顺序、强制翻转、固定边阻塞、指定回路起点、孤立点、分离回路、平行边、自环和空图
- 每份成功证书逐步检查顶点范围、原边编号排列、对应方向与端点，拒绝漏边、重边、反转固定边及假 `NO`
- `n=200`、`m=800` 的有明确构造证书或度数/连通性障碍的有界实例，以及 `T=10000` 的同进程多测重置
- 检查器自身接受不同合法方向，同时拒绝预设损坏证书

ASan/UBSan 模式显式关闭 LeakSanitizer（`detect_leaks=0`）；这不提供内存泄漏检测证据。
两种模式的输入、输出与源码绑定报告仅写到被 Git 忽略的
`build/mixed-euler-demo/{normal,sanitizer}/`，包含源码、展开后程序、输入、输出的 SHA-256，
编译器、编译命令和分组结果。脚本结束前检查依赖源码没有变化。
报告只是这份有界接口演示的本地证据，不更新全库通过状态、不代替完整回归，也不声称线上 AC。

`check_output(data, stdout)` 可安全导入供中央示例检查使用，导入不编译也不执行测试。
它独立判定小实例是否可行并校验任意证书；为避免误用枚举，最多接受 12 条可反转边。
大规模专项测试单独提供由构造或障碍证明的期望可行性，仍逐边核验证书。
