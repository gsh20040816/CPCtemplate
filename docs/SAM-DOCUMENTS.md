# SAM 文档频率及树上字典序应用

本批加入 `SAMDocuments`，将同一个子串出现于多少篇输入文档与出现多少次严格分开。新增用法259为CF204E应用，260为模式串文档频率API，261为TSUBSTR完整应用。复用GeneralSAM、Fenwick与SAMLex，不引入数组版，也不改变已有SAM构造。

## 文档集与接口

`SAMDocuments(sam,s)`要求sam已经按同一文档集完成构造：GeneralSAM须先build；OnlineSAM须按完整文档插入完毕；单文档SuffixAutomaton也可使用。s允许空串和重复串，两个相同输入位置是两篇文档。索引保存sam引用，sam必须存活且保持不变；公开g、cnt只读，不动态追加。拷贝索引仍引用同一个sam。

对非根状态u，`cnt[u]`是其任一代表串出现的文档数，因为同一endpos类中的串共享文档集合。根特别约定`cnt[0]=s.size()`：空串在空文档中也存在。查询非空模式串时从根沿go走，遇缺边立即答0，否则读取最终状态cnt；模式长度不必等于该状态最长代表串长度。

`lengths(k)`要求k>=1，返回best[u]：u的最长代表串中，出现于至少k篇文档的最长后缀长度。不足返回0；k大于文档数全为0。不能直接把best用于长度小于len[u]的任意匹配串而不考虑其实际长度；本批驱动仅在原文档前缀的准确状态使用。

L为文档总长，D为文档数，V为SAM状态数。构造时间O((L+V)log(L+2)+D)，空间O(L+V+D)；每次lengths为O(V)时间和返回数组空间。所有计数、状态数和总长必须可用int索引，数组须可分配。递归深度至多最长文档长度加1；本地深链测试配置512MiB原生栈，不改成显式DFS栈。这个本地栈配置不证明原OJ资源限制通过。

## 去重计数的证明

对每篇文档，沿已构建SAM的根路径走过每个非空前缀，将文档编号挂到对应状态。原输入前缀是该状态最长串；代码对此有assert。同一状态可能挂多个文档，也可能在后缀子树中重复看到同一文档。

在后缀链接树中，u的子树恰好包含所有以u所表示串作为后缀的前缀结束状态。因而u的文档频率等于其子树标记中不同文档编号的数量。递归DFS按进入顺序扫描标记，Fenwick只保留每个编号最近一次出现位置上的1；此前位置减1。进入u时记录l=timer+1，退出时当前timer为该子树末端，区间[l,timer]内的1正好每个出现的文档一个。没有标记的子树l=timer+1，区间和为0。空文档不产生非空标记，由根的专门约定处理。

后缀链接上的文档频率向根不减。满足频率阈值的非空后缀长度因此构成从1开始的连续范围。递归时若当前cnt达标，best设为当前len；否则继承父状态best。对某个原串每个位置，以该位置结尾的合格区间恰有best[p]个，逐位置相加便得到CF204E所求，重复出现区间自然分别计入。长串答案可超过int，使用long long。

## 正式题面与来源核验

[CF204E原题](https://codeforces.com/problemset/problem/204/E)于2026-10-07读取：n、k和总长度上限100000，各文档非空小写；k允许大于n。原题显示3s、256MB，且有旧服务器时间倍增说明。本批没有宣称原OJ时间限制通过。两份官方样例均纳入完整程序验证；它是比赛应用，不登记为非比赛模板题。

TSUBSTR原页面需要JavaScript，但同日通过[CodeChef公开题目API](https://www.codechef.com/api/contests/PRACTICE/problems/TSUBSTR)取得完整题面，另对照[官方题解](https://discuss.codechef.com/t/tsubstr-editorial/861)和其链接的[测试者源码](https://www.codechef.com/download/Solutions/2012/April/Tester/TSUBSTR.c)。输入是一棵以顶点1为根的无向树，字母在顶点上；允许祖先到后代的向下路径，根顶点的字母也计入。不同路径可能产生同串，输出去重数量并包含空串。每个查询给26字母排列和1-based k，空串第1，超出输出-1。

TSUBSTR约束N<=250000、Q<=50000、k<=2^63-1、输出不超过800KB，原题保证顶点字母随机生成。API报告max_timelimit=1，未提供可核对的内存上限。本地测试含额外的全相同字母、克隆密集长链，明确是超出随机字母承诺的压力输入，不用它们替代原随机模型。正式驱动先按树做真正BFS登记Trie，重复同标签边合并；随后调用GeneralSAM的原BFS构造，不把根叶路径展开为长字符串。总构建O(26N)，字典序查询O(26×输出长度)，外加读入Q个字母排列。

用法257继续保留为简化父编号输入的API演示，不与新正式用法261混同。上一批“TSUBSTR完整题面不可用”的表述作为历史记录保留，本批以原站API消除了这一缺口。kuangbin1.6与1.6.2由partial转为local-tested，表示本批两道完整应用与此前构造/查询一起覆盖其列举的功能；不继承原作者AC，不声称线上资源或排名验证。

## 独立验证

文档频率核心每种形式9816组、3075111项检查：所有长度不超过3的二字母串（含空串）组成的单/双/三文档集、600组随机文档集及逆序；GeneralSAM、OnlineSAM和适用的单串SAM分别验证。直接枚举每个子串的文档集合，对所有状态和所有阈值核验cnt、best，并按所有出现区间独立复算CF204E答案。另用cnt作为SAMLex权重，验证按文档次数加权的字典序结果；检查源SAM不变、拷贝、空集合及大k。

最大核心测试包括10万层后缀链、克隆密集串、重复长文档、短文档对长后缀的阈值限制，以及10万相同文档。普通和ASan/UBSan两模式均运行头文件/标准头抄写体各assert及NDEBUG，七个语义破坏分别检验文档合并、误计出现次数、区间边界、子树标记、阈值、继承和空文档处理。

完整CF204E每种程序形式731份输入，频率API182份，TSUBSTR207份；普通与sanitizer均覆盖原驱动、完整展开及最小依赖抄写体。TSUBSTR使用独立祖先路径枚举、随机字母树、不同输入边顺序、所有小树排名、逆字母序、LLONG_MAX、最大点数/查询数及官方样例。逐字符比较完整输出，包括空行；五个驱动语义mutant也必须被输出参考拒绝，不把崩溃当作有效参考证据。

本批仅新增核心和应用，已有核心不修改。局部测试、完整用法、来源功能覆盖、线上AC和排名分别记录。运行及源码摘要见verification/sam-documents-*.json和verification/tsubstr-*.json。
