# 带插入区间第k小：来源审计与未完成范围

kuangbin 3.11/3.11.1不是固定位置的动态区间第k小，也不是上一节的区间等值计数。完整模型要求在线按位置插入、单点改值、区间第k小，参数异或上一次查询答案。现有 `DynamicKth` 需要固定位置和预知未来值，`SequenceScapegoat` 的map没有秩统计，均不能直接覆盖。后续已新增SequenceKth及用法327，见[实现与验证](SEQUENCE-KTH.md)。来源模型现有本地实现证据，仍无官方题面或在线评测证据。

协议按来源：EOF多组，每组n、n个值、m条操作。Q x y k查询1-based闭区间第k小；M x val修改第x项；I x val在第x项之前插入，x=m+1时追加（这里m指当前长度）。所有整数参数都与lastans异或；只有Q更新lastans。来源二分范围固定0..100000，因此本次测试值也限制于这个闭区间，不声称完整signed64接口。来源并不交换查询端点，解码后要求x≤y、k合法。

## 答案核验

`tests/sequence_kth_source.py` 编译完整原稿，以Python列表直接插入/赋值，再排序查询切片作为oracle。穷举三值字母表{0,1,100000}长度1..5共363个初始序列，查询全部区间、全部合法k，穿插重复修改、首尾插入；另120组随机操作，共483组、26043次查询，在同一进程运行以检查EOF多组重置。先按真实操作计算答案，再逐条异或编码，不能用来源自己的答案生成测试输入。

普通和ASan/UBSan均通过这些答案测试。该证据只说明受测输入上的结果，不保证复杂度或完整容量。LeakSanitizer在此环境关闭。

## 不伸展查询的可复现退化

内层 `Splay::query(Node *root,int val)` 从root沿二叉查找路径累加数量，但不调用splay，根指针也按值传递。依次插入1..n时，每个新最大值被伸展到根，形成向左长度n的链。外层初建根的内树恰好按原序列顺序插入，因此递增初值可直接产生这一形态。

连续查询“≤0”的元素数每次访问n个内节点，查询不改变树形，20次恰为20n；不能借Splay的均摊复杂度定理把这种只读查询称为均摊O(log n)。原主程序对值域二分，完整区间第1小的查询也反复遍历这条链。

探针 `tests/sequence_kth_source_probe.cpp` 在完整原稿上只给该while循环插入一个计数器，并改名原main以调用探针。它不调整指针、不添加旋转、不修改比较或返回值。两种编译模式测得一致结果：

| n | 根内树左链长度 | 20次≤0查询访问数 | 20次完整区间第1小访问数 |
|---:|---:|---:|---:|
| 16 | 16 | 320 | 1540 |
| 64 | 64 | 1280 | 7500 |
| 256 | 256 | 5120 | 38820 |
| 1024 | 1024 | 20480 | 194640 |
| 4096 | 4096 | 81920 | 940620 |

这是确定性的访问计数，独立于机器耗时；未据此声称原OJ某次提交超时。答案通过与性能保证必须分开。

## 后续实现与剩余核验

新增实现必须保留在线插入、修改、区间kth的完整范围，不能用固定位置树状数组或扫描std::map替代。内层可采用有严格秩查询保证的平衡树，或正确伸展访问路径的Splay；如采用本库PBDS秩树，应明确GNU依赖、重复值唯一编号、节点编号稳定性和频次树重建成本，并给出完整可抄写依赖。

还需独立测试空树/边界位置（若接口允许）、重复值、值域范围、长插入修改序列、内存回收或增长约定、打印版和完整在线解码。正式题面、独立模板入口、线上AC/排名尚未完成。来源审计本身不作为额外组件；后续SequenceKth采用PBDS红黑秩树并完成本地打印适配，详见实现说明。官方题面、独立模板入口和线上AC/排名仍待核实。
