## 原题和表示差异

已读取 [CF1598G 官方题面](https://codeforces.com/contest/1598/problem/G)。输入字符串和目标整数由非零十进制数字组成，并保证存在相邻两个非空子串，转为整数后之和等于目标。程序应输出两段一基闭区间，任意合法方案均可。

原稿的前缀余数使用底10、数字值0至9和随机素数模数，筛选的是十进制数值加法。当前 StringHash 使用字符码加1以及至少257的底，支持字符串比较和拼接；两者的算术语义不同，不能把两个 StringHash 结果相加就当成十进制两数之和。

原稿再用目标串的Z函数及目标与文本各后缀的LCP缩减候选长度。当前 exkmp 覆盖这一LCP子步骤；完整候选枚举、十进制余数和答案校验应用尚未补齐。

## 合法输入下的越界

```
999124554
99
```

这是有解的题面内输入：位置[6,7]为45，位置[8,9]为54，和为99。

原稿计算文本后缀LCP时，只判断 j!=-1 就读取 z[i-j]，没有判断 i 是否仍在旧匹配窗口内。当窗口结束、边界位置匹配长度为0时，j不一定立即更新，随后i-j可以达到m+1，访问长度m+1的z数组之外。上述输入在ASan下稳定复现heap-buffer-overflow；不修改原稿或随机数发生器。

当前exkmp只有在i<r时才复用窗口内的Z值，窗口外从0比较，因而避开这一访问。独立逐字符真值验证包含这个反例及空串，但没有据此声称完整原应用已实现。

此外，原稿只以模数相等接受答案，没有做最终十进制逐位加法确认。随机余数筛选具有碰撞风险；本批没有提供原稿永不误判的保证，也没有用几组通过样例消除这种风险。
