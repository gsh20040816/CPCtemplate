# HLPP最高标号预流推进

Issue #15；HLPP；用法383为P4722最大流值，用法384展示每条原边流量和最小割源侧集合。

## 接口与数值域

点1..n，2≤n<INT_MAX/2。add(u,v,cap)返回偶数残量边号，反边为id^1；支持自环、重边、反向原边及零容量。原边数<INT_MAX/2，容量非负，全部原容量之和≤LLONG_MAX。只限制最终最大流可能溢出初始化预流，因此要求容量总和界；ex[s]可以为负，其绝对值同样受此界约束。

flow(s,t)要求不同的合法源汇，每次把残量恢复为原容量，从零重算总最大流。允许重复调用、换源汇及加边后重算；与现有Dinic返回新增流量不同，不支持limit参数。used(id)仅接收add返回的原边号，输出该边流量；反向原边是另一个独立残量对。min_cut()返回n+1长的0/1数组，1..n为源侧标记，0不用；只在完整flow之后调用。加边后应先重新求流，再读方案。e/g及其他成员只读；activate/push/relabel仅内部使用。

## 实现不变量

初始从汇点反向BFS，必须查看反向残量e[id^1].cap，不能写成当前边残量。不可达点标为n+1，源点固定n。饱和源点的非自环出边得到预流；中间点ex≥0，源点ex≤0。每个残量对容量和等于原容量，push仅沿高度差1的正残量边，不破坏容量限制。

h是合法高度函数：每条正残量边u→v满足h[u]≤h[v]+1。放流失败时，relabel设为最小残量邻点高度+1；当前弧归零。高度k<n出现空层时，处于其上且<n的非源点都不可能再到汇点，将其提升到n+1；不改变源/汇高度。提升只增不减，保留合法标号。

head[h]与next[u]构成活跃点的单链桶，取最高非空层。点在ex由0变正时入桶，出桶后一直处理到ex=0。gap改动多个点高度后重建所有桶，排除正在放流的u，避免旧高度条目和重复入桶；不需要优先队列或每层独立vector缓存。它是活跃集合，不是显式DFS栈；整个算法不调用DFS。

不可达汇点的顶点也必须继续放流，沿残量边把多余流退回源点。不能将高度≥n的点直接丢掉：那样可能得到正确的ex[t]，但used方案仍违反中间点流守恒。结束时所有中间点ex=0，得到真实可行流；源高n和汇高0阻止残量源汇路径，因此它是最大流。min_cut再从源沿正残量BFS，得到与最大流值相等的割容量。

本实现只做初始反向BFS，不做周期性全局重标号。保守时间界O(n²(n+m))、空间O(n+m)。高度总增长O(n²)，当前弧摊还扫描和标准推送计数给出一般预流推进多项式界；gap最多n次，每次全点重建O(n)。不把启发式平均表现或一次AC当作更强最坏界。程序会把多余流完全退回，不能拿仅求最大预流值版本的时间无条件比较流方案功能。

## 验证

- 19683个三点有向图穷举（含自环，容量0/1/2），独立枚举源汇割求真值。
- 5000随机多重有向图及打乱边序副本；每次检查最大流、每条边容量、反边残量、中间点流守恒及最小割容量。还检查复制、重复求流、交换源汇、加边重算、LLONG_MAX容量及无汇路径环。
- 两个官方样例及150随机驱动；两份用法的头文件/NDEBUG/完整展开/最小抄写在O2及ASan/UBSan运行。
- n=1200、m=120000三种压力：密集内点与小汇割、完全无汇路径的大预流、源割17且有显式17容量链。独立割上界与显式可行流证明答案；方案用法仍逐边检查守恒，不止看数值。
- 不更新反残量、丢弃高标号活跃点、错误返回原边剩余容量三个变体均检出；第一种触发终止超时，其余由值/方案检查发现。

[P4722](https://www.luogu.com.cn/problem/P4722)为直接加强版最大流模板题：n≤1200，m≤120000，正容量≤2^31−1，答案≤2^31−1；页面限时1.50s、内存500MB。两个样例输出14、8。算法背景参考[OI Wiki 最大流](https://oi-wiki.org/graph/flow/max-flow/)，代码按上述接口、完整流方案与单链桶约定独立组织。

实际[AC302390118](https://www.luogu.com.cn/record/302390118)：C++20 O2，100分、7 AC，总计显示1.06s，最慢单点266ms，峰值8.83MB。每点显示5、202、266、209、219、157、7ms；页面总计有秒级舍入。当前最小抄写版与提交归档字节一致；used/min_cut、全64位安全容量、零容量、自环及换源汇是额外本地验证范围，不从只输出流值的AC推断。
