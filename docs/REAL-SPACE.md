# 三维点线面：数值接口与来源缺陷

新增 `RealSpace`、`Line3`、`Plane3`，分别提供向量运算、直线/线段操作、平面操作。以轻量字段和短函数组合，使用者按需抄写；不改已有整数几何的坐标范围和精确谓词。

分类参考 [OI Wiki 三维计算几何基础](https://oi-wiki.org/geometry/3d/)，向量与变换背景见[向量](https://oi-wiki.org/math/linear-algebra/vector/)。实现由向量投影、正交分解和右手旋转公式独立编写。没有找到覆盖这组完整接口的已确认非比赛模板题，故用法348–351明确为API演示；搜索得到的QOJ2839是CCPC Final2020比赛题，未将其当作正式模板题。

## 向量与直线

`RealSpace::Point` 是三个 long double。向量加减、数乘和除法各占普通函数，不压成单行。`dot/cross/norm` 分别为点积、叉积和长度。`unit(a)` 要求a非零；`unit(a)*r` 可改变非零向量长度，零向量须由调用方先处理。`angle(a,b)` 对两个非零向量先单位化，再用 `atan2(norm(cross(a,b)),dot(a,b))` 求0..π夹角；它不是带正负方向的二维角。无需对acos参数夹取，近乎平行时仍能表示小角度。

`Point::operator<` 为有限坐标的精确字典序，不在比较器中使用epsilon。近似重合需另行以 `norm(a-b)<=eps` 判断，不能把该近似关系充当排序等价关系。长度平方可用dot(a,a)，两点距离用norm(a-b)。输入输出由用法main完成；保留位数属于调用方决定。

`Line3(p,d)` 表示p+t*d，第二参数是方向；`through(a,b)` 从两个端点构造，避免混淆。线段限制0≤t≤1。`projection(q)` 和 `segment_projection(q)` 返回直线与线段最近点；对应两种distance返回距离。线段的投影参数必须截断到端点区间。`on_segment(q,eps)` 按到线段的实际距离判断，包括两个端点和退化线段。

当d恰为零，投影和距离按点p计算；极短但非零的方向不会因固定epsilon被自动吞并。绕轴 `rotate(q,rad)` 则要求d非零，rad为弧度。单位方向u与v=q-p的正交分解给出

`p + v*cos(rad) + cross(u,v)*sin(rad) + u*dot(u,v)*(1-cos(rad))`。

正向按右手法则：绕正z轴π/2时正x轴转到正y轴。轴上点保持不变。反转方向需同时反转角度才能保持同一旋转。

## 平面与求交

`Plane3(p,normal)` 将非零法向量单位化，保存点p及单位法向n，方程为dot(n,x-p)=0。`through(a,b,c)` 要求三点不共线；`equation(n,h)` 对应dot(n,x)=h，若原方程为Ax+By+Cz+D=0，则传入n=(A,B,C)、h=-D。n为零无法定义平面，不接受。

signed_distance(q)=dot(n,q-p)，投影为q-n*signed_distance(q)。负法向量翻转距离符号，不改变投影或平面。两法向夹角由RealSpace::angle计算；无向平面的锐角/直角取min(theta,π-theta)，不能把有向法向夹角与无向平面夹角混称。

两种intersect均返回1表示唯一对象，0表示无交，-1表示重合：线面中-1表示整条非退化线在面上，面面中表示两平面重合。只有返回1才写输出参数。零方向的线按点判断，点在面上返回1，而不是-1。

线面求交先把线方向单位化，分母为n点乘u；沿线位移是-signed_distance(line.p)/dot(n,u)。平面求交取单位方向d=unit(cross(n,f.n))，在第一个平面内取v=cross(d,n)，再解第二个平面上的一个一元方程：

`q = p + v * (dot(f.n,f.p-p)/dot(f.n,v))`。

此点属于两个平面，交线为q+t*d。分母必须保留公式中的符号；不能为“防负数”随意取绝对值。输出点未要求最靠近原点，方向为单位向量，正反方向都定义同一条线。

## 容差与数值边界

默认eps=1e-10是距离容差，ang=1e-12是单位方向夹角的正弦容差。线面用abs(dot(n,u))≤ang归入平行；面面用norm(cross(n,f.n))≤ang归入平行。随后按一个代表点的距离决定重合或分离。这是明确的数值分类规则；近乎平行的两对象在精确数学意义上可能仍有交点/交线，因此不能把返回值当作精确拓扑证书。改变代表点、坐标尺度或容差可能影响阈值附近的分类。

所有输入须有限，运算中间量不得溢出或下溢；使用hypot计算长度并不能替其余点积、叉积、坐标相减保证任意尺度安全。法向量虽经归一化，三点构造时近乎共线仍会放大输入误差。近乎平行求交会除以很小的数，输出误差也会相应放大。极大平移与微小相对差值应先平移/缩放坐标，按题目误差要求选择容差。不存在一个固定epsilon能保证所有实数输入的准确分类。

本机GNU16的long double和double尾数均为53位；不能宣称long double在所有平台都额外提供精度。测试包含法向/方向尺度1e-100..1e100，以及1e-13/1e-9的近平行分类，但不是对所有有限浮点输入的保证。需要精确整数共线、共面、线段包含时使用既有IntegerGeometry3D，遵守其坐标范围。

## 完整来源核对

kuangbin §7.2全部188行在印刷238–242页（物理240–244），五页均目视核对。固定PDF SHA256为 `f1c90eae0c3fb309d58a14b050fe12b239efb474b033299a547b55646c2768ad`。原夹具仅归一化排版，未修补，下列行为均明确保留作诊断：

- 第18行output使用scanf与printf格式串，并把坐标值而非指针传入。`-Wformat=2`诊断保存于verification/real-space-source-format.txt；不执行这个错误I/O函数。
- 第24行epsilon字典序不是严格弱序。a=(0,0,0)、b=(0.75e-8,-1,0)、c=(1.5e-8,-2,0)满足c<b、b<a，却不满足c<a；测试只比较这三次，不将错误比较器传给sort。
- 第121行把线段点积条件写成等于零，漏掉严格内部点。线段(0,0,0)到(2,0,0)的中点被拒绝；注释又写“点在直线上”，与方法名/代码互相不一致。新实现按距离提供明确的闭线段判定，直线可用distance判断。
- 第158行是acos(dot)/(len1*len2)，而非acos(dot/(len1*len2))。法向(2,0,0)与(0,2,0)得到π/8而不是π/2；相同法向还会产生NaN。
- 第182行交线分母取fabs。平面x=1与y=2计算出的点y=0，不在第二个平面上。
- 零方向线的距离/投影缺少退化处理，出现0/0。新距离与投影明确按点处理，零方向旋转仍不合法。

原稿的相等、trunc、共面等使用不同量纲的固定epsilon，新实现没有逐位复刻这些阈值行为。两端点有向对象相等可由用户比较端点；无限直线是否重合不可用端点完全相等代替。原系数构造器也未把b,c初始化为平面上的三点，不能再调用pvec恢复有效法向；新Plane3只保存有意义的p,n，避免这个状态歧义。

## 测试证据

`tests/real_space.cpp`运行4999组非退化随机直线输入，对照原投影、两种距离和旋转；其中满足三点非共线的子集还对照平面投影和线面交点。另检查旋转往返、轴向投影及距离不变、单位法向、负法向符号、三点构造、同面、零线段、输出参数不被失败调用覆盖，以及缩放和近平行阈值。它不是对原错误函数的正确性背书。

`tests/real_space.py` 的四组完整API程序共8014组EOF数据：向量2002、线段/旋转2005、线面2004、面面2003。投影和线面交点以Python Fraction精确有理数作为舍入前参考；旋转另用四元数乘法构造；面面结果独立检查两条平面方程、单位方向与法向正交。普通、NDEBUG、展开、抄写四种形式均通过，普通和ASan/UBSan各运行一轮；核心的header/NDEBUG/抄写形式也全部通过。
