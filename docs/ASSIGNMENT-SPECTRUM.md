# 每种匹配基数的最优权值与顶标证书

`AssignmentSpectrum` 补齐 WIDA MaxAssignment 的 `weights()`、`labels()` 语义，并支持缺边、负权、两侧任意大小与指定基数上限。既有 `WeightedMatching` 不变，仍供只需要覆盖全部左点或可选总权最大化的场景使用。

## 接口

`AssignmentSpectrum(n,m)`，两侧0-based，n,m非负且可由int表示。`add(x,y,w)`接受完整signed64边权，重边只保留较大权，缺边是独立于合法边权的哨兵。使用者只通过add改图。

`solve(limit=INT_MAX)`每次从空匹配重算，返回实际基数k=min(limit,图的最大匹配数)，limit≥0；即使新增边后也可重新求解。不是在负增益时停止，指定基数可能迫使总权下降。`best[j]`是全图恰好j条边的最优权值，0≤j≤k，best[0]=0。未达到的基数不补零。所有求和、顶标均为int128；打印前只有确认范围才转long long。

`l[x]`与`r[y]`保存最后k条匹配的互逆方案，-1未匹配，不保存所有历史方案；需要指定j的方案时重新solve(j)。`lx`,`ly`,`level`给出最后基数的对偶证书。添加边之后旧的结果和证书仅对应旧图，须重新solve；构造后尚未求解时这些数组无有效结果。

时间O((k+1)nm+n+m)，空间O(nm+n+m)，适合稠密或两侧点数不大的带权二分图。上限为0仍要扫描图初始化证书。大稀疏图应按题意选择费用流，不能把这个稠密存储版本当作O(E)内存。

## 为什么必须同时从所有未匹配左点出发

某个左点的权值不一定全局最大。仅增广第一个左点后，当前答案只能保证该前缀被匹配，并非全图最佳1条边。例如矩阵[[1,0],[100,0]]，全局best[1]=100，而前缀行处理首先只能得到1。新实现把所有未匹配左点同时作为交错森林根；`slack[y]`记录从森林到右点的最小剩余松弛量，`from[y]`记录相应左点。

每次选最小slack的未访问右点，减小已访问左点顶标、增大已访问右点顶标，使该边变为紧边。如果右点已匹配，把其配偶加入森林继续松弛；遇到未匹配右点沿from和旧匹配回溯翻转。此处是匹配交错路径回溯，没有把DFS改成手动调用栈。所有未匹配左点必须参与根初始化，不能提前break。

## 可独立检查的证书

记h=level，α[x]=lx[x]-h，β[y]=ly[y]。维护：

- α,β均非负，所有存在的边满足α[x]+β[y]+h≥w[x][y]；
- 所有匹配边取等，未匹配左点α=0，未匹配右点β=0。

所以任意恰好k条边的匹配M都有

`weight(M) <= sum(α)+sum(β)+k*h`。

当前匹配恰好达到右式，故是该基数的最优解。这是固定基数匹配线性规划的弱对偶与互补条件，测试直接逐条检查，不仅对比权值。所有森林根都未匹配，它们lx相等；每次减delta时h也减delta，保证上述不变量。松弛量非负，h单调不增；成功增广的权值增量恰为当时h，所以best的相邻差单调不增，但best本身不必单调。

如果所有未访问右点都不可达，按增广路定理当前匹配已经最大基数。失败尝试中已调整的顶标仍对最后成功基数有效，证书不是上一次迭代保存的旧数组。覆盖全部左点时k=n，界简化为sum(lx)+sum(ly)，就是常见的矩形指派顶标证书。

signed64权值绝对值不超过2^63，每次增广路径长O(min(n,m))，边际权值及顶标的变化受O(min(n,m)·2^63)控制。int维数下远小于2^120哨兵和int128上限。缺边不参与算术，不能给它填0或某个可能被合法输入击中的long long常数。

## WIDA来源核对

锁定提交484e9e0e6e4f127f187eb3df5bc419e9ec863795的jiangly MaxAssignment文件，Git blob82eac55b8598db17455a6e26848bbb4904193555。完整原文件保留CRLF与引用，作为独立对照夹具存于tests/fixtures/assignment_spectrum_sources；上游GPL-3.0许可证同时保存，不由本项目MIT重新许可，也不包含到新核心中。

原接口明确要求0≤nx≤ny、完整矩阵、非负权。weights()给出0..nx每种基数权值，assignment()只给最终方案，labels()给最终lx/ly。本实现重新组织为稠密slack选择增广，没有沿用其队列代码；新增的负权/缺边/不等侧/截断能力只由自身测试覆盖，不归功于原稿。来源的AtCoder/QOJ提交链接未作为本项目线上通过证据。

## 使用与验证

API用法展示best、最后配对和顶标。演示输入限定两侧≤1000、|w|≤10^9，保证输出可转long long；核心仍测试全signed64。

[ABC247 G官方题面](https://atcoder.jp/contests/abc247/tasks/abc247_g)要求两种属性均不重复的团队，求每种人数最大总强度。构造两侧150点，人员为带权边，重复属性对保留最大强度。30000人、强度≤10^9，答案≤150×10^9，可安全转long long。不能把缺边当零权，因为官方样例中两人的最优总强度比一人更低。该项是比赛应用，不替代独立模板题，也没有本项目线上AC或运行排名。

测试运行入口为tests/assignment_spectrum.py；枚举全部至3×3的缺边/-2/3矩阵，对每个基数上限分别枚举匹配，并核对双侧配对、所有证书条件、重复solve不改变输入。追加signed64端点、平行边、空侧、负边、矩形及180阶闭式压力数据。另执行完整上游代码在其合法完整非负输入域，并用故障变体验证多源、反向费用与松弛符号不能省略。

[洛谷P6577官方题面](https://www.luogu.com.cn/problem/P6577)作为独立模板题另附用法334：保证完美匹配、n≤500、无重边、权值可负，第二行按右点顺序输出左点编号。本驱动用r而非l并把0-based转回1-based；原WeightedMatching的既有AC不转移给新驱动。此题不检验所有较小基数、缺少完美匹配或对偶证书，故保留额外枚举和API检查。

额外压力入口 `python3 tests/assignment_spectrum_stress.py`：500×500全同负权、可分离行列权，所有完美匹配并列，覆盖大量零松弛量时扫描已匹配列的情况。普通与消毒器均检查完整置换方案与闭式答案。耗时回执为本机进程、输入输出总时间，不是在线评测时间或速度榜排名。
