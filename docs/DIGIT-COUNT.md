# 数位 DP：十进制数码计数

`digit_count(n)` 统计正整数 1..n 中 0..9 的出现次数。n≤0 返回全零；零本身不计入，前导零也不计入。区间 [a,b]（a≥1）用两次前缀相减。状态随具体问题设计，本实现是完整示例，不声称一个接口能处理任意数位 DP。

递归状态为位置、是否紧贴上界和数字是否已经开始。终点仅对已开始的路径返回一个方案；每条有效路径唯一对应一个正整数。枚举当前数码，将子状态的数码计数累加；当当前数码不属于前导零时，它在每个子方案中出现一次，故再加子方案数。这同时说明了零数码与全前导零路径的处理。

只有不紧贴上界的状态可复用；此时剩余位数和 started 已完全决定子问题。memo 与 seen 都是函数局部变量，两个上界以及不同测试组不会互相污染。每个状态枚举十种数码、合并十种计数，时间 O(100L)、空间 O(10L)、递归深度 O(L)。signed long long 正数最多19位，结果使用 __int128：计数总和不超过19n，在128位范围内，但未必在64位范围内。

用法 example-395 对应 [P2602](https://www.luogu.com.cn/problem/P2602)。题目 b≤10^12，最多13b个数码，转换 long long 输出安全；不能把这个转换照搬到完整64位范围。当前代码 [R302624647](https://www.luogu.com.cn/record/302624647) 为100分 AC，10个测试点单点4ms，页面总时间40ms、峰值856KB；运行时间排名未核查。

核心测试对前10000个前缀逐个暴力枚举，对10000个完整正64位范围上界使用独立高位/当前位/低位公式对拍，并检查十进制进位、LLONG_MAX及相邻前缀差。驱动测试覆盖104个短区间暴力答案和完整题目上界的独立公式答案。头文件与最小抄写程序均通过O2、ASan/UBSan；精确印刷用法也单独测试。证据见 verification/digit-count-local.json、digit-count-driver.json、digit-count-online.json。

书册：总册12页模板、13页用法；杂项册10页模板、11页用法。代码与用法各自保持整页，目录、索引与依赖跳转已检查。
