# kuangbin Dinic来源及最大流父节核验

现有Dinic及其历史AC不自动证明kuangbin原片段已被核验。本批视觉核对固定2018原稿正文166–168页（物理168–170页）；完整70行在`tests/fixtures/dinic_sources/kuangbin.inc`。只去掉PDF行号、页眉和排版缩进、合并第48/58行折行并规范减号。固定PDF SHA256为`f1c90eae0c3fb309d58a14b050fe12b239efb474b033299a547b55646c2768ad`。

## 当前递归版与原稿

两版均为BFS分层、当前弧和阻塞流，原片段用sta数组记录增广路径，当前`Dinic`仍用递归DFS。原sta只进入来源测试夹具，不进入库的可抄写实现。当前递归深度、容量/流量、限流续流、方案接口见[FLOW-ATTACHMENT](FLOW-ATTACHMENT.md)。

原`dinic(s,t,n)`的当前弧初始化只遍历0..n−1，因此测试用0-based编号；不能因bfs清理n+1格就当它是1-based算法。当前点号1..n。原边编号从2开始，当前add从0开始，按输入顺序对应原2+2i与当前2i，反边均为id^1。

原addedge(u,v,w,rw)把双向容量放进一个残量对，记录有符号净流，范围[−rw,w]；当前两次add保留两个独立原边方案。默认rw=0时可直接逐边对照；双向非零时应比较正向used−反向used。正常测试明确涵盖w/rw各0..4与两种源汇方向。

两版求流均返回本次增量，不清边流量；耗尽后同源汇再调用返回0。当前可先限流后续流，原接口没有limit，不伪造原稿限流验证。原init清空边表，当前构造新对象。BFS遇汇点早停与完整分层允许产生不同方案；测试比较流值及各自容量/守恒，不要求逐边相等。

## 两个独立来源问题

1. 原MAXN=2010，而bfs按n+1个int清dep；n=2010即发生全局缓冲区越界。ASan在空图重现。0-based图的通用安全n应≤2009，不能只依据顶点数组长度判断。
2. 原增广瓶颈tp初始化为INF=0x3f3f3f3f。若路径瓶颈大于INF，本次并不饱和任何边，tail不会回退，却读取未填入的sta[tail]位置。独立新进程中，0→1单边容量INF+1返回值为INF+1，但原边flow为INF+2，超过容量！这一案例无须有符号溢出就能违反流可行性。当前递归版在同一容量及LLONG_MAX容量上检查流值、逐边方案和割均通过。

正常来源对照限制为n≤2009、每条原边容量<INF、总容量在int内，双向容量测试很小，避免把已发现的不受支持范围混入普通等价测试。原MAXM=1200010且tol从2开始，每条add占两格，可容纳至多600004对；该计数是数组算术边界说明，本批未声称实跑完整600004边上限。当前vector没有这个固定数组上限，仍遵守long long总流合同。

## 独立验证

测试以独立枚举全部s-t割为参照，覆盖三点729种0/1/2容量有向图与2000组随机图，随机源汇、平行/反向原边、自环、零容量与非连通均包含。来源流值与每条原边容量/反边关系、全图守恒分别检查；当前另外检查零限流、半流续流、耗尽及cut的可达集与最小割容量。再测2009点链和当前INF+1/LLONG_MAX边界。

普通及ASan/UBSan各头文件/最小抄写、assert/NDEBUG四种形式，每种2730图、287364项检查。used符号错误、遗漏反向残量、cut漏掉源点三个错误变体均被拒绝。来源INF案例在两种模式均运行，n+1清理越界在sanitizer单独作为预期失败记录。检查不依赖assert。

报告见`verification/dinic-source-normal.json`与`verification/dinic-source-sanitizer.json`。这批不改Dinic源码、不新增题目或AC，不把旧AC改签成新提交。
