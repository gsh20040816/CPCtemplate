# 序列替罪羊树与 CF455D

`SequenceScapegoat` 补齐 kuangbin 3.9/3.9.1 的隐式序列与子树频次表模型。现有 `ScapegoatTree` 是按值排序的可重集合，不能替代按位置修改的序列。新实现以vector保存节点编号，以map保存各子树的有效值频次；导航、收集、重建都递归，不模拟DFS调用栈。

## 接口和正确性

以 `vector<long long>` 构造，默认空序列。`insert(k,x)` 在前k项后插入，k为0..size()；`erase(k)` 删除并返回第k项，k为1..size()。`count(l,r,x)` 查询1-based非空闭区间内等于x的元素数。`rotate(l,r)` 删除第r项，再插入前l-1项之后，实现区间右移一位；l=r合法。完整值域包括LLONG_MIN/LLONG_MAX，不做值加减或设置数值哨兵。

每个节点存两个数量：sz是活元素数，cnt是包含墓碑的实际节点数。按位置导航只使用sz和live，不能把墓碑视为占一个位置。freq只含活元素的正计数，查询用find，查不到的值不插入。修改路径上的频次增减一次；重建时由孩子与当前活元素重算，故完整覆盖子树的查询直接查freq，边界子树继续递归。

当某个孩子的实际节点数超过整棵子树的3/4，或活元素不足实际节点数的一半时重建。中序收集活节点保持原序列，死节点释放map并放回spare，随后按中点递归建树。向量扩容前后只使用编号，递归中不保留vector元素引用。删除最后一个元素得到root=0，后续插入复用空闲节点。a/root/spare与带节点编号的方法属于实现内部，不应在调用方修改。

## 复杂度与内存

每个子树满足重量平衡，且整棵树实际节点数不超过活元素数两倍，因此树高O(log(n+2))。区间计数访问两条边界路径及其完整覆盖的兄弟子树，至多O(log(n+2))次map查询，总计O(log²(n+2))。

一个s节点子树的重建会在每层重新合并频次表，保守成本O(s log²(s+2))，不是裸替罪羊树的O(s)。重建由累计足够多的插删触发，按路径层数分摊，更新保守均摊O(log³(N+2))，单次最坏O(N log²(N+2))；N为历史最大长度。初建O(n log²(n+2))。不把它宣传成普通替罪羊树的均摊O(log n)。

每个活元素最多出现在一条根路径的频次表中，频次表条目总计O(n log(n+2))；节点池复用死节点，vector仍保留历史容量O(N)。计数及节点编号使用int，要求节点池规模小于INT_MAX。频次表节点有std::map分配开销，实际内存须按比赛环境评估。原稿以静态指针池、带+5容忍度的重量重建维护同一模型；当前实现不照搬其常数或分配方式。

## 完整比赛适配

已核对 [Codeforces 455D 官方题面](https://codeforces.com/problemset/problem/455/D)，2026-10-08读取：n,q≤100000，初值和编码参数均1..n，4秒/256MiB。每次参数按(v+lastans-1)%n+1解码，再交换逆序的l/r；只有查询更新lastans，区间移动不改变它。`verify/codeforces/455D.compact.cpp` 与用法326保留完整协议。这是比赛应用，不代替用户要求的独立非比赛模板题；独立模板入口仍待寻找，线上AC和速度榜均未核实。

官方两组样例均纳入测试。原稿支持EOF多组，正式题面只输入一组；当前驱动按正式题面处理一组，而来源程序另测多组重置。接口层的任意插删、空序列和long long边界由独立测试验证，不声称CF455D覆盖这些接口。
