# 附件 2-SAT、点双与边双核对

核对 issue #11 附件实际 15–17、33–36 页（2.1、2.6、2.7），保留现有 vector 核心和递归 DFS。
本批不新增同义封装，新增两个 Library Checker 完整适配、P4782 打印用法，并加强独立验证。

## 2-SAT 的编号方向

附件使用 Tarjan，SCC 编号按逆拓扑顺序；变量为真的分量编号较小时取真。
本库 TwoSAT 使用同文件的递归 Kosaraju，编号按拓扑顺序；因此实际比较是
`bel[id(x,1)] > bel[id(x,0)]`。不能只复制附件的不等号而不检查 SCC 编号契约。
另一份 TarjanSCC 仍独立提供，不能换掉依赖却保留同样的比较方向。

变量号 1..n，`add(x,a,y,b)` 添加 `(x=a) OR (y=b)`，不是单独的蕴含。
`x=a => y=b` 写为 `add(x,!a,y,b)`；强制值写 `add(x,a,x,a)`。
两边相同不是特殊错误：同值是单位子句，反值是永真式。
`solve()` 每次重新计算，支持增加子句后重算；仅返回 true 时读取 ans。
没有字典序保证。空公式可满足，n=0 的 API 也有定义。

一般时间/空间为 O(n+m)，蕴含图有 2n 个点、2m 条边。
附件以“点边同阶”写 O(n) 不适用于任意稀疏或稠密输入。
[P4782](https://www.luogu.com.cn/problem/P4782) 当前限制 n,m≤10^6；读入四元组、输出布尔赋值。
已有 LC DIMACS 用法保留，新例只补附件采用的洛谷输入格式。

## 点双的定义及父边

[P8435](https://www.luogu.com.cn/problem/P8435) 采用“连通且没有割点”的点双约定。
桥的两个端点形成一个块；孤立点形成单点块；割点可出现在多个块。
自环不改变顶点之间的连通性，不应为非孤立点额外创建单点块。
BiconnectedCore 保留自环原边号，跳过其 DFS 邻接项；其桥标记恒为零。

附件点双代码跳过所有指向父顶点的邻接项，少算平行父边对 low 的贡献。
对于仅输出顶点点双，这不改变 `low[child]>=dfn[parent]` 的真假：
被省略的平行边最多把 low 降到父亲 dfn，不能降到更早祖先。
因此不能仅凭此就宣称该点双输出错误；但这份 low **不能复用来判断桥**。
本库共享点双、割点和桥结果，所以必须只跳过父边编号，保留其它平行边。

内部 st 是尚未归块的顶点栈，不是模拟 DFS 的显式调用栈。
每棵 DFS 树结束只留下根，run 将其弹出；重复 run 会清空全部分解结果。
点号 1..n，原边号从零开始；blocks/cut/bridge/bel 在 run 之后才有效。

## 边双与两种森林

[P8436](https://www.luogu.com.cn/problem/P8436) 允许自环和重边，规模同点双：n≤500000，m≤2000000。
附件边双通过 is_first 只跳过一次父顶点，与无向边的两份邻接对应，能正确保留其它平行父边。
本库使用原边编号，先标桥，再递归遍历所有非桥边染色；分量号 1..cnt，无拓扑方向约定。
两个方向各 add 一次会人为制造重边：每条逻辑无向边只 add 一次。

block_cut_forest 将原顶点 1..n 与方点 n+i+1 连接；孤立点亦连接自己的单点方块。
bridge_component_forest 将每条桥映射为边双之间的一条边，保留原桥编号。
不连通原图得到森林，不能默认结果只有一棵树。所有这些操作均 O(n+m)。

## 验证范围

- tests/biconnected.cpp 已去掉旧 classic 依赖。枚举全部 1024 个五点简单图和 1500 个随机多重图；
  通过枚举顶点子集、删除顶点和逐条删除原边独立获得点双、割点和桥参考。
  同时核对边双、圆方森林、桥森林、重复运行、20 万点长链加边后成为整环。
- tests/two_sat.cpp 对 2500 组公式逐次添加六条子句，每次重复 solve，并以全部赋值枚举验证；
  明确核对空公式、单位子句、矛盾单位和 SCC 拓扑方向。
- tests/graph_attachment.py 检查三个完整洛谷驱动：2-SAT 200 组真值表参考及百万变量/百万子句长链；
  点双/边双各 200 组子集/删边参考，50 万点/200 万边长链加自环、四份平行边整环。
- 新增 Library Checker biconnected_components 和 two_edge_connected_components 适配。
  LC 点双输入无自环，重边合法；点双/边双适配均将输入点号加一、输出减一。
  固定上游版本生成全部数据，点双 22 组、边双 21 组分别在普通及 ASan/UBSan 下由官方 checker 接受，
  且故意错误输出被拒绝。这是官方数据的**本地检查**，不是线上 AC。

本地普通驱动保留原 main，macOS 配置 512 MiB 主线程栈。
百万变量矛盾长链可造成接近两百万层 DFS；ASan 扩大栈帧后超出该平台主线程栈上限。
只在 P4782 的 sanitizer 测试中将 main 重命名后放到 1 GiB pthread 栈执行；
完整输入、算法和输出不变，提交源码仍为普通 main 和递归 DFS。
这说明本地 sanitizer 的栈配置要求，不代表 OJ 时间或内存排名。
