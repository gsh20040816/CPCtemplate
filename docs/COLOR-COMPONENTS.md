# 固定树翻色与同色连通块

`ColorComponents(h, color={})`依赖已完成`build(root)`的HLD，点编号1..n。省略颜色数组时全部为0；否则数组长n+1，每点为0或1。`flip(u)`翻转单点，`query(u)`返回包含u的同色连通块大小。可读取`col[u]`，不要直接改写颜色、树、内部集合或树状数组。h的生命期须覆盖本对象，构造后不能修改或重新build。

初始化O(n log n)，每次翻色/查询O(log²n)，空间O(n)。只处理固定拓扑，不支持link/cut，也不是QTREE7的带权最大值算法。1≤n≤INT_MAX/2；内部用long long，答案不超过n。复用HLD的递归DFS，需要相应栈空间；没有改为显式开栈。

## 不变量与证明

定义f[u][c]为假定u颜色为c时，从u向下可达的同色节点数，不论u的实际颜色是什么。于是

`f[u][c] = 1 + sum(f[v][c] : v是u的儿子且col[v]==c)`。

反向dfn顺序初始化，每个儿子先于父亲完成。这是树上DP次序，不是模拟DFS。两棵差分树状数组维护两种颜色的f，重链dfn区间加、单点查询。

翻转u不会改变f[u][0/1]，只改变它向父亲提供哪一色的贡献。对旧色减去f[u][old]，对新色加上f[u][new]。变化从父亲沿对应颜色的连续祖先链传播，并且必须包含紧接着的首个异色祖先：它的假定颜色贡献也变了，但它的实际颜色使变化不再向上传播。若父亲已异色，仍更新父亲；若u为根，不更新任何祖先。两种颜色数组相互独立，完成传播后再修改颜色集合。

`top(u)`求同色连通块最高点。每条重链中，在相反颜色dfn集合里找不超过u的最后一个位置；若它落在当前重链区间，答案是其下一位置。若区间没有异色点，继续跨向链头父亲，直到根或异色父亲。每次跨重链经过轻边，最多O(log n)条链，每次集合查询O(log n)。最高点以下的同色可达节点恰好就是整个连通块，因此读取该点对应颜色的f即可。

[QTREE6的洛谷RemoteJudge页面](https://www.luogu.com.cn/problem/SP16549)于2026-10-12核对：n,q≤100000，初始全黑；单组树，0 u询问、1 u翻色。页面显示5秒、1.46GB；这是洛谷页面信息，不推断SPOJ编译器版本或栈设置。样例为五点星形树，输出5、1。已提交[302642339](https://www.luogu.com.cn/record/302642339)，当前为Waiting，尚无远端AC或排名结论。线上状态单独记录，不能用本地对拍代替AC。

## 本地验证

- n≤5的全部标号树、全部颜色、全部根；n=6的全部1296棵标号树、全部64种颜色、各选一个根。每个状态检查所有节点，并逐点翻转、恢复。另有20棵200点随机树各500次连续翻色，共1318058个状态。
- 独立BFS核验真实连通块大小和最高点；只沿儿子边的另一项BFS核验两种假定颜色贡献，能发现尚未影响当前查询的陈旧值。
- 十万点链、星形树、二叉树各十万次翻色，链以末端为根，并检查中点断开；星形树反复翻转高度数中心，无逐邻边更新。
- 普通O2、NDEBUG、ASan/UBSan构建全部通过；检查使用显式异常而非会被NDEBUG去掉的assert。Mac测试通过链接器预留512MiB进程栈；这属于本地测试配置，不修改竞赛程序或推断评测环境。未启用LeakSanitizer。
- 完整原稿、头文件驱动、最小抄写程序分别与BFS核对101组完整输入，在O2和ASan/UBSan两种构建下执行。两个手册用法也单独编译运行。
- 五个错误变体（漏异色边界、旧色增减号反向、遗漏颜色集合删除、漏重链头边界、只查子树）都被独立oracle拒绝。
