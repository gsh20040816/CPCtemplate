# Dinic 可选容量缩放（Issue 19）

默认源码保持普通 Dinic；本次 flow.hpp 去掉行注释与空白后，与 5ff2bde 完全一致。BFS、DFS 的阈值条件、递归参数和 flow 的外层降阈值循环，都在修改位置以 `// Scaling:` 标出。不是只取消一行注释就能切换。

阈值 lim 从不超过当前最大残量 mx 的最大二次幂降到 1。mx 要扫描正反两个方向的当前残量，不能读 initial 代替。mx=0 直接返回；从1开始、满足 lim≤mx/2 时才翻倍，不对0取 clz，也不会在 LLONG_MAX 边界左移溢出。BFS/DFS的lim默认1，故cut照常检查全部正残量。限流剩余量可以小于lim；本次仍只增广剩余量，到达limit停止，之后可用同一源汇续流。

一般整数容量缩放上界为 O(VE log(U+1))，U是本次开始的最大残量。每阶段之前，小于2lim的残量割限制了待增广流量，每条完整增广路至少送lim，故该阶段O(E)次增广；一次路径处理O(V)，分层与当前弧扫描计入O(VE)。最终限流截断至多多出一次不足lim的增广。最终lim=1才能保证整数最大流精确。单位容量或普通图不保证更快；很大INF可能增加无效阈值阶段。

## 本地验证

`tests/dinic_scaling.py` 按每一处注释生成切换版，并同时测试默认版。每种构建4000张有自环、平行边、反向原边、零容量和悬殊容量的随机图，共4061872次独立最小割枚举、流守恒、残量对及割证书检查。覆盖限流0、分段续流、增容后续流、全图清零后更换源汇、反向边重路由、LLONG_MAX链、最大阈值和递归传参；普通及ASan/UBSan通过。测试不仅比较两种实现的返回值。

15份依赖Dinic的准确纸面用法分别通过普通及ASan/UBSan执行。默认版无算法改动的证据见 verification/dinic-scaling-default.json。
